# Olvin: architecture

<p align="center"><a href="ARCHITECTURE.md">Русский</a></p>

A modular game engine in Rust. Each subsystem lives in its own crate and is attached as a plugin. Subsystems talk to each other only through shared resources and do not depend on each other directly.

The visual style (colours, fonts, glass, motion, copy): [STYLE.en.md](STYLE.en.md). The logo, wordmark and app icon (SVG, PNG, ICO): `assets/logo/`. The roadmap: [ROADMAP.en.md](ROADMAP.en.md).

## Principles

- **Modularity at the subsystem level, not the object level.** A plugin registers systems, and a system processes all its data in one call. There are no virtual calls per object.
- **Hot paths work with flat arrays.** The renderer sorts instances by mesh into reusable `Vec`s and makes one instanced draw per mesh. In steady state a frame allocates nothing.
- **The core knows nothing about the GPU or the window.** The renderer and the platform are linked through `SurfaceTarget` (raw-window-handle), so winit can be replaced with SDL or a canvas without touching the renderer.
- **The minimum hardware level is WebGL2 / GLES 3.0.** The device is requested with `Limits::downlevel_webgl2_defaults()`. Anything stronger is enabled by `RenderTier::Full`.

## olvin_core

- `app.rs`: `App` holds `Resources`, `Schedule`, the plugin set and the runner. `add_plugin` skips duplicates of the same type, so a plugin can add its own dependencies. `run()` hands control to the runner; without it a headless loop runs. There is `startup()` (Stage::Startup, once) and `update()` (one frame). `AppExit { requested }` stops the loop.
- `resources.rs`: `Resources` are singletons keyed by `TypeId` in a `RefCell`. Methods: `get/get_mut` return an Option, `fetch/fetch_mut` panic with the type name. Different resources can be borrowed mutably at the same time, the same one cannot.
- `schedule.rs`: stages `Startup, First, PreUpdate, Update, PostUpdate, Render, Last`. A system is `FnMut(&mut Resources)`. Everything is single-threaded for now.
- `time.rs`: `Time` (delta clamped to 0.25 s, elapsed, frame) is updated in `First`.
- `logging.rs`: a single logger with no extra dependencies. `Logging::new(filter).file("logs/x.log").init()`: the filter works like env_logger (`"info,wgpu_core=warn"`, overridden by `OLVIN_LOG`/`RUST_LOG`; `Filter` takes the longest module prefix). Lines go to stderr and to the file. A panic hook writes `crash-<unix-time>.txt` next to the log (or into `crash_dir`): message, location, thread, backtrace, the last 64 log lines, then calls the previous hook. It is used by `sandbox`, `script_demo`, the hub's game template (`logs/` is in `.gitignore`) and the editor (`olvin_editor::run`, file `<project>/logs/editor.log`).
- `surface.rs`: `SurfaceTarget { handle: Arc<dyn WindowHandleSource>, size }`, the contract between the platform and the renderer.

## olvin_ecs

Re-exports the hecs types (`World`, `Entity`, `Query`, `CommandBuffer`, …). The rest of the code imports them only from here, so the ECS backend can be replaced in one place. `EcsPlugin` inserts the `World`. 3 tests for the facade contract (filtered queries, `CommandBuffer`, `EntityBuilder`).

## olvin_scene

`Transform` (translation/rotation/scale, `matrix()`, `looking_at`, `forward/right/up`) and `Camera` (perspective, right-handed, depth 0..1 through `glam::camera::rh::proj::directx`). Runtime components `Name`, `Tag`, `MeshGeometry` (triangles for mesh colliders). `primitives.rs`: `Shape` (Cube, Sphere, Capsule, Cylinder, Plane, Quad, sizes as in Unity) and `Primitive` (positions, normals, indices, an outline for selection). This is the shared geometry source for the engine and the editor. No dependency on the ECS or the GPU.

## olvin_window

- `lib.rs`: `WindowPlugin { title, width, height, resizable }` installs the runner on winit 0.30 (`ApplicationHandler`). The window is created in `resumed`, because Android requires that. There `SurfaceTarget` is inserted and `app.startup()` is called. A frame is `RedrawRequested → app.update()`. On Resize, `SurfaceTarget.size` is updated.
- `input.rs`: `Input` stores pressed keys and mouse buttons, `just_pressed/just_released`, the cursor position and the raw `mouse_delta` from `DeviceEvent`. It is reset in `Stage::Last`; losing focus releases everything.

## olvin_transform

`Parent(Entity)` and `GlobalTransform(Mat4)`. `TransformPlugin` calls `propagate` in `Stage::PostUpdate`: missing `GlobalTransform`s are added, roots get a global matrix equal to their local one, children are computed with a cache, and cycles are cut. `world_matrix(world, e)` gives the world matrix right away, before propagation (physics uses it). The plugin is part of `DefaultPlugins` and `RenderPlugin`. 5 tests: hierarchy levels, the plugin in PostUpdate, scale/rotation, detaching from a parent, a dangling parent, cycles.

## olvin_render

- `lib.rs`: `RenderPlugin { settings }`, `RenderSettings` (vsync, low_power, clear_color, light_dir/light_color/light_shadows, the fallback sun; ambient (sky) + ground_ambient, exposure, `tonemapping: Tonemapping::{None, Aces}`, `fog: Option<Fog>`, shadow_distance, shadow_map_size), the component `MeshRenderer { mesh, color }`, `Color` (linear RGBA). The plugin adds `EcsPlugin`, the resources `Meshes` and `RenderStats`, and the systems `init` (Startup) and `render` (Render).
- `core.rs`: `RenderCore`, rendering without a window. Pipelines are created for a specific colour format, MSAA and depth. If the target is not sRGB (as in egui), gamma is encoded in the shader. `GpuMeshes` are GPU copies of one `Meshes` registry, `ViewData` is the data of one camera (a uniform buffer and instances). Methods: `upload`, `prepare(view, gpu, world, view_proj, settings)` (walks `(GlobalTransform|Transform, MeshRenderer)` with sphere culling, buckets by mesh, one instance buffer) and `draw(view, gpu, pass)` into someone else's render pass. `camera_view_proj(world, aspect)`. Order per view: `prepare` → `render_shadows(view, gpu, encoder)` → `draw`. Each `ViewData` has its own shadow map (Depth32Float, created lazily; a 1×1 stub until then), and shadow casters are culled against the shadow box. A pixel test draws a cube into an offscreen texture (verified on Vulkan and llvmpipe).
- `renderer.rs`: the windowed `Renderer` = `RenderCore` + surface. It creates the instance with a display handle (for GLES/Wayland), the adapter and the device with WebGL2 limits, and determines `RenderTier` (`tier_of`). With vsync it uses Fifo, otherwise Mailbox or Immediate. Also `begin_pass` and `create_depth`. The crate re-exports `wgpu`.
- `light.rs`: the component `Light { kind: LightKind::{Directional, Point, Spot}, color (linear), intensity, range, spot_angle_deg, shadows }`; forward = −Z from `GlobalTransform`. The first directional `Light` replaces the sun from the settings; the others are the nearest up to `MAX_LIGHTS = 16` after frustum culling, packed into a uniform (std140). The shadow camera: a sphere around the first `shadow_distance` metres of the frustum, snapped to texels (no shimmer).
- `mesh.rs`: `Vertex { position, normal }`, `MeshData` (`cube`, `plane`, `from_triangles`, `bounding_sphere`). `Meshes::add` returns a `MeshHandle` before the GPU copy exists; uploading is lazy. `Meshes::set` re-uploads geometry into the same slot (mesh editing in the editor).
- `texture.rs` / `material.rs` / `shader.rs`: the registries `Textures` (`TextureData { width, height, format: TextureFormat::{Rgba8Srgb, Rgba8Linear, Rgba16Float, Rgba32Float}, pixels }`, mips on the CPU, sRGB averaged in linear space; Rgba32Float is uploaded as Rgba16Float, since only that one is filterable on WebGL2), `Materials` (`Material` mirrors `MaterialDesc` with handles instead of paths; `MeshRenderer { material: None }` is drawn with `Material::fallback()`) and `Shaders` (surface shaders). Like `Meshes`, the registries work before the GPU exists; `RenderCore::upload_assets(gpu, textures, materials, shaders)` is called next to `upload`. Custom WGSL is placed before the template (`globals.wgsl` + `mesh.wgsl`), so line numbers in errors match the file. naga validates on `add`/`set`, the pipeline is created in an error scope, and on failure `Shaders::error(h)` is set while the last working pipeline stays. `validate_surface_shader(src)` is for editors. PBR: GGX + Smith + Schlick (metallic-roughness, the Unity convention), normal map, ORM, emissive, alpha cutoff, unlit, triplanar; ambient specular samples the sky along the reflection. `RenderSettings.sky: SkyMode::{Color, Procedural{..}, Texture{texture, rotation, intensity}}` is a fullscreen triangle on the far plane in the same pass (and in the editor's pass), with a sun disc from the first directional light, and fog at the horizon fades into the sky. Instances are grouped by (material, mesh) and ordered (pipeline, material, mesh), with no allocations. `RenderCore::set_time`. WebGL2: 9 attributes (Vertex = position, normal, uv, tangent, 48 bytes), 5 varyings, 2 bind groups, 6 textures. 27 tests on Vulkan and llvmpipe GL.
- `frustum.rs`: 6 planes from view-proj (Gribb–Hartmann, depth 0..1), sphere test.
- `RenderSettings.scene_lights` (default true): when false, `Light` components are ignored (the editor's Solid view).
- `mesh.wgsl`: an instanced shader within WebGL2 limits: one uniform, 7 attributes (the model matrix as 4 vec4 + colour). Hemispherical ambient, the sun with PCF 3×3 (comparison sampler, slope bias + normal offset, fade towards the edge of the distance), 16 point/spot lights (falloff `saturate(1-(d/r)^4)^2/(d²+1)`, soft cone), Blinn-Phong, fog, exposure + ACES, sRGB. `shadow.wgsl` is a depth-only pass. Shadows work on Compat (GL) too.

## olvin_csg

The classic level-editor CSG (Hammer, Realtime CSG) over convex brushes.
- `shapes.rs`: `BrushShape` (Box, Wedge, Cylinder{sides}, Pyramid{sides}, Stairs{steps}) in the local unit cube `[-0.5, 0.5]³`, so the brush size is its scale. Each shape is a set of convex pieces (stairs have one piece per step).
- `convex_hull(points)` (brute force over triples, for brushes with dozens of vertices), `shape_vertices(shape)` (the corners of a single-piece shape). `BrushInput.vertices: Option<Vec<Vec3>>` is an edited brush: the hull of its own vertices instead of a parametric shape.
- `lib.rs`: `build(&[BrushInput]) -> Vec<Polygon>`. Each face is split by the planes of the intersecting pieces (AABB rejection), so every fragment lies entirely inside or entirely outside every brush. A fragment is kept if the solidity on its two sides differs: points are taken 2 mm either side along the normal, and the operations `CsgOp::{Add, Subtract, Intersect}` are applied in order. Coincident faces with the same orientation keep only the last piece. The method is robust against touching and coincident faces, where BSP approaches break. Mirrored transforms re-orient the faces. `brush_edges` gives outlines, and `TriMesh::from_polygons` builds the mesh. `BrushInput.faces` is a modelled brush (a closed surface of convex polygons; it may be non-convex): such a piece is tested for "inside" with a generalised winding number (solid angle, Van Oosterom–Strackee), and fragments are cut by all of its planes (convex brushes use a fast rejection by the front side). Face orientation is aligned by the sign of the volume (mirrored transforms). 8 tests: a room, a tunnel, the order of operations, intersection, closedness of all shapes.

## olvin_mesh

An editable polygon mesh `PolyMesh { positions, faces: Vec<Vec<u32>> (n-gons, counter-clockwise from outside), wire: Vec<[u32; 2]> (free edges) }`, serialisable (feature `serde`). Adding operations keep all indices; removing operations return a `Remap` for vertices and faces. `validate()` checks the invariants. Operations: `extrude_faces` (the region: side walls only on the selection boundary) / `extrude_edges` / `extrude_vertices`, `inset_faces`, `split_edge`, `connect_vertices`, `knife`, `loop_cut` (a ring across quads), `make_face` (the order of selection does not matter, orientation follows a neighbour), `fill_edges` (a loop, a chain or a bridge between two edges), `delete_vertices/edges/faces(keep_edges)` (faces → edges), `dissolve_edges`, `merge_vertices`, `merge_by_distance`, `flip_faces`, `recalculate_normals_outside`, `subdivide_faces`, `catmull_clark`, `triangulate` (ear clipping in the face's plane, flat normals), `compact`. `walk.rs`: `adjacency()` (`Adjacency`: edges → faces, neighbours and faces around vertices), `edge_loop` (through 4-valence vertices, along the boundary and wire chains), `ring` (a face loop and an edge ring across quads), `linked`, `grow_selection`, `shrink_selection`, `duplicate`. Constructors: `cube`, `plane`, `from_polygons(polys, weld_eps)`. UVs per face corner: `uvs[f][i]` ↔ `faces[f][i]`; an empty array means "no UVs yet" (`ensure_uvs` does a box projection). V points up as in Blender (the renderer flips V: `olvin::render_assets::poly_mesh_data`). Seams are `seams`. All operations keep the UVs consistent (interpolation, mean value coordinates for inset, isometric walls for extrude). `uv.rs`: projections (box/planar/cylinder/sphere/from view/follow active quads), islands, `transform_uvs`, texel density, `triangulate_uv`. `unwrap.rs`: LSCM over charts cut by the seams, scaled to the real area, rotated to the minimal bounding box, packed in shelves into 0..1. 55 tests.

## olvin_assets

Unity-style assets, without the GPU. `AssetRoot` (`assets/`): `resolve/relative`, `scan()` creates `.meta` files (RON: `Meta { guid, importer: Importer::{None, Texture(TextureImport { srgb, max_size, generate_mips, point_filter }), Model(ModelImport { scale, .. })} }`); copies with someone else's meta get a new GUID; `guid_of/path_of`; `move_asset/delete_asset` carry the meta along. `texture.rs`: `load_image(path, srgb)` → `ImageData` (HDR/EXR as float), `thumbnail`, `ThumbnailCache` (LRU). `model.rs`: `import_gltf` → `ModelData { meshes, materials: MaterialDesc, nodes (YXZ), extracted_textures, skipped }`; embedded images go to `<model>_textures/`; `model_to_entities` (poly + `uvs_per_face`); `write_materials`. `AssetWatcher` (notify 8): a non-blocking `poll()` with debouncing. `AssetsPlugin`. 9 tests.

## olvin_scene::material

`MaterialDesc` (`*.mat.ron`): base_color/texture, normal + strength, metallic, roughness, orm, emissive (+ texture), uv_scale/offset, triplanar, point_filter, alpha_cutoff, unlit, shader (`*.wgsl`). `SURFACE_SHADER_CONTRACT`: `fn surface(in: SurfaceInput) -> SurfaceOutput`, and `default_surface`, the standard material. `EntityDesc.material` is the material path for a mesh, a poly mesh or brush faces. `Environment.skybox: Sky::{Color, Procedural{..}, Texture{path, rotation_deg, intensity}}`; the environment presets also set the sky.

## olvin_script

Unity-style scripts, in Rust. Default features: `input`, `physics`.

- `behaviour.rs`: `trait Behaviour`: `start`, `update`, `fixed_update`, `on_collision_enter/exit`, `on_trigger_enter/exit`, `on_destroy`.
- `lib.rs`: the component `Scripts(Vec<ScriptDesc>)` with the builder `Scripts::new().with(name, params)`; `ScriptPlugin` creates the registry and the runtime, `FixedSystems` gets `fixed_update`, `Update` gets `run_update`. The extension `App::register_script::<T>(name)` (trait `ScriptAppExt`).
- `registry.rs`: `ScriptRegistry`: `register::<T: Behaviour + FromParams>(name)`, `register_fn(name, schema, make)`, `create`, `schema`, `export_schema() -> ScriptSchema` (RON for the editor). The macro `register!` accepts `"name" => Type` or plain type names.
- `runtime.rs`: `ScriptRuntime` (a resource) holds the instances; `run_pass` on each pass: attach new ones, `start` once, collision events (only in `Update`), then `update` or `fixed_update`, then deferred commands and `on_destroy`. A panic in a callback disables only that script (`catch_unwind`).
- `ctx.rs`: `ScriptCtx`: the world and components (`get`, `component`, `has`), `spawn`/`despawn`/`insert`/`remove` (deferred until the end of the pass; the id from `spawn` is valid at once), Transform helpers (`translate`, `rotate_euler_deg`, `look_at`, `forward`), time (`TimeInfo`, `dt`, `fixed_dt`), lookup `find_by_name`/`find_by_tag`/`find_all_by_tag`, resources `res`/`res_mut`, input `input()` (feature `input`), `raycast`, `motor()` and `move_character()` (feature `physics`), logs `log`/`warn`.
- `params.rs`: `Params` and `FromParams` (`from_params`, `schema() -> Vec<ParamSpec>`): string parameters from the editor, with types (`parse_vec3`, `parse_bool`).
- `builtin.rs`: ready-made behaviours: Rotator, Oscillator, Mover, FollowTarget, DestroyAfter, FreeFlyCamera, SimplePlayerController.
- `tests.rs`: 10 tests.

## olvin_input

Action maps: `InputMap { actions: name → [Binding] }` (keys, mouse, wheel, gamepad, `Axis1D/Axis2D`, `Chord`), `assets/input.ron`, a default map (Move, Look, Jump, Sprint, Fire, Interact, Pause, Ascend). `ActionState`: pressed/just_pressed/just_released/value/axis2d, mouse, `lock_cursor`. Stage::First. Gamepads through gilrs (feature `gamepad`). 6 tests.

## olvin_audio

kira 0.12: `AudioPlugin { assets_dir, enabled }`, the resource `Audio` (one-shots, `play_at`, `play_with`, streamed music, volume, pitch). `AudioSourceDesc` plays when it appears and follows its position; in 3D, attenuation and panning come from the `AudioListener`. Without a device it is a no-op. 3 tests.

## olvin_physics (additions)

Fixed steps: `FixedSystems`, kinematics, characters, `step_with_events`, writing poses back; bodies of removed entities are cleaned up. Character Controller: a capsule + `CharacterMotor { velocity, grounded, sliding, gravity_scale }`, steps, slopes, `move_character`. `CollisionEvents` per entity. `raycast(_filtered)`, `spherecast(_filtered)`, `overlap_sphere`. `olvin_window`: `Input.scroll`, public setters, `CursorOptions`.

## olvin_scene::file (feature `serde`)

The scene format `*.scene.ron`, shared by the editor and the games. `SceneFile { entities, environment, extensions }`. `environment: Environment` (sky and ground for ambient + intensity, background, exposure, `filmic` (ACES), `fog: Option<FogDesc>`, shadow distance and resolution) is written only when it differs from the default; `Environment::PRESETS`: Day / Sunset / Night / Studio. `EntityDesc`: a stable `id`, `active`, `tag`, `layer`, `parent`, position, rotation in degrees as Euler YXZ, scale, `mesh`, `camera`, `brush: BrushDesc { shape, op, color, vertices }`, `poly: PolyMesh` (an edited mesh: for a normal object it replaces `mesh.shape`, with the colour from `mesh`; for a brush it is the shape used by CSG), `EntityDesc::brush_input(transform)` is the CSG input (convex faces of `poly` as they are, non-convex ones as triangles), `light: LightDesc` (Directional/Point/Spot), `collider: ColliderDesc` (Box/Sphere/Capsule/Mesh, center, trigger, friction, bounciness), `rigidbody` (Dynamic/Kinematic, mass, drag, gravity, freeze rotation, CCD), `character_controller`, `audio_source`, `audio_listener`, `scripts: [ScriptDesc { name, params }]`. Empty fields are not written to the file. `active_in_hierarchy`, `sun()` is the first active Directional Light. Parents always come before their children in the list. `world_matrices[_with]` expands the hierarchy into world matrices, `hierarchy_order()` gives the DFS order as in the hierarchy panel, and `csg_brushes()` gives the brushes in operation order. `extensions` are data of editor elements (animator clips).

## olvin_physics

`PhysicsPlugin { gravity }` and the resource `Physics { world: rapier PhysicsWorld }`. Every frame (PreUpdate): entities with a `ColliderDesc` or `RigidbodyDesc` but no `Body` marker get bodies (Dynamic, Kinematic, or Fixed if there is no Rigidbody). The object's scale is baked into the collider shape, since Rapier has no scale. `Mesh` uses `MeshGeometry`. Kinematic bodies follow `Transform`, then fixed steps of 1/60 (at most 5 per frame), then dynamic bodies write their pose back. Rapier 0.36 computes in glam 0.33, converting through arrays. Tests: a box lands on the ground, a ball lands on a mesh floor, a ball passes through a trigger.

## olvin (facade)

The `window` and `render` features are on by default. `scene` adds `scene_file::{load, spawn}`: loads an editor scene into the `World`, only active objects. Components are carried over as data (`LightDesc`, `ColliderDesc`, `RigidbodyDesc`, `AudioSourceDesc`, `Scripts`, `AudioListener`, `Name`, `Tag`); a Mesh Collider on a primitive gets a `MeshGeometry`. An object with `poly` gets its own mesh (triangulated) and a `MeshGeometry` for its Mesh Collider. Each `LightDesc` gets a runtime `olvin_render::Light` (`runtime_light`). `apply_lighting(scene, &mut RenderSettings)` carries the sun and the `Environment` into the render settings (it does not touch vsync or other window options); both the loader and the editor use it. A brush with a Rigidbody is not part of the level: it becomes a separate body with its own mesh and a convex collider. The first Directional Light sets `RenderSettings.light_dir/light_color`. CSG is built on load: meshes grouped by face colour, plus one "CSG Level" entity with a static mesh collider. The hierarchy is kept: `Transform` is local, `Parent` links the children, and `GlobalTransform` is set right away to the world matrix. `physics` pulls `olvin_physics` into `DefaultPlugins`. Without it you get the bare core + ECS (servers, tools). `DefaultPlugins` adds everything that is enabled. There is a `prelude` for games. The `script`/`input`/`audio` features attach their plugins; `Scripts`/`AudioListener` in `scene_file` are their types, and a loaded scene starts its scripts, characters and sound immediately. `render_assets.rs` (feature `scene`): `RenderAssets` is a cache from path to handle for materials, textures, shaders and the sky, with hot reload by mtime (every 0.5 s), `Registries`, `material_in(res, path)`, `poly_mesh_data` (UVs with V flipped). `RenderAssetsPlugin` is in DefaultPlugins; the root is set by `scene_file::load` (the `assets` folder above the scene). The loader hands materials to meshes, poly meshes and the CSG level (groups by (colour, material), box UVs) and sets the sky. Re-export of `olvin::csg`.

## olvin_ui

The shared UI kit of the editor and the hub: it depends only on `egui` and `serde` (no eframe). The hub installs the editor from the same repository (path or git, `EngineSource::crate_dependency`), so a crate under `crates/` is available to the editor install without changes in the hub; `engine_fingerprint` already walks `crates/`.

- `lib.rs`: `Palette`, the STYLE.md tokens as fields (`bg`, `surface`, `surface_raised`, `glass`, `glass_strong`, `footer`, `text`, `text_2`, `muted`, `faint`, `ghost`, `accent`, `accent_glow`, `accent_border`, `on_accent`, `warn`, `error`, `info`, `line`, `line_top`, `line_soft`, `logo_ring`, plus `selection`, `shadow`, `shadow_popup`, `dark`), constants `Palette::{DARK, LIGHT, GRAPHITE, HIGH_CONTRAST}`. `ThemeKind` (serde, `ALL`, `label()`, `palette()`). `apply(ctx, kind)`: fonts once per context (Inter/JetBrains Mono, the families `bold()`/`mono_bold()`), `visuals(&palette)` for both egui themes, spacing, text sizes, the palette in `ctx.data` → `palette(ctx)`, `kind(ctx)`. `set_reduce_motion`/`reduce_motion` (also egui's `animation_time`). `RADIUS_XS…PILL`, `FS_XS…FS_2XL`, `caps`, `menu_title`, `contrast`/`luminance` (WCAG). Fonts take effect from the next pass, so call `apply` before the first frame. Test: the text tokens of every theme are ≥ 4.5:1 on `bg`/`surface`/`surface_raised`/`footer`, and the accent is ≥ 3:1.
- `logo.rs`: the wordmark and mark from the geometry of `olvin-wordmark.svg` (SVG units, height 68, stroke `W` = 12): the ring O (`circle_stroke`), the cursor "l", the v from two convex quadrilaterals, i, and n as one polyline. `wordmark(ui, h)`, `mark(ui, size)`, `wordmark_intro(ui, h, t0)` (500 ms delay, letters typed one by one in 70–130 ms, the cursor moves ahead of them and returns to the "l" slot), `paint_wordmark`/`paint_mark` for custom layouts, and `cursor_visible` (step-end over 1 s, a single `request_repaint_after` until the next switch).
- `anim.rs`: `ease_out`/`ease_pop`/`ease_std` (`cubic_bezier` as in CSS), `HOVER`/`PRESS`/`PANEL`/`LAUNCHER`, `toward`, `fade`, `hover_t`, `value`, `lerp_color`, `stagger`/`restart`, `appear`, `pulse`, `button_colors`/`button` (a selectable button with a smooth hover and selection; it reads the state from the previous frame via `next_auto_id`). Under reduce motion everything jumps straight to its final value.
- `tests/render.rs` (ignored): `egui_kittest` + wgpu draws a sample of each theme and the logo into `target/tmp/olvin_ui/*.png` (llvmpipe: `__EGL_VENDOR_LIBRARY_FILENAMES=…/50_mesa.json WGPU_BACKEND=gl cargo test -p olvin_ui --test render -- --ignored`).

## editor (olvin-editor)

A scene editor on egui 0.36 + egui_dock 0.21, Blender + Unity style, interface in English. It is installed separately, and individual elements attach to it as plugin crates. The hub generates an install crate whose `main.rs` lists the plugins. Plugins are linked statically, without dylibs: that is faster and avoids ABI problems.

- `lib.rs`: `run(plugins)`; the first command-line argument is the project folder. Native options: wgpu, depth 32, MSAA 4. The editor and the engine run on one wgpu 30 (egui 0.36). It re-exports egui, egui_dock, glam and olvin_scene, so plugins build against exactly the same versions.
- `registry(plugins)` builds the registry (base panels + plugins), `build_app(cc, registry, project)` creates the `EditorApp` in the eframe context (theme, `render::init`); `run` uses both. `EditorApp::{state_mut, reset_layout, show_workspace}` are for running without a window. It re-exports `DEPTH_FORMAT` and `MSAA`.
- Screenshots for the README: `apps/editor_dev/tests/screenshots.rs` (`#[ignore]`). It uses a demo project in a temp folder, all elements, and egui_kittest with its own renderer (MSAA 4 + depth 32, as in eframe; without them the viewport pipelines do not match the pass). It writes `docs/screenshots/editor-{dark,light,modeling}.png` (or `$OLVIN_EDITOR_SHOTS`). Run it with `__EGL_VENDOR_LIBRARY_FILENAMES=/usr/share/glvnd/egl_vendor.d/50_mesa.json WGPU_BACKEND=gl cargo test -p editor_dev --test screenshots -- --ignored`.
- Window icon: `window_icon()` in `lib.rs` embeds `assets/logo/png/olvin-icon-256.png` (`include_bytes!` from `CARGO_MANIFEST_DIR`) and decodes it with `eframe::icon_data::from_png_bytes`; it is passed to `ViewportBuilder::with_icon`.
- `registry.rs`: the traits `Panel` (`ui(ui, &mut EditorState)`, one instance per tab) and `EditorPlugin` (`build(&mut Registry)`). `PanelKind`, `WorkspaceTemplate`, `TabAlloc`. Extension points: `add_viewport_extension`, `add_component`, `add_create_item`.
- `ext.rs`: the API for elements. `Geometry` (world polygons with `GRID`/`SELECTED` flags, lines with depth and lines drawn on top, `raycast`), `ViewCamera` (project, ray, world_per_point, an egui line with near-plane clipping), `Ray` (plane, triangle, closest point on a line), `Snap`, `ToolDesc`, `ViewportCtx`, the trait `ViewportExtension` (`geometry`, `interact`, `tools`), `ComponentEditor`, `CreateItem` (a path like "CSG/Box" makes a submenu).
- `engine.rs`: the engine inside the editor. `EngineGpu` (in the egui callback resources): a `RenderCore` on egui's device, `GpuMeshes` for editing and for play, a `ViewData` per panel. `ScenePreview` is an ECS world rebuilt from the scene each frame (meshes, poly meshes, cameras, lights). `Shading::{Solid, Rendered}` (per viewport, Shift+Z or the toolbar): Rendered = `settings_for` (the same as in the game); Solid = studio light from the camera, `RenderSettings.scene_lights = false`, no fog or tone mapping. `render_shadows` is called from `CallbackTrait::prepare` in render.rs on egui's encoder, before the pass that reads the map. `prepare_view(state, id, frame, view_proj)` prepares a view: in Play it is the game world, otherwise the preview. `PlaySession` is a real `App` with `EcsPlugin`, `TransformPlugin` and `PhysicsPlugin`; the scene loads through `olvin::scene_file::spawn`. There is pause and single-frame stepping.
- `render.rs` + `viewport.wgsl`: the GPU viewport draws straight into egui's render pass through `egui_wgpu::CallbackTrait`, into a shared depth buffer. First the engine's renderer (`Frame.engine`) draws the meshes, then the editor's geometry goes on top. Pipelines: meshes (lighting, a triplanar 1 m and ¼ m grid for `GRID`, selection highlight), an infinite adaptive grid (a fullscreen triangle, ray-plane intersection, `frag_depth`, fading of small lines via `fwidth`, the X and Z axes), and lines with depth and lines on top. Per-viewport buffers grow to powers of two.
- `state.rs`: `EditorState` holds the scene, the path, the project, the selection, `preview` (pose overrides, not saved), the log, `scene_generation`, the active tool (`tools::{VIEW, MOVE, ROTATE, SCALE}` or an element id), `local_space`, `SnapSettings { enabled, step: Option (None = adaptive), angle_deg }`, and extensions. Undo/redo uses snapshots: changes are committed when the mouse and keyboard are released, so a drag counts as one step. Operations: `create/delete/duplicate/reparent/move_sibling`, `open/save/save_as/new_scene`, `request_open`.
- `workspace.rs`: `Tab { kind, id }`, `Workspace { name, dock: DockState<Tab> }`, `Layout` (the workspace tabs, saved to `<config>/olvin-editor/layout.ron` on exit). Duplicating gives the tabs new ids, and the copies have independent panel state.
- `app.rs`: the menus (File/Edit/GameObject/Window). GameObject works as in Unity: Create Empty, 3D Object/…, Light/…, Audio/…, Camera, and the element items. Primitives are created with their own collider; a camera gets an Audio Listener. If a tool set `state.tool_owns_keys`, Delete and Ctrl+D go to it. Workspace tabs work like browser tabs (click; double-click to rename; middle-click or × to close; right-click to duplicate or move; "+" for a template, empty or a copy), a DockArea (dragging, splitting, pop-up windows, a "+" in each tab group), hotkeys (Ctrl+S/N/Z/Shift+Z/Y/D, Del/X), a confirmation when there are unsaved changes, a status bar, and the window title.
- `theme.rs`: a thin wrapper over `olvin_ui` (it re-exports `Palette`, `ThemeKind`, `palette`, `anim`, `logo`, `caps`, `menu_title`, `bold`, `RADIUS_*`, `FS_*`). The constants `BG…LINE_SOFT` are the tokens of the **Dark** theme (`Palette::DARK`), kept so that panels and plugins compile without changes; the old names `BACKDROP`/`RAISED`/`TEXT_WEAK` are aliases. The chrome (top bar, status bar, dock, menus, buttons) takes its colours from `theme::palette(ctx)` and follows the selected theme; egui widgets follow it through Visuals. Outside STYLE.md: `SELECTED`, `AXIS_*`/`AXES`, `VIEWPORT_BG` (the viewport does not depend on the theme; `Viewport` and `Game` set their own dark-theme Visuals so overlays read on the dark scene). `apply(ctx)` reinstalls the current theme, `apply_kind(ctx, kind)` changes it. `dock_style(style, &palette)` gives pill-shaped tabs with the focused one inverted; `eased_tab_style` smoothly (ease-std, 200 ms) moves a tab between inactive → front → focused through `TabViewer::tab_style_override`. The top bar: the wordmark `olvin_ui::logo::wordmark` at 16 px (the cursor blinks once a second through `request_repaint_after`), the menus, the workspace tabs, ▶ ⏸ ⏭ in the centre; the menu titles, tabs, ⚙ and ▶ use `anim::button` (hover and selection fade). `EditorApp::sync_theme` checks the theme and "Reduce motion" against `Preferences` every frame; the Play tint is applied on top. Status bar: `● PLAYING` with a "breathing" dot (`anim::pulse`), or `PAUSED`; a new log message fades in (`anim::appear`). Pop-up menus and windows appear through egui's `animation_time` (0.18 s, 0 under reduce motion).
- `assets/fonts/`: Inter 4.1 and JetBrains Mono 2.304 (Regular + Bold, static TTFs), with the licences `Inter-OFL.txt` and `JetBrainsMono-OFL.txt`. `olvin_ui` embeds them through `include_bytes!` from `CARGO_MANIFEST_DIR` (`/../../assets/fonts/...`).
- Selection (`state.rs`): `selection` is the active object, `multi` holds the rest; `select`, `toggle_selected` (Ctrl+click in the hierarchy and viewport), `select_range` (Shift in the hierarchy). Move moves everything selected, and Delete/Ctrl+D act on the whole selection. A hierarchy row: click selects, dragging changes the parent.
- `panels/viewport.rs`: the camera works as in Unity: middle-drag to pan, Alt+LMB to orbit, Alt+RMB to zoom, RMB to look around, with WASD/QE to fly (Shift speeds up, the wheel changes speed while RMB is held), Hand (Q)+LMB to pan, wheel, F. A clickable view gizmo: the axes ±X/±Y/±Z switch to that view, the centre toggles Persp/Iso (orthographic). Primitives come from `olvin_scene::primitives` with smooth normals; inactive objects are hidden; the viewport light comes from the scene's Directional Light. Gizmos for the selected object's components: colliders (green), lights (rays, sphere, cone), sound radii, the Character Controller. The light and sound icons are clickable. Tools: Q/W/E/R and element tools; X toggles Global/Local. Gizmos: Move (axes by the nearest point on the ray, planes, a free handle in the screen plane), Rotate (axis rings with the front half-arc, a view ring, the angle from the screen angle around the centre), Scale (axes with cubes, uniform). A drag is computed from a snapshot of the start: position snaps to the absolute grid on world axes and to a step on local ones; the angle snaps in 1–90°, scale in 0.1. Ctrl inverts Snap. Auto step is a power of two from the camera height, matching the grid. Frame order: extensions → gizmo → ray picking → geometry assembly → a callback into a slot reserved in advance in the painter (3D under the overlays). A toolbar and an axis indicator at the top.
- `prefs.rs`: `Preferences` (theme `theme: ThemeKind`, `reduce_motion`, UI scale, camera sensitivity/inversion/fly speed/zoom/FOV, the default view Solid/Rendered, shadows and fog in the editor windows, the statistics overlay) in `<config>/olvin-editor/preferences.ron`.
- `settings.rs`: the Settings window (Edit → Settings…, Ctrl+, or ⚙ at the top right): pages Rendering (the scene environment `environment_ui` + editor window quality), Scene Camera, Interface, Keymap. It saves `Preferences` when they change. `engine::editor_quality` applies the shadow and fog settings to all editor views; `state.render_stats` holds the last frame's statistics per view (an overlay in the corner of the viewport).
- `panels/lighting.rs`: the Lighting window and the Lighting workspace: the "Render Settings…" button, presets and a list of all lights; the environment itself (`environment_ui`) lives in Settings → Rendering.
- Lights in the viewport: the icon is a disc in the light's colour with a type glyph and a direction ray. For the selected light there are handles, as in Unity: range (for Point, 4 points on the sphere's silhouette; for Spot, the cone tip along the axis) and the spotlight angle (4 points on the rim), with snapping. In the Light inspector there are quick colour temperatures (Candle…Sky, Tanner Helland's formula converted to linear colour).
- `panels/game.rs`: the Game panel shows the view from the scene's first camera; in Play it is the live game.
- Play Mode (`app.rs` and `state.rs`): ▶ ⏸ ⏭ in the top bar, Ctrl+P. During play the interface is tinted. Stop restores the scene and the undo history to the moment play started (`start_play`/`stop_play`). In Play the viewport shows the game world and does not draw the element geometry: CSG is already part of the game world.
- `panels/hierarchy.rs`: a tree with drag and drop to change the parent, search, a context menu (Create child with the element items, Rename, Duplicate, Move Up/Down, which matters for CSG order, Unparent, Delete). `create_menu` is shared with the GameObject menu.
- `panels/inspector.rs`: a header with Active / name / Tag / Layer. Collapsible sections: Transform, Mesh Renderer (mesh choice), Camera, Light, Box/Sphere/Capsule/Mesh Collider, Rigidbody, Character Controller, Audio Source, Audio Listener, Scripts (name + key–value parameters), element components. Add Component is a pop-up menu with search and categories Rendering / Physics / Audio / Scripts / Elements.
- `panels/assets.rs`: a browser for the project's `assets/`: breadcrumbs, tiles, a filter, creating a folder or a scene; double-clicking opens a scene.
- `olvin_editor_console`: a log panel with level filters.
- `olvin_editor_csg` (the CSG element): `CsgViewport` rebuilds the CSG only when the set of brushes changes (a comparison of `BrushInput`s), draws the polygons with the grid and selection highlight, and draws brush outlines in the colour of their operation (with depth, and faintly on top, so subtractions show through walls). The "Mapping" window (a panel + a workspace): modes Object / Draw / Resize / Edit Shape (= the Modeling element's Edit Mode), Boolean blocks (operation, Earlier/Later, Duplicate as Carve, Hollow, Rotate 90°, Flip), New brushes, Display, Build. The CSG no longer has its own polygon editor: a brush is modelled in the shared Edit Mode (Tab), and CSG cuts according to its shape. The Draw Brush tool (B): the ray picks the axis plane of a surface, a rectangle snapped to the grid, then the height from the ray's nearest point to the normal; dragging down subtracts, Shift always subtracts, Esc/RMB cancel. The result is a brush of the chosen shape sized from the rectangle. Resize (T): 6 face handles; a face moves along its own axis and lands exactly on a grid line, while the opposite face stays put (scale and position are recalculated in the parent's space). The CSG panel: settings for new brushes (operation, shape, colour), Hollow (a subtracting child with walls of a set thickness), Rotate 90°, Flip X/Z, Earlier/Later, display, and build statistics (brushes → polygons → triangles, ms). The CSG Brush component in the inspector, GameObject → CSG/{Box, Wedge, Cylinder, Pyramid, Stairs, Room}, the Mapping workspace. The shared settings live in a thread_local `Shared`.
- `olvin_editor_modeling` (the Modeling element): Blender-style Edit Mode for objects with `poly` and for CSG brushes (a brush stays a brush: `make_editable` puts its current surface into `poly`; selecting another brush in Edit Mode makes it editable at once; in the panel, a CSG Brush section: operation, colour, Reset to Shape, Detach from CSG). Edit Mode keys do not fire while RMB is held (WASD flight). The overlay is drawn below the toolbar (`ViewportCtx.overlay_top`). Tab enters/exits (a primitive or brush is first converted to a `PolyMesh` with `make_editable`). Shared state `Shared` (thread_local): mode, vertex selection (`verts`; edges and faces are derived from it), `hidden`, `xray`, `gizmo`, `move_by`, `status`. `transform.rs`: the shared modal G/R/S engine (`Transform::step`): axes X/Y/Z (repeat for local/normal, a third press resets), Shift+axis for a plane, numeric input (`NumInput`), Ctrl for snapping (grid / 5° / 0.1), Shift for precision ×0.1, the pivot is the median; pure functions `cycle`, `constrain_move`, `rotation`, `scaling`, `apply`. `gizmo.rs`: the move gizmo (arrows, planes, centre); dragging goes through the same engine. `cage.rs`: the frame of the cage: screen points, an edge/triangle cache, visibility (self-occlusion by rays, accelerated by `select::Occluders`, bins of triangles on a screen grid, recalculated only when the camera or mesh changes), drawing (face points in face mode, dimmed hidden ones), picking and box select. `select.rs`: pure functions `combine`, `box_edges`, `Occluders`. `edit.rs`: the viewport extension: hotkeys (1/2/3, A, Alt+A, Ctrl+I, L/Shift+L, Ctrl+L, Ctrl±, H/Shift+H/Alt+H, Alt+Z, G/R/S, E: extrude and immediately move, for faces along the normal; I, Shift+D, J, F, X, M, Shift+N, Ctrl+R, K). LMB-drag is a box (Shift adds, Ctrl subtracts); Alt+click is an edge loop, Ctrl+Alt a ring, and in face mode a face loop. A badge at the top left (Vertex/Edge/Face, X-ray, Gizmo, the operation text) and a dynamic hint. It sets `tool_owns_keys`; the viewport core sees this through `keys_owned_last_frame` and does not turn plain keys into tool switches. While Edit Mode is on, egui zoom on Ctrl+=/- is disabled. A modal operation sets `state.busy`, so the whole gesture is one undo step. The Modeling panel mirrors everything with buttons. GameObject → Mesh/{Cube, Plane, Cylinder, Sphere}, the Modeling workspace. The base viewport draws `poly` through the engine's renderer.
- Materials and assets: `materials.rs`: `MaterialLibrary` (scans `assets/`: `*.mat.ron`, images, `*.wgsl`; rereads on mtime changes; `create`, `create_shader`), `material_ui`, presets. Inspector: a Material section (choose/create, edit all fields, saved immediately). Settings → Rendering: Skybox. Assets: image thumbnails; `.gltf/.glb` by double-click or "Import into scene" (`EditorState::import_model`: hierarchy, poly with UVs, materials in `materials/<model>/`); "Create material" on an image. `ScenePreview` holds its own `Textures/Materials/Shaders` and `RenderAssets`, hands out materials, sets the sky in Rendered mode, and builds a textured CSG for brushes with a material (the CSG element keeps them only for picking). Play gets the registries, `InputPlugin` (`assets/input.ron`) and `ScriptPlugin`; the Game window passes keyboard and mouse to the game while the cursor is over it (`PlaySession::feed_input`). `EditorState.mesh_selection` is the Edit Mode selection, for other elements.
- `olvin_editor_uv` (the UV Editor element): as in Blender (no sync). The "UV Editor" panel and the "UV Editing" workspace. `view.rs`: the 2D camera; `select.rs`: selection of face corners (a UV vertex is the corners of one vertex at one UV point), modes vertex/edge/face/island; `transform.rs`: G/R/S, the X/Y axes, numeric input, Ctrl snapping; `ops.rs`: unwrap (U), projections, seams (Ctrl+E), packing (Ctrl+P), flip/rotate/align; `defaults.rs`: "only what is selected in 3D" from `state.mesh_selection`, and the material's texture under the layout.
- `olvin_editor_ide` (the IDE element, off by default): Explorer / Code / Problems / Output and the Code workspace. Syntax highlighting for Rust/WGSL/RON/TOML/Markdown, find/replace, auto-indent, bracket pairs, Ctrl+/; a background `cargo check|build|run` with JSON diagnostics; a naga check of surface shaders; the palette Ctrl+Shift+P, go to file Ctrl+E; `KeyRouter` takes Ctrl+S/N from the scene while focus is in the code. 38 tests.
- `olvin_editor_animator`: a timeline. A clip `{ length, tracks: entity id → keys }` is stored in `scene.extensions["animator"]`. It has keying by button, dragging keys, RMB to delete, scrubbing, play/loop, and a preview through `state.preview`. It adds the Animation workspace template.

## hub (olvin-hub, working name)

The hub creates game projects and installs modules into them. The source of truth for modules is the game's `Cargo.toml`; the hub keeps no state of its own about what is installed.

- `olvin_hub/catalog.toml`: the built-in catalogue. `kind = "olvin"` is a feature of the `olvin` facade (the plugin pulls in `DefaultPlugins`). `kind = "crate"` is a dependency from crates.io (rapier3d, kira, gltf, rand, serde, ron). The field `requires` installs modules together with their dependencies.
- `catalog.rs`: `Catalog` (parsing, checking `requires`, `resolve`: dependencies first, detects cycles, `categories`), `Module`, `Source`.
- `project.rs`: `Project::create` (modules with `default = true`) and `create_with(modules)` for templates, `modified()`, `open`, `discover` (searches upwards through folders), `add` (together with requires), `remove` (refuses to remove something others depend on, unless `force`), `save`. Edits go through `toml_edit`, so the user's comments and formatting are kept. `olvin` is included with `default-features = false`, and the list of Olvin modules is its `features`.
- `config.rs`: `HubConfig` in `<config_dir>/olvin-hub/config.toml` (on Linux it honours `XDG_CONFIG_HOME`): the project list, `EngineSource` (`path` to a checkout, or `git`; by default the folder the hub was built from if it exists, otherwise GitHub), and `[gui]` (`GuiSettings`: `theme` = dark/light/graphite/high-contrast, `reduce_motion`, `view` = list/grid, `sort` = modified/name, all as strings so that the core does not depend on the UI).
- `template.rs`: Cargo.toml (deps always -O3, its own empty `[workspace]`), `src/main.rs`, either graphical (it loads `assets/scenes/main.scene.ron`, or a cube if there is none) or headless when there is no window+render+scenes; a README and a .gitignore.
- `editor.rs`: `EditorInstall` in `<data_dir>/olvin-hub/editor`: a generated crate (`Cargo.toml` + `main.rs` with the plugins, binary `olvin-editor`). The source of truth is its `Cargo.toml`. Methods: `write`, `build_command` (`cargo build --release`), `launch(project)`. Freshness: `engine_fingerprint(engine)` is the maximum mtime of `*.rs/*.toml/*.wgsl` in `crates/` and `editor/`, plus `Cargo.lock`; after a build `mark_built` writes `.engine-stamp`, and `is_stale` compares. The CLI `editor open` and the GUI when opening a project rebuild a stale editor themselves; the GUI shows a banner "The engine changed…" with a Rebuild button. Editor elements are described in the catalogue as `[[editor_module]]`.
- Logo: `olvin-hub-gui` sets the window icon the same way the editor does (`window_icon()`, `olvin-icon-256.png`). The CLI prints the text logo `Olvin_` with a green `_` in the help header (`logo()` → clap `before_help`; running with no arguments shows the help). clap drops the colour under `NO_COLOR` and when output is not a terminal.
- CLI: `new`, `list`, `add`, `remove [--force]`, `run [--release]`, `projects`, `register`, `forget`, `engine [--path|--git]`, `editor install|list|add|remove|open [project]`.
- The hub, the CLI and the catalogue (module names and descriptions) are in English, and the texts follow STYLE.md §10.
- GUI (`olvin_hub_gui`, a launcher in the spirit of Unity Hub, built on `olvin_ui`; it has no theme of its own). Modules:
  - `main.rs`: `Hub` (state, actions, `poll` of cargo processes, toasts), `draw`. `sync_style` sets the theme and reduce motion. The first `olvin_ui::apply` runs in the eframe creation closure (fonts become active from the next pass, and `bold()` in the same pass would panic); the frame right after the first apply is skipped.
  - `chrome.rs`: the `--bg-radial` background (a polar mesh), the sidebar (the wordmark `logo::wordmark_intro` + "Hub", the items Projects / Editor / Settings, the selection bar slides through `widgets::tween`; below 1000 px a narrow column with `logo::mark` and icons), the status line (a status dot, Ready / Building editor / the game + Stop; on the right `ENGINE path · /…` in mono, cut off), toasts (bottom right, slide in and fade over 300 ms, click to close, errors for 8 s with an icon), page transitions (fade + a 10 px shift), `page_header` (the buttons drop under the title when the width is below 560).
  - `projects.rs`: search, the Recent / Name sort switch and the list / grid view switch as pills, an empty state. Layout by width: at ≥ 900, a table `name+path | modified | modules | actions` with shared `Columns` for the header and the rows (clicking NAME/MODIFIED sorts); 600–900, a narrow modules column; below 600, cards with a meta line "4h ago · 5 modules"; grid, cards ≥ 250 px. Module chips always stay on one line, and the overflow collapses into `+N`; paths are mono with `…`, and the full path is in the tooltip. A letter tile; the most recent project (within a week) gets the accent. Hover: a lighter background, a 3–4 px lift, a stronger shadow. Rows appear in a staircase (`anim::stagger`, with its own id for each opening of the page).
  - `editor_page.rs`: the install card (mark, version, status, Open / Install / Rebuild), elements as cards with Install/Remove. Changes accumulate (`editor_pending`) and are applied in one rebuild from a pop-up bar "N changes · Discard · Apply". A build log (cargo's stderr is read on a background thread).
  - `settings.rs`: the theme (miniature cards for every `ThemeKind`), Reduce motion, the engine source, About. Saved in the `[gui]` section of the config.
  - `dialogs.rs`: modals for New project (templates as cards, modules as toggle cards honouring `requires`, a name with validation, a path), Add project, and Modules (by category; edits go straight into Cargo.toml). They appear with `--ease-pop` (a shift + fade), radius 20, and a light top edge. Note: do not use `ui.separator()` inside a horizontal layout in the modals, since it takes all the available height and the window grows every frame.
  - `widgets.rs`: `Btn` (primary/secondary/ghost, scale 0.98 on press), line icons, `chip_line`, `pill_switch` (the highlight slides), `toggle`, `card_bg`, `tween`/`since`/`entrance`.
  - Hotkeys: Ctrl+N for a new project, Ctrl+, for settings. All animations are ≤ 500 ms and are turned off by reduce motion; a repaint is requested only while something moves (and every half second for the cursor blink).
  - Tests: `dialogs_fit_their_content`, `pages_render_at_all_widths` (470/800/1280/1920, both layouts, headless `Context::run_ui`). `shots.rs` (ignored): `egui_kittest` + wgpu through `build_eframe` draws all pages, dialogs and themes at 4 widths into PNGs (`OLVIN_HUB_SHOTS=<folder>`, on llvmpipe: `__EGL_VENDOR_LIBRARY_FILENAMES=…/50_mesa.json WGPU_BACKEND=gl cargo test -p olvin_hub_gui -- --ignored screenshots`).

## Verified

- Vulkan, RTX 3050: Full tier, 40k cubes in 2 draw calls, limited by vsync.
- GL through Mesa llvmpipe (`__EGL_VENDOR_LIBRARY_FILENAMES=.../50_mesa.json WGPU_BACKEND=gl`): Compat tier, 10k cubes, about 90 fps on the CPU rasteriser.
- GL on proprietary NVIDIA under Wayland does not work: EGL does not provide a native-renderable config, and wgpu-hal refuses to present. This is a wgpu limitation, not the engine's.
