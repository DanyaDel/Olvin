# Olvin: architecture

<p align="center"><a href="ARCHITECTURE.md">Русский</a></p>

State of the code as of 2026-11-22 (commit `0e3451e`). ROADMAP ticks are set together with the code; a mismatch is a documentation bug, please open an issue.

A modular game engine in Rust. Each subsystem lives in its own crate and is attached as a plugin. Subsystems talk to each other only through shared resources and do not depend on each other directly.

The visual style (colours, fonts, glass, motion, copy): [STYLE.en.md](STYLE.en.md). The logo, wordmark and app icon (SVG, PNG, ICO): `assets/logo/`. The roadmap: [ROADMAP.en.md](ROADMAP.en.md).

## Principles

- **Modularity at the subsystem level, not the object level.** A plugin registers systems, and a system processes all its data in one call. There are no virtual calls per object.
- **Hot paths work with flat arrays.** The renderer sorts instances by mesh into reusable `Vec`s and makes one instanced draw per mesh. In steady state a frame allocates nothing.
- **The core knows nothing about the GPU or the window.** The renderer and the platform are linked through `SurfaceTarget` (raw-window-handle), so winit can be replaced with SDL or a canvas without touching the renderer.
- **The minimum hardware level is WebGL2 / GLES 3.0.** The device is requested with `Limits::downlevel_webgl2_defaults()`. Anything stronger is enabled by `RenderTier::Full`.

## olvin_core

- `app.rs`: `App` holds `Resources`, `Schedule`, the plugin set and the runner. `add_plugin` skips duplicates of the same type, so a plugin can add its own dependencies. `run()` hands control to the runner; without it a headless loop runs. There is `startup()` (Stage::Startup, once) and `update()` (one frame). `AppExit { requested }` stops the loop.
- `resources.rs`: `Resources` are singletons keyed by `TypeId` in a `RefCell`. Methods: `get/get_mut` return an Option, `fetch/fetch_mut` panic with the type name. Different resources can be borrowed mutably at the same time, the same one cannot.
- `schedule.rs`: stages `Startup, First, PreUpdate, Update, PostUpdate, Render, Last`. A system is `FnMut(&mut Resources)`. Everything is single-threaded for now.
- `time.rs`: `Time` is updated in `First`. `delta()/elapsed()` are simulation time: multiplied by `time_scale` (`set_time_scale`, negative = 0) and frozen by `pause()`; `step()` lets one frame through while paused (frame stepping). `unscaled_delta()/unscaled_elapsed()` ignore scale and pause (UI). For tests: `Time::with_fixed_delta(dt)` / `set_fixed_delta(Some(dt))` makes every frame exactly dt with no wall clock, `advance(dt)` is a manual frame. A real frame is clamped to 0.25 s; `frame()` also counts paused frames.
- `events.rs`: `Events<T>` is a typed queue resource. `send/send_batch`, reading through a per-system `EventCursor` (`events.read(&mut cursor)`, each reader sees an event once), `clear()`. Two buffers: an event lives through its frame and the whole next one, so a reader running before the sender in the frame still sees it. `App::add_event::<T>()` creates the resource and swaps buffers in `First` (repeat calls are no-ops, safe from several plugins). Buffers are cleared, not freed: no allocations in steady state.
- `logging.rs`: a single logger with no extra dependencies. `Logging::new(filter).file("logs/x.log").init()`: the filter works like env_logger (`"info,wgpu_core=warn"`, overridden by `OLVIN_LOG`/`RUST_LOG`; `Filter` takes the longest module prefix). Lines go to stderr and to the file. A panic hook writes `crash-<unix-time>.txt` next to the log (or into `crash_dir`): message, location, thread, backtrace, the last 64 log lines, then calls the previous hook. It is used by `sandbox`, `script_demo`, the hub's game template (`logs/` is in `.gitignore`) and the editor (`olvin_editor::run`, file `<project>/logs/editor.log`). Relative `file`/`crash_dir` paths are resolved against `ProjectPaths::detect().root`, not the working directory.
- `paths.rs`: `ProjectPaths { root, assets, source }`, the "where are the game's files" resource; `App::new` inserts it (insert your own before the plugins to override). `ProjectPaths::detect()` runs once per process: `OLVIN_PROJECT_DIR`, the exe's folder if it has `assets/` (the `olvin-hub build` layout), `CARGO_MANIFEST_DIR` (`cargo run`/`cargo test`), the working directory (`PathsSource` says which one won); `OLVIN_ASSETS_DIR` replaces only `assets`. `asset(p)` and `resolve(p)` (absolute paths stay). Read by `AudioPlugin`, `InputPlugin`, `Logging` and the hub template; `detect_from(env, exe)` for tests.
- `surface.rs`: `SurfaceTarget { handle: Arc<dyn WindowHandleSource>, size, scale_factor }` (display scale, screen-space UI multiplies its sizes by it; `with_scale_factor`), the contract between the platform and the renderer.
- `profile.rs` (feature `profile`, puffin 0.20, pure Rust): `profile_scope!("name")` (a literal; expands to nothing without the feature), `SystemScope::register/enter` (zero-sized without the feature), `set_enabled`/`is_enabled`, `new_frame`, `Collector` (a puffin sink; `latest()`/`recent(n)` return `FrameProfile { scopes: Vec<ScopeTiming { name, depth, thread, start_ns, duration_ns }> }`). `Schedule::add` registers a scope per system under its type path (`olvin_core::time::update_time`; for closures the path of the enclosing function without `{{closure}}`) and one per stage (`stage Update`); `Schedule::run` wraps the calls in them. Scopes are recorded only after `set_enabled(true)` (otherwise one atomic load): `OLVIN_PROFILE=1` in a game, the Profiler panel in the editor. `App::update` cuts profiler frames itself (`new_frame`); a host that owns the frame turns that off with `set_profile_frames(false)` (the editor). Engine scopes: render (`render frame/prepare…/shadow pass/scene passes/submit and present`), physics (`physics step`, `physics fixed step`, `physics fixed systems`), scripts (`script update pass`, `script fixed_update pass`). Feature `profile-http` (puffin_http 0.17): `OLVIN_PROFILE_HTTP=1` (or `addr:port`, default 127.0.0.1:8585) starts a server for `puffin_viewer`; `profile::serve(addr)` does the same from code. The `olvin` facade forwards both features (`olvin/profile`, `olvin/profile-http`). puffin_egui is not usable: it targets egui 0.33 and the editor is on 0.36, so `olvin_editor_profiler` draws the views itself.

## olvin_ecs

Re-exports the hecs types (`World`, `Entity`, `Query`, `CommandBuffer`, …). The rest of the code imports them only from here, so the ECS backend can be replaced in one place. `EcsPlugin` inserts the `World`. 3 tests for the facade contract (filtered queries, `CommandBuffer`, `EntityBuilder`).

## olvin_scene

`Transform` (translation/rotation/scale, `matrix()`, `looking_at`, `forward/right/up`) and `Camera` (perspective, right-handed, depth 0..1 through `glam::camera::rh::proj::directx`). Runtime components `Name`, `Tag`, `MeshGeometry` (triangles for mesh colliders). `primitives.rs`: `Shape` (Cube, Sphere, Capsule, Cylinder, Plane, Quad, sizes as in Unity) and `Primitive` (positions, normals, indices, an outline for selection). This is the shared geometry source for the engine and the editor. No dependency on the ECS or the GPU.

`action.rs` (always compiled, serde via the `serde` feature): Blender-style object animation. `Action { fps (24), frame_start (1), frame_end (250), autoplay, looping, curves }`, `FCurve { object, prop: Prop::{Location, Rotation, Scale}, index, extrapolation, keys }`, `Key` (a `BezTriple`: frame, value, absolute left/right handles, `Interp::{Constant, Linear, Bezier}` of the segment after it, `HandleType::{Free, Auto, Vector, Aligned, AutoClamped}`, `select` flags, not saved). Ported from Blender 4.x: `recalc_handles` (`BKE_nurb_handle_calc` for F-curves: 2.5614 handle factor, 5x neighbour clamp, Auto Clamped flat at extrema and clamped to neighbours' values, first/last key flat for constant extrapolation), `eval` (`fcurve_eval_keyframes`: 0.01-frame key threshold, handle overlap correction `correct_bezpart`, bezier solved on x(t) then y(t), constant / linear extrapolation), `insert_key` (replace on the same frame, inherit the previous key's interpolation). `Action` ops: `insert_key/insert_vec3`, `delete_keys_at`, `key_state` (`KeyState::{None, Keyed, Animated, Changed}` = Blender's yellow / green / orange fields), `jump_frame`, selection, `move_selected`, `scale_selected`, `translate_selected` (graph grab, a lone handle turns Aligned), `snap_selected`, `duplicate/delete/copy/paste`, `set_interp/handle_type`. Rotation is Euler degrees interpolated per channel (no slerp). Tests compare against values from an independent reference implementation (keys 0@1, 10@10, 0@20: flat middle handles, no overshoot).

## olvin_window

- `lib.rs`: `WindowPlugin { title, width, height, resizable }` installs the runner on winit 0.30 (`ApplicationHandler`). The window is created in `resumed`, because Android requires that. There `SurfaceTarget` is inserted and `app.startup()` is called. A frame is `RedrawRequested → app.update()`. On Resize, `SurfaceTarget.size` is updated, on `ScaleFactorChanged` `scale_factor` is.
- `settings.rs`: `WindowSettings { mode: WindowMode::{Windowed, Borderless, Exclusive}, width, height }` is a request resource the runner applies after each frame (like `CursorOptions`): `set_mode`, `set_resolution`, `toggle_fullscreen`; RON `load/save/load_or` (`assets/window.ron`). Size is logical in a window and a physical video mode in Exclusive (closest via `Monitors::closest`, Borderless if the list is empty). `Monitors { modes }` lists the monitor's video modes for menus (`resolutions()`). `WindowPlugin.mode` and `with_settings` set the start; a manual window resize is written back to `WindowSettings`. The logic is tested without a window; the actual mode switch on winit is not.
- `tests/window_smoke.rs`: a real-window smoke test (hidden window, `any_thread`; `WindowPlugin { visible, any_thread }`): skipped without `OLVIN_WINDOW_SMOKE=1` and a display; CI runs it under `xvfb-run`.
- `input.rs`: `Input` stores pressed keys and mouse buttons, `just_pressed/just_released`, the cursor position and the raw `mouse_delta` from `DeviceEvent`. It is reset in `Stage::Last`; losing focus releases everything.

## olvin_transform

`Parent(Entity)` and `GlobalTransform(Mat4)`. `TransformPlugin` calls `propagate` in `Stage::PostUpdate`: missing `GlobalTransform`s are added, roots get a global matrix equal to their local one, children are computed with a cache, and cycles are cut. `world_matrix(world, e)` gives the world matrix right away, before propagation (physics uses it). The plugin is part of `DefaultPlugins` and `RenderPlugin`. 5 tests: hierarchy levels, the plugin in PostUpdate, scale/rotation, detaching from a parent, a dangling parent, cycles.

## olvin_anim

Pure animation, no GPU or window (depends on `olvin_core`/`olvin_ecs` only for the plugin).
- `skeleton.rs`: `Skeleton` (`Joint { parent, target, rest, inverse_bind }`, any order, a cycle is an error), `JointPose`, `Pose`; `globals`, `skin_matrices` (`global * inverse_bind`). `target` is the node id in the source file; clips find joints through it.
- `clip.rs`: `Clip { channels, events }`, `Channel` (translation/rotation/scale; Step, Linear with slerp, glTF CubicSpline), `Clip::apply(time, skeleton, pose)`, clip events (`events_between`).
- `graph.rs`: `AnimGraph` (`State`s with `Motion::{Clip, Blend1D}`, `Transition`s with conditions on `Params`, `exit_time`, cross-fade), `Params` (float/bool/trigger; the first transition that fires consumes a trigger), `LayerState::update/pose`. No new transition starts during a cross-fade.
- `animator.rs`: component `Animator { skeleton, clips, params, layers, pose, matrices, version, events }` (layers blend by `weight` and a joint mask); `AnimPlugin` advances every `Animator` in `Update` by `Time::delta` and sends `Events<AnimationEvent>`. It is added by `RenderDataPlugin` (so by `RenderPlugin` too), `DefaultPlugins` and `HeadlessPlugins`.
- `object.rs`: `ActionPlayer` (resource started by `AnimPlugin`): plays the scene's object animation (`olvin_scene::action::Action`, F-curves) in game time. Finds entities by `SceneId`, writes `Transform` (Euler YXZ like `EntityDesc`; channels without a curve keep the authored base values passed to `ActionPlayer::new`). Loop period is `frame_end - frame_start`, so a clip whose last key repeats the first loops seamlessly. `olvin::scene_file::spawn` fills it from `SceneFile::animation` (autoplay / loop flags).
- `tests.rs`: 15 tests (sampling, skeleton, graph, layers, events, plugin, action player).
- `Channel::sample(NaN)` returns the first key; a NaN step no longer poisons layer/`ActionPlayer` time; `JointPose::from` of a zero-scale matrix has a finite rotation.

## olvin_render

- `lib.rs`: `RenderPlugin { settings }`, `RenderSettings` (vsync, low_power, clear_color, light_dir/light_color/light_shadows, the fallback sun; ambient (sky) + ground_ambient, exposure, `tonemapping: Tonemapping::{None, Aces}`, `fog: Option<Fog>`, shadow_distance, shadow_map_size), the component `MeshRenderer { mesh, color }`, `Color` (linear RGBA). The plugin adds `RenderDataPlugin`, the resource `RenderStats`, and the systems `init` (Startup) and `render` (Render). `RenderDataPlugin` is the GPU-free half of the renderer: `EcsPlugin`, `TransformPlugin`, `AnimPlugin`, the `Meshes/Textures/Materials/Shaders` registries, the particle simulation and CPU skinning in `PostUpdate`; headless games (`olvin::HeadlessPlugins`) add it without `RenderPlugin`.
- `core/`: `RenderCore`, rendering without a window. Split by subsystem: `mod.rs` (shared types: `RenderCore`, `GpuMeshes`, `ViewData`, `Globals`, `InstanceRaw`, the GPU asset structs, `camera_view_proj`), and each sibling adds its own `impl RenderCore` block: `init.rs` (device, samplers, default textures, `create_view`), `assets.rs` (mesh and texture uploads, material bind groups, surface shader compilation), `shadows.rs` (sun cascades and the depth pass), `frame.rs` (`prepare` and `draw`); `instancing.rs` holds batching (`InstanceSet` by material and mesh, `BlendSet` sorted back to front). The offscreen GPU tests live in `core/tests/` (a shared `Harness` and one file per area). Pipeline, layout and buffer constructors are in `pipelines.rs`. Pipelines are created for a specific colour format, MSAA and depth. If the target is not sRGB (as in egui), gamma is encoded in the shader. `GpuMeshes` are GPU copies of one `Meshes` registry, `ViewData` is the data of one camera (a uniform buffer and instances). Methods: `upload`, `prepare(view, gpu, world, view_proj, settings)` (walks `(GlobalTransform|Transform, MeshRenderer)` with sphere culling, buckets by mesh, one instance buffer) and `draw(view, gpu, pass)` into someone else's render pass. `camera_view_proj(world, aspect)`. Order per view: `prepare` → `render_shadows(view, gpu, encoder)` → `draw`. Each `ViewData` has its own shadow map (Depth32Float, created lazily; a 1×1 stub until then), a 2×2 atlas of cascade tiles (see below); each cascade's casters are culled against its own box. A pixel test draws a cube into an offscreen texture (verified on Vulkan and llvmpipe).
- `renderer.rs`: the windowed `Renderer` = `RenderCore` + surface. It creates the instance with a display handle (for GLES/Wayland), the adapter and the device with WebGL2 limits, and determines `RenderTier` (`tier_of`). `RenderStats { draw_calls, instances, culled, triangles }` (per frame, overwritten every frame; triangles = mesh indices / 3 × instances over all draws). `gl_check.rs`: the proprietary NVIDIA driver (vendor 0x10de, not Mesa/nouveau) + GL + Wayland does not present (a wgpu limitation); `check_gl(&GlCheckInput) -> GlCheck::{Fine, UseVulkan, Warn}` (a pure function, tested with fake adapters): when `WGPU_BACKEND` is unset `Renderer::new` re-creates the instance with Vulkan only, otherwise (or when Vulkan is missing) it logs one warning with the fix (unset `WGPU_BACKEND` / use Vulkan / llvmpipe via `__EGL_VENDOR_LIBRARY_FILENAMES=…/50_mesa.json WGPU_BACKEND=gl`). Mesa llvmpipe is not affected. With vsync it uses Fifo, otherwise Mailbox or Immediate. Also `begin_pass` and `create_depth`. The crate re-exports `wgpu`.
- `light.rs`: the component `Light { kind: LightKind::{Directional, Point, Spot}, color (linear), intensity, range, spot_angle_deg, shadows, shadow_bias, size }`; forward = −Z from `GlobalTransform`. The first directional `Light` replaces the sun from the settings; the others are the nearest up to `MAX_LIGHTS = 16` after frustum culling, packed into a uniform (std140). The shadow camera: a sphere around the first `shadow_distance` metres of the frustum, snapped to texels (no shimmer).
- `mesh.rs`: `Vertex { position, normal }`, `MeshData` (`cube`, `plane`, `from_triangles`, `bounding_sphere`). `Meshes::add` returns a `MeshHandle` before the GPU copy exists; uploading is lazy. `Meshes::set` re-uploads geometry into the same slot (mesh editing in the editor).
- `texture.rs` / `material.rs` / `shader.rs`: the registries `Textures` (`TextureData { width, height, format: TextureFormat::{Rgba8Srgb, Rgba8Linear, Rgba16Float, Rgba32Float}, pixels }`, mips on the CPU, sRGB averaged in linear space; Rgba32Float is uploaded as Rgba16Float, since only that one is filterable on WebGL2), `Materials` (`Material` mirrors `MaterialDesc` with handles instead of paths; `MeshRenderer { material: None }` is drawn with `Material::fallback()`) and `Shaders` (surface shaders). Like `Meshes`, the registries work before the GPU exists; `RenderCore::upload_assets(gpu, textures, materials, shaders)` is called next to `upload`. Custom WGSL is placed before the template (`globals.wgsl` + `mesh.wgsl`), so line numbers in errors match the file. naga validates on `add`/`set`, the pipeline is created in an error scope, and on failure `Shaders::error(h)` is set while the last working pipeline stays. `validate_surface_shader(src)` is for editors. PBR: GGX + Smith + Schlick (metallic-roughness, the Unity convention), normal map, ORM, emissive, alpha cutoff, unlit, triplanar; ambient specular samples the sky along the reflection. `RenderSettings.sky: SkyMode::{Color, Procedural{..}, Texture{texture, rotation, intensity}}` is a fullscreen triangle on the far plane in the same pass (and in the editor's pass), with a sun disc from the first directional light, and fog at the horizon fades into the sky. Instances are grouped by (material, mesh) and ordered (pipeline, material, mesh), with no allocations. `RenderCore::set_time`. WebGL2: 9 attributes (Vertex = position, normal, uv, tangent, 48 bytes), 5 varyings, 2 bind groups, 6 textures. 33 tests on Vulkan and llvmpipe GL.
- Transparency: `Material.blend: BlendMode::{Opaque, Alpha}`. Blended instances leave the main list for a `BlendSet`: `prepare` computes the depth of the bounding-sphere centre along `view_plane`, `sort_unstable_by` (far first, ties by key so they still batch), and consecutive (material, mesh) runs share a draw. `draw` order: opaque, sky, blended (a separate pipeline: `ALPHA_BLENDING`, no depth writes, `Less` test). Blended meshes don't cast shadows. Surface shaders get their blend pipeline lazily (`SurfacePipeline { module, opaque, blend }`, `build_blend_pipelines` in `upload_assets`). No allocations in steady state.
- Cascaded shadows (`light.rs::fit_cascades`, `RenderSettings.shadow_cascades/shadow_filter/shadow_filter_radius`): the first `shadow_distance` metres are split into up to `MAX_CASCADES` (4) slices (0.6/0.4 logarithmic/uniform; uniform for orthographic cameras), each with its own orthographic camera around the slice's bounding sphere, snapped to texels. One `Depth32Float` is a 2×2 atlas (the whole map for one cascade); `render_shadows` is a single pass with a `set_viewport` per cascade; the sampling matrices in `Globals` are already shifted into the tile. In `mesh.wgsl`, `sun_shadow` picks the cascade by depth, blends over the last 10% into the next one, falls through to the next when the lookup (kernel included) leaves the tile, and fades out at `shadow_distance`. Filter `ShadowFilter::{Hard, Pcf (3×3, default), Soft (16 taps on a rotated disc, gradient noise), Pcss}`; `RenderCore::tier()` (from the backend; `set_tier` overrides): Compat is limited to 2 cascades, and Soft / Pcss fall back to Pcf.
- PCSS (sun, `ShadowFilter::Pcss`, `pcss_filter` in `mesh.wgsl`): a 16-tap rotated-disc blocker search in the pixel's own cascade (`PCSS_SEARCH` texels) averages the occluder depth; the gap to the receiver (metres, from `Globals.shadow_depth` = world length of the cascade's depth range) times the sun's angular radius (`Light.size` in degrees, `RenderSettings.shadow_light_size` for the fallback sun; `shadow_cfg.w` = tan of the radius) over the texel's world size (`shadow_texel`) is the filter radius (up to `PCSS_MAX_RADIUS` texels), then a 16-tap comparison filter. No blockers = lit. The blocker search reads raw depths with `textureLoad` on a depth texture, which GLSL cannot do: `shader::for_device` swaps `shadow_depth_at` for a stub where the backend is GL / WebGL2, and `RenderCore::pcss_shader` (set once, at pipeline creation) keeps the filter off there. So PCSS is Full only and offscreen tests of it need a native Vulkan / Metal / DX12 adapter (they skip under `WGPU_BACKEND=gl`).
- Spot / point shadows (`light.rs::{fit_spot, fit_point, assign_tiles, atlas_matrix}`, `core/shadows.rs::plan_local_shadows`, `Light.shadows` + `shadow_bias`, `RenderSettings.max_spot_shadows/max_point_shadows/local_shadow_size`): a second `Depth32Float` per view (`ViewData.local_map`, created lazily, binding 5 of group 0) is a 4×4 atlas of tiles (`MAX_LOCAL_TILES = 16`): a spot light takes one tile (a perspective camera, FOV = cone + 8°, up to 150°), a point light six (faces +X −X +Y −Y +Z −Z, each slightly overscanned, tan(half) = 1.1, so a filter never crosses a face edge; no cube arrays, so it works on WebGL2). `plan_local_shadows` ranks the casting lights in the frustum by `importance` (luminance × range / (1 + gap to the camera)²) and `assign_tiles` hands tiles out within the caps (default 4 spot + 2 point = 16 tiles; Compat 2 + 1 = 8; slots are exhausted first, extra casters stay unshadowed, nothing panics). Each tile is a `Cascade` (its own matrix buffer and casters, culled against its frustum), all drawn by one extra depth-only pass (`render_local_shadows`, `set_viewport` per tile). `PackedLight` got a fourth vec4 `shadow` (first tile + 1, bias in texels, texel size per metre, point flag); `Globals.local_view_proj` holds the 16 world→atlas matrices. `local_shadow` in `mesh.wgsl` is called from the light loop: for a point light it picks the face by the dominant axis of the (offset) direction from the light; the lookup is shifted along the normal and towards the light by `bias` texels at that distance (the same normal-offset approach as the sun, on top of the pipeline's slope-scaled depth bias); PCF 3×3 / 16-tap disc by `shadow_filter` (Pcss counts as Soft here), clamped inside the tile (outside = lit). Scene format: `LightDesc.shadow_bias` and `size` and the `Environment` fields `shadow_filter/shadow_cascades/max_spot_shadows/max_point_shadows/local_shadow_resolution` all have serde defaults (old files load unchanged, `FORMAT_VERSION` is not bumped); new lights cast shadows only if they are directional. Editor: Settings → Rendering → Shadows (filter, cascades, limits, local resolution) and the light inspector (Cast Shadows, Shadow Bias, the sun's Size). Tests: `core/tests/lighting.rs` (spot, point side / flip / seams, caps, PCSS widths, Compat); `OLVIN_SHOTS_DIR=… cargo test -p olvin_render` writes PNGs of them.
- `post.rs` / `post.wgsl`: `PostProcess`, the Full-tier post-processing chain. The window draws the scene into `HDR_FORMAT` (Rgba16Float, `RenderCore::set_hdr_output(true)`: the shaders skip exposure, tonemapping and sRGB), then fullscreen passes: bright-pass + downsample to 1/2, to 1/4, Gaussian blur H/V, and a composite (bloom + exposure + ACES/clamp + sRGB if the target isn't sRGB). `RenderSettings.bloom: Option<Bloom { threshold, intensity }>` (off by default). Then `RenderSettings.post: PostSettings`: `fxaa` (FXAA 3.11, quality preset 12, after tonemapping; the composite writes to an intermediate target in the surface format; on by default), `ao: Option<AmbientOcclusion { radius, strength, bias }>` (world-space GTAO from the depth: 2 slices x 5 steps per side, a 4x4 ordered-dither pattern and a depth-aware blur along the tangent plane; multiplied onto the colour, fading on bright pixels; off by default: the only costly effect and it changes every scene's look; `PostProcess` owns the depth texture and the scene pass keeps it (`begin_scene_pass(.., keep_depth)`) only when AO is on; the depth is read as a `texture_2d<f32>` with `textureLoad` because `texture_depth_2d` does not translate to GLSL) and `grade: ColorGrade { lut, lut_strength, saturation, contrast, lift, gamma, gain }` (after tonemapping, on sRGB-encoded colour; the LUT is an N slices of N² strip (32 -> 1024x32, `lut_strip` / `identity_lut`), `Rgba8Linear`, bound by `PostProcess::sync_lut`; neutral grading is skipped). Bind group 1 of the post pipelines: depth, AO, LUT (two sets: while AO is written it is not bound). `run(.., view_proj)`. Compat and the editor (egui's MSAA pass, so AO/LUT/FXAA are not visible there) keep the old path: tonemapping in the mesh shader. TAA is not done (needs jitter and history; FXAA covers AA).
- Height fog: `RenderSettings.height_fog: Option<HeightFog { color, density, falloff, height }>` lives in `mesh.wgsl` (`height_fog_amount`: the analytic integral of exp(-falloff*y) along the eye ray, `fog_tint` shared with the linear fog: the sky horizon colour when a sky is set), so it works on every tier and in the editor viewport. `Globals` gets two vec4 (`height_fog_color`, `height_fog`). Scene: `Environment.height_fog: Option<HeightFogDesc>` and `Environment.post: PostDesc` (fxaa, ao, saturation, contrast, lift/gamma/gain, lut path, lut_strength) with serde defaults (old scenes load, `FORMAT_VERSION` unchanged); `olvin::scene_file::apply_lighting` copies them into the settings, the LUT image loads in `spawn_ids`. Editor: Height Fog and Post-processing sections in Settings → Rendering (`panels/lighting.rs`). GPU tests: `core/tests/post.rs` (FXAA, AO, LUT, grading), `core/tests/fog.rs`.
- `skinning.rs`: `SkinnedMesh { animator, bind mesh, joints, weights }`: CPU skinning (4 influences, normals/tangents rotated); `skin_meshes` (public, added by `RenderDataPlugin`) in `PostUpdate` re-poses the mesh through `Meshes::set` whenever the `Animator`'s `version` grew. Works on every tier (WebGL2/GLES3) and the posed mesh reaches shadows and blending; one mesh slot per instance. No GPU (shader) skinning yet.
- `frustum.rs`: 6 planes from view-proj (Gribb–Hartmann, depth 0..1), sphere test.
- `particles.rs`: CPU particles. Component `ParticleEmitter { params: EmitterParams, texture, playing }` + `EmitterParams`, plain data (feature `serde`, `#[serde(default)]`): `rate`, `bursts`, `duration`/`looping`, `shape: EmitShape::{Point, Sphere, Hemisphere, Cone, Box, Circle}`, ranges for `lifetime/speed/size/rotation/spin`, `gravity`, `drag`, `space: SimSpace::{World, Local}`, `color` × `color_over_life` (gradient), `size_over_life`, `blend`, `flip_book`, `sort`, `texture_path` (resolved by the loader), `seed`. Simulated in `Stage::PostUpdate` (`update_emitters(world, dt)`): storage is reserved up to `max_particles`, dead ones are `swap_remove`d, births are spread over the step, the RNG is deterministic per `seed`. `ParticleRenderer::{new, prepare(device, queue, gpu, world, view_proj), draw(pass)}`: billboards on the camera's axes (taken from the rows of view-proj), depth-tested without writing depth, alpha sorted far to near. No tonemapping or lighting.
- GPU particles (`particles_gpu.rs`, `particles_sim.wgsl`, `particles_draw.wgsl`): `ParticleEmitter` has `ParticleMode::{Cpu, Gpu}`; `EmitterParams.gpu` asks for the GPU and the mode is resolved on the fly (`gpu_particles_available()` is set by the first `ParticleRenderer` on a compute-capable device: not GL, storage buffers, `full_tier_limits(adapter)` in `Renderer`). Compat (GL/WebGL2) stays on the CPU. In Gpu mode the emitter only schedules: the cycle/rate/bursts produce `GpuStep { seq, dt, births, matrix }` (queue of <= 32) and `GpuSim::prepare` keeps a ring storage buffer per emitter (64 B a slot, a zeroed slot is dead), runs unseen steps in a compute pass (one dynamic-offset uniform write per step; births take the next ring slots and overwrite the oldest when full) and draws quads straight from the buffer (the vertex shader reads storage, dead slots collapse, colour/size LUTs of 32 samples, billboards as on the CPU). Unsorted; `read_gpu` reads the buffer back (tests). The editor has one renderer per view, each simulating its own copy (steps are deterministic). GPU tests run on native Vulkan and print why and skip on llvmpipe. Also `color_max` (random start colour), `prewarm`, `soft_circle_texture()`.
- `quad.rs` / `quad.wgsl`: the shared coloured-quad batcher (`QuadBatcher`): an instance is origin + two edges + colour + uv (80 B, 5 attributes), 6 vertices from `vertex_index`, one uniform, texture + sampler per batch; consecutive quads with the same (texture, `QuadFilter::{Linear, Mipmapped, Nearest}`, `QuadBlend::{Alpha, Additive}`) share one draw. Bind groups are cached by (texture, filter, generation); buffers are reused. The tests render offscreen and read pixels back (particles, sprites, atlases, tilemaps).
- `sprite.rs`: 2D. `Sprite` (texture/`uv`/`size`/`pivot`/colour/flip/`layer`/`y_sort`/blend/filter/`space`), `SpriteAtlas` (`grid`, named regions with a pivot, `sprite(region, ppu)`), `TileSet` (margin/spacing, uv inset by 0.02 texel), `Tilemap` (`tiles: Vec<u32>`, 0 = empty, otherwise index + 1 with `FLIP_X/FLIP_Y` bits; only cells in view are drawn), `Camera2d { height }` (pose from the entity's transform, y up). `Space2d::{World, Screen}`: Screen is pixels from the top-left corner (y down), ignores the camera and always draws over the world (in-game UI). `SpriteRenderer::{new, prepare, draw}`: viewport culling, sort by (space, layer, depth z or y, texture), no depth test, over the 3D scene. All data + serde, like particles.
- `overlay.rs`: screen overlay (in-game UI). `Overlay { quads }` is a resource where producers (`olvin_gui`) push `OverlayQuad`s every frame (a rectangle in physical pixels, uv, linear colour, texture) in paint order; `RenderPlugin` clears it in `Stage::First`. `OverlayRenderer` is a thin wrapper over `QuadBatcher` (no depth, alpha blending, linear filter, consecutive quads with one texture = one draw), `begin_overlay_pass` is a pass over the finished image (`LoadOp::Load`). `Renderer` draws it in its own pass after post-processing and tonemapping, so the UI gets neither bloom nor ACES. Plain vertex/fragment shaders only: works on the Compat tier (WebGL2/GLES3). Test: `overlay_paints_in_order_without_depth`.
- The window `Renderer` creates a `ParticleRenderer` and a `SpriteRenderer` and draws them in the main pass after the meshes (also in the HDR chain). Not done: sprite animation (frames over time), text rendering, 9-slice, light/shadows on sprites, stretched billboards, particle collisions and trails; the editor viewport (`EngineGpu`) draws particles but not sprites.
- `RenderSettings.scene_lights` (default true): when false, `Light` components are ignored (the editor's Solid view).
- `mesh.wgsl`: an instanced shader within WebGL2 limits: one uniform, 9 attributes (vertex: position, normal, uv, tangent; instance: the model matrix as 4 vec4 + colour). Hemispherical ambient, the sun with PCF 3×3 (comparison sampler, slope bias + normal offset, fade towards the edge of the distance), 16 point/spot lights (falloff `saturate(1-(d/r)^4)^2/(d²+1)`, soft cone), GGX + height-correlated Smith + Schlick (metallic-roughness), fog, exposure + ACES, sRGB. `shadow.wgsl` is a depth-only pass. Shadows work on Compat (GL) too.
- A mesh with no vertices/indices creates no GPU buffers (empty slot, every pass skips it); `max_particles` reserves at most `MAX_RESERVED` (65536) slots and a NaN particle step is ignored; a tile holding only flip flags is empty. Known gap: `Meshes` cannot free slots, so respawning scenes/skinned meshes grows GPU memory (the engine has no scene unloading).

## olvin_csg

The classic level-editor CSG (Hammer, Realtime CSG) over convex brushes.
- `shapes.rs`: `BrushShape` (Box, Wedge, Cylinder{sides}, Pyramid{sides}, Stairs{steps}) in the local unit cube `[-0.5, 0.5]³`, so the brush size is its scale. Each shape is a set of convex pieces (stairs have one piece per step).
- `convex_hull(points)` (brute force over triples, for brushes with dozens of vertices), `shape_vertices(shape)` (the corners of a single-piece shape). `BrushInput.vertices: Option<Vec<Vec3>>` is an edited brush: the hull of its own vertices instead of a parametric shape.
- `lib.rs`: `build(&[BrushInput]) -> Vec<Polygon>`. Each face is split by the planes of the intersecting pieces (AABB rejection), so every fragment lies entirely inside or entirely outside every brush. A fragment is kept if the solidity on its two sides differs: points are taken 2 mm either side along the normal, and the operations `CsgOp::{Add, Subtract, Intersect}` are applied in order. Coincident faces with the same orientation keep only the last piece. The method is robust against touching and coincident faces, where BSP approaches break. Mirrored transforms re-orient the faces. `brush_edges` gives outlines, and `TriMesh::from_polygons` builds the mesh. `BrushInput.faces` is a modelled brush (a closed surface of convex polygons; it may be non-convex): such a piece is tested for "inside" with a generalised winding number (solid angle, Van Oosterom–Strackee), and fragments are cut by all of its planes (convex brushes use a fast rejection by the front side). Face orientation is aligned by the sign of the volume (mirrored transforms). 8 tests: a room, a tunnel, the order of operations, intersection, closedness of all shapes.

## olvin_mesh

An editable polygon mesh `PolyMesh { positions, faces: Vec<Vec<u32>> (n-gons, counter-clockwise from outside), wire: Vec<[u32; 2]> (free edges) }`, serialisable (feature `serde`). Adding operations keep all indices; removing operations return a `Remap` for vertices and faces. `validate()` checks the invariants. Operations: `extrude_faces` (the region: side walls only on the selection boundary) / `extrude_edges` / `extrude_vertices`, `inset_faces`, `split_edge`, `connect_vertices`, `knife`, `loop_cut` (a ring across quads), `make_face` (the order of selection does not matter, orientation follows a neighbour), `fill_edges` (a loop, a chain or a bridge between two edges), `delete_vertices/edges/faces(keep_edges)` (faces → edges), `dissolve_edges`, `merge_vertices`, `merge_by_distance`, `flip_faces`, `recalculate_normals_outside`, `subdivide_faces`, `catmull_clark`, `triangulate` (ear clipping in the face's plane, flat normals), `compact`. `walk.rs`: `adjacency()` (`Adjacency`: edges → faces, neighbours and faces around vertices), `edge_loop` (through 4-valence vertices, along the boundary and wire chains), `ring` (a face loop and an edge ring across quads), `linked`, `grow_selection`, `shrink_selection`, `duplicate`. Constructors: `cube`, `plane`, `from_polygons(polys, weld_eps)`. UVs per face corner: `uvs[f][i]` ↔ `faces[f][i]`; an empty array means "no UVs yet" (`ensure_uvs` does a box projection). V points up as in Blender (the renderer flips V: `olvin::render_assets::poly_mesh_data`). Seams are `seams`. All operations keep the UVs consistent (interpolation, mean value coordinates for inset, isometric walls for extrude). `uv.rs`: projections (box/planar/cylinder/sphere/from view/follow active quads), islands, `transform_uvs`, texel density, `triangulate_uv`. `unwrap.rs`: LSCM over charts cut by the seams, scaled to the real area, rotated to the minimal bounding box, packed in shelves into 0..1. 55 tests.

## olvin_assets

Fixed steps: `FixedSystems`, kinematics, characters, `step_with_events`, writing poses back; bodies of removed entities are cleaned up. Character Controller: a capsule + `CharacterMotor { velocity, grounded, sliding, gravity_scale }`, steps, slopes, `move_character`. `CollisionEvents` per entity. `raycast(_filtered)`, `spherecast(_filtered)`, `overlap_sphere`. `forces.rs`: `Physics::apply_force(&World, entity, force)` (a one-shot force for the next step, cleared after the step by `clear_forces`, so call it every step), `apply_impulse` (dv = impulse / mass), `set_velocity`, `velocity`; they only work on a Dynamic body and return false otherwise (kinematic/fixed/character: a character uses `CharacterMotor::velocity`). `olvin_window`: `Input.scroll`, public setters, `CursorOptions`. **Pose ownership:** kinematic bodies follow `Transform` every step; Fixed (a collider without Rigidbody) and Dynamic bodies are teleported when gameplay changed their `Transform` (world matrix compared with `Body.seen`, one matrix compare per untouched body per step; velocity is kept); scale is baked and not followed; a static collider that moves every frame should be Kinematic. `Physics::teleport(&World, entity)` puts the body at the `Transform` pose right now and clears velocities, forces and `CharacterMotor::velocity` (contacts are rebuilt); `angular_velocity`/`set_angular_velocity`. The character pushes dynamic bodies (`CharacterMotor::push_mass`, from `CharacterControllerDesc::push_mass`, default 80 kg; 0 turns it off) through Rapier's `solve_character_collision_impulses` and sends `ControllerHit { character, other, point, normal, direction }` into `Events<ControllerHit>` (once per collider per step, `move_character` included). `CharacterMotor` is serde.

## olvin_scene::file (feature `serde`)

The scene format `*.scene.ron`, shared by the editor and the games. `SceneFile { entities, environment, animation, extensions }`; `animation: olvin_scene::action::Action` (F-curves of object transforms, written only if not default; `apply_animation(frame)` / `apply_action` evaluate it into the objects, `insert_keys(id, frame, KeyChannels)` is Blender's `I`). `environment: Environment` (sky and ground for ambient + intensity, background, exposure, `filmic` (ACES), `fog: Option<FogDesc>`, shadow distance and resolution) is written only when it differs from the default; `Environment::PRESETS`: Day / Sunset / Night / Studio. `EntityDesc`: a stable `id`, `active`, `tag`, `layer`, `parent`, position, rotation in degrees as Euler YXZ, scale, `mesh`, `camera`, `brush: BrushDesc { shape, op, color, vertices }`, `poly: PolyMesh` (an edited mesh: for a normal object it replaces `mesh.shape`, with the colour from `mesh`; for a brush it is the shape used by CSG), `EntityDesc::brush_input(transform)` is the CSG input (convex faces of `poly` as they are, non-convex ones as triangles), `light: LightDesc` (Directional/Point/Spot), `collider: ColliderDesc` (Box/Sphere/Capsule/Mesh, center, trigger, friction, bounciness), `rigidbody` (Dynamic/Kinematic, mass, drag, gravity, freeze rotation, CCD), `character_controller`, `audio_source`, `audio_listener`, `scripts: [ScriptDesc { name, params }]`. Empty fields are not written to the file. `active_in_hierarchy`, `sun()` is the first active Directional Light. Parents always come before their children in the list. `world_matrices[_with]` expands the hierarchy into world matrices, `hierarchy_order()` gives the DFS order as in the hierarchy panel, and `csg_brushes()` gives the brushes in operation order. `extensions` are data of editor elements (animator clips). `model: Option<ModelDesc { path, animation: Option<AnimationDesc::{Clip(name) | Graph(.animgraph.ron path) | Inline(AnimGraphDesc)}> }>` (a glTF under the object, `anim.rs`; format v2; `collider: Mesh` on the object uses the model's triangles). `SceneFile.version` (`FORMAT_VERSION`, currently 4; the v1→v2 migration is empty, but older builds refuse v2 files; v2→v3 turns the old timeline clip from `extensions["animator"]` (seconds) into F-curves at 24 fps with linear keys and removes the extension; v3→v4 is empty and adds `EntityDesc::prefab`, see below) is always written; a file without the field is version 0. `SceneFile::parse(text)`/`load` check the version (newer than supported is an error) and run the `MIGRATIONS` chain (`fn(&mut SceneFile)`, entry `n` takes `n → n+1`) over the parsed scene; renames and new fields are covered by `#[serde(alias/default)]`, a migration fixes the meaning of data. Old-version fixtures: `crates/olvin_scene/tests/fixtures/`. A breaking format change = `FORMAT_VERSION += 1` + a new migration. **Stable id and game components:** `EntityDesc::components: BTreeMap<String, String>` (registered type name → RON text of the value) is an optional `serde(default)` field, not written when empty, no format version bump. Spawning puts `SceneId(id)` (`olvin_scene`) and the components from the `olvin::scene_file::SceneComponents` registry on the entity (a resource, `register::<T>(name)` for `T: Component + Deserialize`; unknown names and bad values are skipped with a warning, the editor keeps them). `scene_file::find(world, id)`, `spawn_ids` returns `id → Entity`, `spawn_loaded(res, handle)` takes a finished background load and spawns it like `load` (the `assets/` root for materials is derived from the scene path).

## olvin_scene::prefab (feature `serde`)

Prefabs: `*.prefab.ron` is an ordinary `SceneFile` with one root and its children (its own `id`s, the same migrations, `AssetKind::Prefab` in `olvin_assets`). In a scene an instance is a single entity, the root, with `EntityDesc::prefab: Option<PrefabInstance { asset, overrides, removed }>`: `asset` is a path relative to `assets/`, like materials and models (GUIDs in `.meta` move with the file, and the Assets panel rewrites paths on a move); `overrides: BTreeMap<node path, BTreeMap<field, RON text>>` is the generic difference from the prefab: a field is a top-level `EntityDesc` field by name (`position`, `mesh`, `scripts`, `material`…) or `components.<Type>` (empty text: the instance does not have the component); `removed` holds the paths of deleted nodes. A node path is the prefab's ids joined by `/`: `""` the root, `"3"` node 3, `"3/2"` node 2 of a nested prefab that is node 3 itself. Children added to an instance stay ordinary scene entities whose `parent` is a node of the instance. The root owns its name, activity, parent and transform (`ROOT_OWN`): placing and renaming an instance is not an override. Format v4 (`FORMAT_VERSION = 4`, the v3→v4 migration is empty, older builds refuse the file).

- Particles in scenes: `EntityDesc.particles: Option<ParticleDesc>` (format version 5, `olvin_scene::particles`; a mirror of `EmitterParams` + `gpu`, `play_on_awake`, `texture` relative to `assets/`, angles in degrees, serde defaults on every field). `ParticleDesc::{fire, smoke, sparks, dust, rain, snow, explosion, magic_glow}` and `PRESETS`. Prefab overrides cover the `particles` field. `olvin::particles::{emitter_params, emitter, emitter_in}` build the component; `scene_file::spawn*` adds it, the texture goes through `RenderAssets::particle_texture` (the file or the built-in soft circle).

`member_id(parent, local_id)` is a node's id in the scene: a hash with the `MEMBER_BIT` set, so it is the same on every load and for nested prefabs, and "highest + 1" for new ids ignores it (`is_member_id`); `node_id(root, path)`. `SceneFile::expand_prefabs(loader)` expands instances into ordinary entities (the nodes carry `EntityDesc::prefab_node: PrefabNode { root, path }`, `#[serde(skip)]`; calling it again does nothing; a prefab that cannot be read or that loops (guard: the asset path is already on the stack, depth `MAX_DEPTH` 16) gives a warning and the object stays empty, no panic). The way back is `collapse_prefabs(loader)`: nodes are compared with the asset and the difference becomes `overrides`/`removed`. Also: `prefab_pristine`, `prefab_diff`, `prefab_added` (children added to an instance), `revert_prefab`, `revert_prefab_field`, `unpack_prefab`, `unpack_asset`, `apply_prefab(root)` (the asset with the changes accepted; an override on a node of a nested prefab goes into the inner instance inside the asset). The field list is a macro with an exhaustive destructuring of `EntityDesc`: a new field does not compile until it is listed. The granularity is the whole field (`position` is the whole vector), `scripts` the whole list.

## olvin_game

Game layer on top of the core, no GPU or window. Spawning a loaded scene stays with the `olvin::scene_file` facade.

- `state.rs`: `App::add_state(S)` (`S: Copy + Eq + Hash + Debug`, usually an enum), resource `State<S>` (`get`, `is`, `set`). `set` only requests a transition; it is applied once per frame at the start of `PreUpdate` (last request wins): `on_exit(old)` hooks, the switch, `on_enter(new)` hooks, a `StateChanged<S>` event. A hook may request the next transition itself (chains are cut at 8 steps). `on_enter(initial)` runs in `Startup`. `add_system_in_state(stage, S, system)` runs a system only in its state. Pause: `on_enter(Paused, |r| r.fetch_mut::<Time>().pause())`.
- `loader.rs`: `SceneLoaderPlugin` + resource `SceneLoader`. `request(path) -> LoadHandle` reads and parses a scene (with all migrations) on a worker thread; `status` (`Pending/Ready/Failed/Gone`), `take(handle) -> Option<Result<SceneFile, String>>`, `is_loading`. The channel is polled by a `First` system. A loading screen is a `Loading` state that waits for `Ready` and sets `Playing`. `take_with_path(handle)` also returns the path (for `scene_file::spawn_loaded`).
- `save.rs`: save games, separate from scenes (a scene is a level as the editor authored it, a save is the state of a play session). `SaveRegistry`: `register_component::<T>(name)` and `register_resource::<T>(name)` (serde + RON, the name is part of the format). Only entities with `SaveId(u64)` are saved. `capture(res, meta) -> SaveData { version, meta: SaveMeta { title, scene, playtime_secs, saved_at }, entities, resources }`, `restore(res, &data)`: `SaveId` entities are updated or created, those missing from the save are despawned, others are left alone, registered components absent from the save are removed. Everything is parsed before the world is touched, so an error changes nothing. Unknown names are skipped with a warning. References between entities inside components are not remapped: store `SaveId`s. `SaveSlots` (`SavePlugin::new(dir)`): `<dir>/<slot>.save.ron`, `save` (tmp + rename), `load`, `list` (newest first, broken files skipped), `delete`, `exists`; a slot name cannot escape the directory. `SAVE_VERSION` + `SAVE_MIGRATIONS` chain as for scenes; a future version is an error. 18 tests, fixture `tests/fixtures/v1.save.ron`. **Engine state:** `SaveRegistry::register_engine()` (on in `SavePlugin::new`, off with `without_engine()`) registers `transform`; with feature `physics` `motor` (`CharacterMotor`) and `velocity` (`BodyVelocity`: linear and angular velocity of dynamic bodies); with feature `script` `scripts` (`Behaviour::save_state`/`load_state` of every instance, `ScriptRuntime::save_states/load_states`; state for scripts not created yet is applied right after creation, before `start`). A restored `Transform` teleports the body at the next physics step, the velocity is set at once. `register_external::<T>(name, read, write)` is state outside ECS components (written after the components, the world is not borrowed). The entity key is `SaveId`, and with `scene_objects` (on by default) also the `SceneId` of scene objects (a separate id space; `SavedEntity.scene`; a scene object is never created from a save, one missing from the save is despawned). The Lua extension point is the same `save_state/load_state` on the `self` table (not wired yet).

## olvin_physics

Modules: `lib.rs` has `Physics`, `Body`, `FixedSystems`, `PhysicsPlugin`; `sync.rs` (the `step` system, ECS↔Rapier pose exchange), `bodies.rs` (creating bodies and colliders), `character.rs`, `query.rs`, `events.rs`, `forces.rs`; tests in `tests.rs`.

`PhysicsPlugin { gravity }` and the resource `Physics { world: rapier PhysicsWorld }`. Every frame (PreUpdate): entities with a `ColliderDesc` or `RigidbodyDesc` but no `Body` marker get bodies (Dynamic, Kinematic, or Fixed if there is no Rigidbody). The object's scale is baked into the collider shape, since Rapier has no scale. `Mesh` uses `MeshGeometry`. Kinematic bodies follow `Transform`, then fixed steps of 1/60 (at most 5 per frame), then dynamic bodies write their pose back. Rapier 0.36 computes in glam 0.33, converting through arrays. Tests: a box lands on the ground, a ball lands on a mesh floor, a ball passes through a trigger.
- Edge input: a zero scale no longer writes a NaN rotation (`split` falls back to identity); a mesh collider with indices past its vertices is skipped with a warning (parry would panic); NaN/negative `dt` is ignored.

## olvin (facade)

The `window` and `render` features are on by default. `scene` adds `scene_file::{load, spawn}`: loads an editor scene into the `World`, only active objects. Components are carried over as data (`LightDesc`, `ColliderDesc`, `RigidbodyDesc`, `AudioSourceDesc`, `Scripts`, `AudioListener`, `Name`, `Tag`); a Mesh Collider on a primitive gets a `MeshGeometry`. An object with `poly` gets its own mesh (triangulated) and a `MeshGeometry` for its Mesh Collider. Each `LightDesc` gets a runtime `olvin_render::Light` (`runtime_light`). `apply_lighting(scene, &mut RenderSettings)` carries the sun and the `Environment` into the render settings (it does not touch vsync or other window options); both the loader and the editor use it. A brush with a Rigidbody is not part of the level: it becomes a separate body with its own mesh and a convex collider. The first Directional Light sets `RenderSettings.light_dir/light_color`. CSG is built on load: meshes grouped by face colour, plus one "CSG Level" entity with a static mesh collider. The hierarchy is kept: `Transform` is local, `Parent` links the children, and `GlobalTransform` is set right away to the world matrix. `physics` pulls `olvin_physics` into `DefaultPlugins`. Without it you get the bare core + ECS (servers, tools). `DefaultPlugins` adds everything that is enabled (and `AnimPlugin` with the `anim` feature). `HeadlessPlugins { physics, input, script, audio }` is the same set without a window and GPU (audio off by default; with `render` it adds `RenderDataPlugin`, with `scene` `RenderAssetsPlugin`, `ModelPlugin` and `SceneComponents`, with `gui` a `GuiPlugin` that is not drawn): game tests, servers; not to be combined with `DefaultPlugins`. There is a `prelude` for games (with `HeadlessPlugins` and `ProjectPaths`). The `script`/`input`/`audio` features attach their plugins; `Scripts`/`AudioListener` in `scene_file` are their types, and a loaded scene starts its scripts, characters and sound immediately. `render_assets.rs` (feature `scene`): `RenderAssets` is a cache from path to handle for materials, textures, shaders and the sky, with hot reload by mtime (every 0.5 s), `Registries`, `material_in(res, path)`, `poly_mesh_data` (UVs with V flipped). `RenderAssetsPlugin` is in DefaultPlugins; the root is set by `scene_file::load` (the `assets` folder above the scene). The loader hands materials to meshes, poly meshes and the CSG level (groups by (colour, material), box UVs) and sets the sky. Re-export of `olvin::csg`. `models.rs` (feature `scene`): `scene_file::spawn` puts a `PendingModel` on an object with a `model`; `ModelPlugin` (in DefaultPlugins) builds the model under the object once the `AssetManager` (resource `olvin_assets::AssetManager`) has it: child mesh entities with materials (`RenderAssets::inline_material`), the skeleton, `SkinnedMesh` and an `Animator` with the graph from `AnimationDesc` (`olvin_assets/animation.rs` turns `AnimGraphDesc` into `AnimGraph`); `pending_count` tells when to stop waiting; works without a renderer (meshes go to `Meshes`). Features `anim` and `assets` re-export `olvin::anim`, `olvin::assets`; `AnimPlugin` needs no renderer. `olvin_game`'s `SceneLoader` loads the same `SceneFile`, spawning is shared. `spawn_ids` expands prefab instances itself (assets are read from the `RenderAssets` root, so `spawn_from`/`spawn_loaded` cover background loading too; a broken or missing prefab is logged and the object spawns empty); the instance root gets `olvin_scene::PrefabInstanceOf(asset path)`. `scene_file::instantiate_prefab(res, path, Transform) -> Result<Entity, String>` creates a prefab at run time (a fresh `SceneId` above every one in the world).

## olvin_text

The built-in Inter licence is in `licenses/Inter-OFL.txt` (in the package `include`; a test compares it with `assets/fonts/`). Same for `olvin_ui` (Inter and JetBrains Mono). Summary: `THIRD_PARTY.md`. The `.exe` icon for the hub and editors: `build.rs` + `winresource` (`cfg(windows)` only), `assets/logo/olvin-icon.ico`.

Text without a GPU or a window: depends on `ab_glyph` (pure Rust, already in the tree through egui) and `glam`.

## olvin_gui

In-game UI, separate from egui (egui is editor-only; the crate depends on `olvin_core`, `olvin_input`, `glam`). The core does not draw by itself: it outputs a `DrawList`. With feature `render` (on in the facade together with `gui`) it is drawn.

- `render.rs` (feature `render`): `GuiRenderPlugin` = `GuiPlugin` + `GuiText` (font, `GlyphAtlas`, the atlas texture in `Textures`) + `FontMeasure` in `Gui::measure` (layout uses real font metrics). A `PostUpdate` system after layout turns the `DrawList` into `olvin_render::Overlay` quads: rectangles sample the atlas's white block, glyphs their own regions, so a whole menu is one textured batch. Sizes are UI pixels, multiplied by `Gui::scale` = `SurfaceTarget.scale_factor × Gui::ui_scale` on the way to the screen (HiDPI); the pointer is divided by it. Theme colours are taken as sRGB and converted to linear. `set_font` swaps the font at runtime. The renderer does not know the UI and the UI does not know the renderer: only the `Textures` and `Overlay` resources connect them.
- `tests/render.rs`: an offscreen test (llvmpipe: `__EGL_VENDOR_LIBRARY_FILENAMES=/usr/share/glvnd/egl_vendor.d/50_mesa.json WGPU_BACKEND=gl cargo test -p olvin_gui --features render`) draws a plate with Cyrillic text over a frame and checks the pixels.

- `node.rs`: `Node` (builder: `panel/label/button`, `row/column`, `px/fill/size`, `gap/padding/align/justify`, `anchor/centered`, `name`, `disabled/hidden`), `Dim::{Fixed, Content, Fill(weight)}`, `Layout::{Overlay, Row, Column}`, `Place::{Flow, Anchor{anchor, pivot, offset}}`, `NodeId`.
- `layout.rs`: `Ui::layout(viewport, &dyn TextMeasure)`: content sizes bottom-up, then placement top-down (flex-like row/column with weighted `Fill`, justify and align, overlay, anchors). `TextMeasure` is where real font metrics plug in; `Monospace` is a fallback estimate.
- `ui.rs`: `Ui` is an arena tree (ids are not reused until `clear`). Focus: `focus_next/prev` (Tab in tree order), `navigate(Dir)` (nearest button in that direction, off-axis distance counts double), `set_focus`. `update(&UiInput)` yields `UiEvent::{Click, Focus, Cancel}` (a click is press and release on the same button; pointer hover moves focus; accept clicks the focused one). `ButtonState` for painting.
- `nav.rs`: `NavRepeat` repeats a held direction (0.4 s, then every 0.12 s) for sticks and the d-pad.
- `paint.rs` / `draw.rs`: `Ui::paint(&Theme, &mut DrawList)` -> `DrawList { quads, texts, order }`; `DrawList::vertices` gives `GuiVertex` (position + colour, 6 per quad). Its own theme, unrelated to `olvin_ui`.
- `plugin.rs`: `GuiPlugin` inserts the `Gui` resource (tree, theme, `draw`) and `Events<UiEvent>`. The actions `UiNavigate/UiAccept/UiCancel/UiNext/UiPrev` (`UiActions`) are added to `InputMap` only if missing, so a player's remapping survives. Input runs in `First`, right behind `update_actions` (add `InputPlugin` first; real time, so menus work while paused). The UI swallows the input it handled: while the pointer is over a button or a panel with a background (or a press that began on the UI is held), every action bound to a mouse button (`Fire`) reads idle; while a widget is focused, so do the actions sharing a key/button with `UiNavigate/UiAccept/UiNext/UiPrev` (`Move` on WASD, `Jump` on Space); `UiCancel` is not swallowed (Esc is also Pause). Mechanism: `ActionState::consume`, `InputMap::actions_using`, `Binding::leaves`; state via `Ui::pointer_captured/keyboard_captured/covers`. Layout and `DrawList` in `PostUpdate`; the size comes from `SurfaceTarget`.
- Not done: line wrapping (explicit `\n` only) and clipping, text fields/sliders/scrolling, the UI swallowing input (a click on a button is still seen by games as `Fire`), image nodes in `DrawList` (`Overlay::image` exists, a picture node does not). 16 tests + 1 render test (layout, navigation, clicks, the plugin over `olvin_input`).

## hub (olvin-hub, working name)

The hub creates game projects and installs modules into them. The source of truth for modules is the game's `Cargo.toml`; the hub keeps no state of its own about what is installed.

- `olvin_hub/catalog.toml`: the built-in catalogue. `kind = "olvin"` is a feature of the `olvin` facade (the plugin pulls in `DefaultPlugins`). `kind = "crate"` is a dependency from crates.io (rapier3d, kira, gltf, rand, serde, ron). The field `requires` installs modules together with their dependencies. Olvin modules: window, render, scenes, physics, scripts, input, audio, `lua` (requires scripts), `game`; a test checks them against the facade's features.
- `catalog.rs`: `Catalog` (parsing, checking `requires`, `resolve`: dependencies first, detects cycles, `categories`), `Module`, `Source`.
- `project.rs`: `Project::create` (modules with `default = true`) and `create_with(modules)` for templates, `modified()`, `open`, `discover` (searches upwards through folders), `add` (together with requires), `remove` (refuses to remove something others depend on, unless `force`), `save`. Edits go through `toml_edit`, so the user's comments and formatting are kept. `olvin` is included with `default-features = false`, and the list of Olvin modules is its `features`.
- `build.rs`: `Project::build(&BuildOptions { release, out, archive, target_dir })` — `olvin-hub build [--release] [--out DIR] [--archive tar.gz|zip]`. Runs `cargo build --message-format=json-render-diagnostics` (cargo's output goes to the terminal, the exe path comes from `compiler-artifact`), then puts the exe and a copy of `assets/` (plus `licenses/` with Inter-OFL.txt and THIRD_PARTY.md when the `gui` feature is on, and the project's own `licenses/`; `BuildReport.licenses`) (without hidden files and `*~`) into `<project>/dist/<name>` (or `--out`) and optionally packs it next to it as `<out>.tar.gz` / `<out>.zip` (a folder named after the game inside; `flate2`+`tar`/`zip`). It only replaces an output folder the hub made itself (marker `.olvin-build`) and never touches a foreign non-empty one. `dist/` stays inside the project, but a build into the default folder appends `/dist` to an existing `.gitignore` that lacks it (`BuildReport.gitignore_updated`, the CLI says so). The game finds `assets/` next to its exe through `ProjectPaths`, so the folder runs from any working directory. Tests: the core on temporary projects with a stub `olvin` (4), the CLI (`hub/olvin_hub_cli/tests/build.rs`, 2) with `XDG_CONFIG_HOME` in a temporary folder. Not done: cross-compilation (`--target`), asset compression/stripping, a GUI button, signing and installers.
- `config.rs`: `HubConfig` in `<config_dir>/olvin-hub/config.toml` (on Linux it honours `XDG_CONFIG_HOME`): the project list, `EngineSource` (`path` to a checkout, or `git`; by default the folder the hub was built from if it exists, otherwise GitHub), and `[gui]` (`GuiSettings`: `theme` = dark/light/graphite/high-contrast, `reduce_motion`, `view` = list/grid, `sort` = modified/name, all as strings so that the core does not depend on the UI).
- `template.rs`: Cargo.toml (deps always -O3, its own empty `[workspace]`), `src/main.rs`, either graphical (it loads `ProjectPaths::asset("scenes/main.scene.ron")`, or a cube if there is none) or headless on `HeadlessPlugins` when there is no window+render+scenes; neither depends on the working directory. A README and a `.gitignore` (`GITIGNORE`: `/target`, `/dist`, `/logs`, `/saves`).
- `editor.rs`: `EditorInstall` in `<data_dir>/olvin-hub/editor`: a generated crate (`Cargo.toml` + `main.rs` with the plugins, binary `olvin-editor`). The source of truth is its `Cargo.toml`. Methods: `write`, `build_command` (`cargo build --release`), `launch(project)`. Freshness: `engine_fingerprint(engine)` is the maximum mtime of `*.rs/*.toml/*.wgsl` in `crates/` and `editor/`, plus `Cargo.lock`; after a build `mark_built` writes `.engine-stamp`, and `is_stale` compares. The CLI `editor open` and the GUI when opening a project rebuild a stale editor themselves; the GUI shows a banner "The engine changed…" with a Rebuild button. Editor elements are described in the catalogue as `[[editor_module]]`.
- Logo: `olvin-hub-gui` sets the window icon the same way the editor does (`window_icon()`, `olvin-icon-256.png`). The CLI prints the text logo `Olvin_` with a green `_` in the help header (`logo()` → clap `before_help`; running with no arguments shows the help). clap drops the colour under `NO_COLOR` and when output is not a terminal.
- CLI: `new`, `list`, `add`, `remove [--force]`, `run [--release]`, `projects`, `register`, `forget`, `engine [--path|--git]`, `editor install|list|add|remove|open [project]`.
- The hub, the CLI and the catalogue (module names and descriptions) are in English, and the texts follow STYLE.md §10.
- GUI (`olvin_hub_gui`, a launcher in the spirit of Unity Hub, built on `olvin_ui`; it has no theme of its own). Modules:
  - `main.rs`: `Hub` (state, actions, `poll` of cargo processes, toasts), `draw`. `sync_style` sets the theme and reduce motion. The first `olvin_ui::apply` runs in the eframe creation closure (fonts become active from the next pass, and `bold()` in the same pass would panic); the frame right after the first apply is skipped.
  - `state.rs`: `impl Hub`: `load`/`new` from the config, saving, `refresh` of the project list, toasts, page and dialog switching.
  - `jobs.rs`: `impl Hub`: creating/adding/forgetting projects, running and stopping the game, the editor build, `poll` of child processes; `kill_tree`.
  - `tests.rs`: GUI unit tests (dialogs, templates, stopping a process, pages at every width).
  - `main.rs` is now just the types (`Hub`, `Page`, `Modal`, ...), `main`, `draw`, `sync_style`, `shortcuts` and small helpers; `Hub`'s methods live in `state.rs`/`jobs.rs`.
  - `chrome.rs`: the `--bg-radial` background (a polar mesh), the sidebar (the wordmark `logo::wordmark_intro` + "Hub", the items Projects / Editor / Settings, the selection bar slides through `widgets::tween`; below 1000 px a narrow column with `logo::mark` and icons), the status line (a status dot, Ready / Building editor / the game + Stop; on the right `ENGINE path · /…` in mono, cut off), toasts (bottom right, slide in and fade over 300 ms, click to close, errors for 8 s with an icon), page transitions (fade + a 10 px shift), `page_header` (the buttons drop under the title when the width is below 560).
  - `projects/` (`mod.rs` the page, toolbar and table header; `parts.rs` the tile, name/path and row buttons; `rows.rs` the list row and grid card): search, the Recent / Name sort switch and the list / grid view switch as pills, an empty state. Layout by width: at ≥ 900, a table `name+path | modified | modules | actions` with shared `Columns` for the header and the rows (clicking NAME/MODIFIED sorts); 600–900, a narrow modules column; below 600, cards with a meta line "4h ago · 5 modules"; grid, cards ≥ 250 px. Module chips always stay on one line, and the overflow collapses into `+N`; paths are mono with `…`, and the full path is in the tooltip. A letter tile; the most recent project (within a week) gets the accent. Hover: a lighter background, a 3–4 px lift, a stronger shadow. Rows appear in a staircase (`anim::stagger`, with its own id for each opening of the page).
  - `editor_page.rs`: the install card (mark, version, status, Open / Install / Rebuild), elements as cards with Install/Remove. Changes accumulate (`editor_pending`) and are applied in one rebuild from a pop-up bar "N changes · Discard · Apply". A build log (cargo's stderr is read on a background thread).
  - `settings.rs`: the theme (miniature cards for every `ThemeKind`), Reduce motion, the engine source, About. Saved in the `[gui]` section of the config.
  - `dialogs.rs`: modals for New project (templates as cards, modules as toggle cards honouring `requires`, a name with validation, a path), Add project, and Modules (by category; edits go straight into Cargo.toml). They appear with `--ease-pop` (a shift + fade), radius 20, and a light top edge. Note: do not use `ui.separator()` inside a horizontal layout in the modals, since it takes all the available height and the window grows every frame.
  - `widgets/` (`icons`, `text`, `buttons`, `chips`, `motion`, `switches`; all re-exported from `widgets`): `Btn` (primary/secondary/ghost, scale 0.98 on press), line icons, `chip_line`, `pill_switch` (the highlight slides), `toggle`, `card_bg`, `tween`/`since`/`entrance`.
  - Hotkeys: Ctrl+N for a new project, Ctrl+, for settings. All animations are ≤ 500 ms and are turned off by reduce motion; a repaint is requested only while something moves (and every half second for the cursor blink).
  - Tests: `dialogs_fit_their_content`, `pages_render_at_all_widths` (470/800/1280/1920, both layouts, headless `Context::run_ui`). `shots.rs` (ignored): `egui_kittest` + wgpu through `build_eframe` draws all pages, dialogs and themes at 4 widths into PNGs (`OLVIN_HUB_SHOTS=<folder>`, on llvmpipe: `__EGL_VENDOR_LIBRARY_FILENAMES=…/50_mesa.json WGPU_BACKEND=gl cargo test -p olvin_hub_gui -- --ignored screenshots`).

## Verified

- Vulkan, RTX 3050: Full tier, 40k cubes in 2 draw calls, limited by vsync.
- GL through Mesa llvmpipe (`__EGL_VENDOR_LIBRARY_FILENAMES=.../50_mesa.json WGPU_BACKEND=gl`): Compat tier, 10k cubes, about 90 fps on the CPU rasteriser.
- GL on proprietary NVIDIA under Wayland does not work: EGL does not provide a native-renderable config, and wgpu-hal refuses to present. This is a wgpu limitation, not the engine's. The renderer detects it at startup (`olvin_render::check_gl`): without `WGPU_BACKEND` it switches to Vulkan by itself, with it set it only warns.

The full plan with priorities and checklists: [ROADMAP.en.md](ROADMAP.en.md). Only what changes the architecture is listed here: a parallel scheduler (rayon), web and Android (`web-time`, recreating the surface), asset handles with reference counting, a 2D pipeline, skeletal animation, and navigation.

Sweep notes (hub and runtime): `Project::create_with` picks the graphical template from module requirements (`scenes` brings `render` and `window`) and removes the folder on failure; project names are checked by `olvin_hub::name_problem` (`olvin`, `log`, keywords, `std`... are reserved); `Project::remove_many` removes a set of modules all or nothing; `olvin-hub add/remove` print and save nothing on error, and only commands that need the hub config read it (a damaged one does not block `build`); a build always puts `assets/` into the game folder (the engine recognizes a built folder by it); the hub GUI runs the game in its own process group so Stop kills all of it, a damaged config is copied to `config.toml.broken` before the first write, `~` in paths expands. `SceneFile::parents_first` orders spawning (a child listed before its parent keeps `Parent`), parent cycles no longer hang `active_in_hierarchy`/`hierarchy_order`.
