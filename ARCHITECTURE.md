# Olvin: архитектура

<p align="center"><a href="ARCHITECTURE.en.md">English</a></p>

Модульный игровой движок на Rust. Каждая подсистема живёт в отдельном крейте и подключается как плагин. Подсистемы общаются только через общие ресурсы и не зависят друг от друга напрямую.

Визуальный стиль (цвета, шрифты, стекло, движение, тексты): [STYLE.md](STYLE.md). Логотип, вордмарк и иконка приложения (SVG, PNG, ICO): `assets/logo/`. Дорожная карта: [ROADMAP.md](ROADMAP.md).

## Принципы

- **Модульность на уровне подсистем, а не объектов.** Плагин регистрирует системы, система проходит по всем данным за один вызов. Нет виртуальных вызовов на каждый объект.
- **Горячие пути работают с плоскими массивами.** Рендер раскладывает инстансы по мешам в переиспользуемые `Vec` и делает один instanced draw на меш. В установившемся режиме кадр ничего не аллоцирует.
- **Ядро ничего не знает про GPU и окно.** Рендер и платформа связаны через `SurfaceTarget` (raw-window-handle), поэтому winit можно заменить на SDL или канвас, не трогая рендер.
- **Минимальный уровень железа — WebGL2 / GLES 3.0.** Устройство запрашивается с `Limits::downlevel_webgl2_defaults()`. Всё, что сильнее, включается по `RenderTier::Full`.

## olvin_core

- `app.rs`: `App` хранит `Resources`, `Schedule`, набор плагинов и runner. `add_plugin` пропускает повторы того же типа, поэтому плагин может сам добавить свои зависимости. `run()` отдаёт управление runner'у, без него крутится headless-цикл. Есть `startup()` (Stage::Startup, один раз) и `update()` (один кадр). `AppExit { requested }` останавливает цикл.
- `resources.rs`: `Resources` — синглтоны по `TypeId` в `RefCell`. Методы: `get/get_mut` возвращают Option, `fetch/fetch_mut` паникуют с именем типа. Разные ресурсы можно одновременно брать на запись, один и тот же нельзя.
- `schedule.rs`: стадии `Startup, First, PreUpdate, Update, PostUpdate, Render, Last`. Система — это `FnMut(&mut Resources)`. Пока всё однопоточное.
- `time.rs`: `Time` обновляется в `First`. `delta()/elapsed()` — время симуляции: умножаются на `time_scale` (`set_time_scale`, отрицательное = 0) и замирают на `pause()`; `step()` пропускает один кадр при паузе (покадровый шаг). `unscaled_delta()/unscaled_elapsed()` игнорируют масштаб и паузу (UI). Для тестов: `Time::with_fixed_delta(dt)` / `set_fixed_delta(Some(dt))` — каждый кадр ровно dt без часов, `advance(dt)` — ручной кадр. Реальный кадр ограничен 0.25 с, `frame()` считает и кадры паузы.
- `events.rs`: `Events<T>` — типизированная очередь-ресурс. `send/send_batch`, чтение через `EventCursor` у каждой системы (`events.read(&mut cursor)`, каждое событие отдаётся читателю один раз), `clear()`. Два буфера: событие живёт кадр отправки и весь следующий, поэтому читатель раньше отправителя в кадре тоже его увидит. `App::add_event::<T>()` создаёт ресурс и меняет буферы в `First` (повторный вызов — no-op, можно из нескольких плагинов). Буферы очищаются без освобождения: в установившемся режиме аллокаций нет.
- `logging.rs`: единый логгер без лишних зависимостей. `Logging::new(фильтр).file("logs/x.log").init()`: фильтр как у env_logger (`"info,wgpu_core=warn"`, переопределяется `OLVIN_LOG`/`RUST_LOG`, `Filter` — самый длинный префикс модуля), строки в stderr и файл. Перехват паники пишет `crash-<unix-время>.txt` рядом с логом (или в `crash_dir`): сообщение, место, поток, backtrace, последние 64 строки лога, потом зовёт прежний хук. Им пользуются `sandbox`, `script_demo`, шаблон игры из хаба (`logs/` в `.gitignore`) и редактор (`olvin_editor::run`, файл `<проект>/logs/editor.log`).
- `surface.rs`: `SurfaceTarget { handle: Arc<dyn WindowHandleSource>, size, scale_factor }` (масштаб экрана, UI умножает на него размеры; `with_scale_factor`) — контракт между платформой и рендером.

## olvin_ecs

Реэкспорт типов hecs (`World`, `Entity`, `Query`, `CommandBuffer`…). Остальной код импортирует их только отсюда, чтобы бэкенд ECS можно было заменить в одном месте. `EcsPlugin` вставляет `World`. 3 теста на контракт фасада (запросы с фильтрами, `CommandBuffer`, `EntityBuilder`).

## olvin_scene

`Transform` (translation/rotation/scale, `matrix()`, `looking_at`, `forward/right/up`) и `Camera` (perspective, правая система координат, глубина 0..1 через `glam::camera::rh::proj::directx`). Рантайм-компоненты `Name`, `Tag`, `MeshGeometry` (треугольники для mesh-коллайдеров). `primitives.rs`: `Shape` (Cube, Sphere, Capsule, Cylinder, Plane, Quad — размеры как в Unity) и `Primitive` (позиции, нормали, индексы, контур для выделения). Это общий источник геометрии для движка и редактора. Нет зависимостей от ECS и GPU.

## olvin_window

- `lib.rs`: `WindowPlugin { title, width, height, resizable }` ставит runner на winit 0.30 (`ApplicationHandler`). Окно создаётся в `resumed`, потому что так требует Android. Там же вставляется `SurfaceTarget` и вызывается `app.startup()`. Кадр — это `RedrawRequested → app.update()`. На Resize обновляется `SurfaceTarget.size`, на `ScaleFactorChanged` — `scale_factor`.
- `settings.rs`: `WindowSettings { mode: WindowMode::{Windowed, Borderless, Exclusive}, width, height }` — ресурс-запрос, который runner применяет после каждого кадра (как `CursorOptions`): `set_mode`, `set_resolution`, `toggle_fullscreen`; RON `load/save/load_or` (`assets/window.ron`). Размер логический в окне и физический видеорежим в Exclusive (ближайший через `Monitors::closest`, Borderless, если список пуст). `Monitors { modes }` — видеорежимы монитора для меню (`resolutions()`). `WindowPlugin.mode` и `with_settings` задают старт; ручной ресайз окна записывается обратно в `WindowSettings`. Логика проверена тестами без окна, само переключение режима на winit — нет.
- `input.rs`: `Input` хранит нажатые клавиши и кнопки мыши, `just_pressed/just_released`, позицию курсора и сырую `mouse_delta` из `DeviceEvent`. Сброс в `Stage::Last`, при потере фокуса всё отпускается.

## olvin_transform

`Parent(Entity)` и `GlobalTransform(Mat4)`. `TransformPlugin` в `Stage::PostUpdate` вызывает `propagate`: недостающие `GlobalTransform` добавляются, у корней глобальная матрица равна локальной, у потомков считается с кэшем, циклы обрезаются. `world_matrix(world, e)` даёт мировую матрицу сразу, ещё до распространения (её использует физика). Плагин включён в `DefaultPlugins` и `RenderPlugin`. 5 тестов: уровни иерархии, плагин в PostUpdate, масштаб/поворот, отвязка от родителя, висячий родитель, циклы.

## olvin_anim

Чистая анимация, без GPU и окна (зависит от `olvin_core`/`olvin_ecs` только ради плагина).
- `skeleton.rs`: `Skeleton` (`Joint { parent, target, rest, inverse_bind }`, порядок любой, цикл — ошибка), `JointPose`, `Pose`; `globals`, `skin_matrices` (`global * inverse_bind`). `target` — id узла в исходном файле, по нему клипы находят суставы.
- `clip.rs`: `Clip { channels, events }`, `Channel` (translation/rotation/scale; Step, Linear со slerp, CubicSpline как в glTF), `Clip::apply(time, skeleton, pose)`, события клипа (`events_between`).
- `graph.rs`: `AnimGraph` (состояния `State` с `Motion::{Clip, Blend1D}`, переходы `Transition` с условиями по `Params`, `exit_time`, кроссфейдом), `Params` (float/bool/trigger; триггер гасится первым сработавшим переходом), `LayerState::update/pose`. На время кроссфейда новые переходы не стартуют.
- `animator.rs`: компонент `Animator { skeleton, clips, params, layers, pose, matrices, version, events }` (слои смешиваются по `weight` и маске суставов), `AnimPlugin` двигает все `Animator` в `Update` по `Time::delta` и шлёт `Events<AnimationEvent>`. `RenderPlugin` подключает его сам.
- `tests.rs`: 14 тестов (сэмплирование, скелет, граф, слои, события, плагин).

## olvin_render

- `lib.rs`: `RenderPlugin { settings }`, `RenderSettings` (vsync, low_power, clear_color, light_dir/light_color/light_shadows — запасное солнце, ambient (небо) + ground_ambient, exposure, `tonemapping: Tonemapping::{None, Aces}`, `fog: Option<Fog>`, shadow_distance, shadow_map_size), компонент `MeshRenderer { mesh, color }`, `Color` (линейный RGBA). Плагин добавляет `EcsPlugin`, ресурсы `Meshes` и `RenderStats`, системы `init` (Startup) и `render` (Render).
- `core/`: `RenderCore` — рендер без окна. Разбит по подсистемам: `mod.rs` (общие типы: `RenderCore`, `GpuMeshes`, `ViewData`, `Globals`, `InstanceRaw`, GPU-структуры ассетов, `camera_view_proj`), каждый соседний файл добавляет свой блок `impl RenderCore`: `init.rs` (устройство, сэмплеры, текстуры по умолчанию, `create_view`), `assets.rs` (загрузка мешей и текстур, bind group материалов, компиляция поверхностных шейдеров), `shadows.rs` (каскады солнца и проход глубины), `frame.rs` (`prepare` и `draw`); `instancing.rs` — батчинг (`InstanceSet` по материалу и мешу, `BlendSet` с сортировкой). Offscreen GPU-тесты в `core/tests/` (общий `Harness` и по файлу на область). Конструкторы пайплайнов, раскладок и буферов вынесены в `pipelines.rs`. Пайплайны создаются под конкретный формат цвета, MSAA и глубину. Если цель не sRGB (как в egui), гамма кодируется в шейдере. `GpuMeshes` — GPU-копии одного реестра `Meshes`, `ViewData` — данные одной камеры (uniform-буфер и инстансы). Методы: `upload`, `prepare(view, gpu, world, view_proj, settings)` (проход по `(GlobalTransform|Transform, MeshRenderer)` с отсечением по сфере, бакеты по мешу, один буфер инстансов) и `draw(view, gpu, pass)` в чужой проход рендера. `camera_view_proj(world, aspect)`. Порядок на вид: `prepare` → `render_shadows(view, gpu, encoder)` → `draw`. У каждого `ViewData` своя карта теней (Depth32Float, создаётся лениво, до этого 1×1 заглушка), атлас 2×2 из тайлов каскадов (см. ниже); кастеры каждого каскада отсекаются по его собственному боксу. Пиксельный тест рисует куб в offscreen-текстуру (проверен на Vulkan и llvmpipe).
- `renderer.rs`: оконный `Renderer` = `RenderCore` + surface. Создаёт instance с display handle (для GLES/Wayland), adapter и device с лимитами WebGL2, определяет `RenderTier` (`tier_of`). При vsync — Fifo, иначе Mailbox или Immediate. Также `begin_pass` и `create_depth`. Крейт реэкспортирует `wgpu`.
- `light.rs`: компонент `Light { kind: LightKind::{Directional, Point, Spot}, color (линейный), intensity, range, spot_angle_deg, shadows }`, вперёд = −Z из `GlobalTransform`. Первый направленный `Light` заменяет солнце из настроек; остальные — до `MAX_LIGHTS = 16` ближайших после отсечения по фрустуму, упаковываются в uniform (std140). Камера тени: сфера вокруг первых `shadow_distance` метров фрустума, привязка к текселям (без дрожания).
- `mesh.rs`: `Vertex { position, normal }`, `MeshData` (`cube`, `plane`, `from_triangles`, `bounding_sphere`). `Meshes::add` возвращает `MeshHandle` ещё до появления GPU, загрузка ленивая; `Meshes::set` перезаливает геометрию в тот же слот (правка мешей в редакторе).
- `texture.rs` / `material.rs` / `shader.rs`: реестры `Textures` (`TextureData { width, height, format: TextureFormat::{Rgba8Srgb, Rgba8Linear, Rgba16Float, Rgba32Float}, pixels }`, мипы на CPU, sRGB усредняется в линейном пространстве; Rgba32Float заливается как Rgba16Float — на WebGL2 только он фильтруется), `Materials` (`Material` повторяет `MaterialDesc` с хэндлами вместо путей; `MeshRenderer { material: None }` рисуется `Material::fallback()`) и `Shaders` (поверхностные шейдеры). Реестры, как `Meshes`, работают до GPU; `RenderCore::upload_assets(gpu, textures, materials, shaders)` вызывается рядом с `upload`. Пользовательский WGSL ставится перед шаблоном (`globals.wgsl` + `mesh.wgsl`) — номера строк ошибок совпадают с файлом; naga проверяет при `add`/`set`, пайплайн создаётся в error scope, ошибка — `Shaders::error(h)`, остаётся последний рабочий пайплайн; `validate_surface_shader(src)` для редакторов. PBR: GGX + Smith + Schlick (metallic-roughness, конвенция Unity), normal map, ORM, emissive, alpha cutoff, unlit, triplanar; спекуляр ambient берёт небо вдоль отражения. `RenderSettings.sky: SkyMode::{Color, Procedural{..}, Texture{texture, rotation, intensity}}` — полноэкранный треугольник на дальней плоскости в том же проходе (и в чужом проходе редактора), солнечный диск по первому направленному свету, туман у горизонта уходит в небо. Инстансы по (материал, меш), порядок (пайплайн, материал, меш), без аллокаций. `RenderCore::set_time`. WebGL2: 9 атрибутов (Vertex = position, normal, uv, tangent, 48 Б), 5 varyings, 2 bind group, 6 текстур. 33 теста на Vulkan и llvmpipe GL.
- Прозрачность: `Material.blend: BlendMode::{Opaque, Alpha}`. Смешиваемые инстансы уходят из основного списка в `BlendSet`: `prepare` считает глубину центра ограничивающей сферы вдоль `view_plane`, `sort_unstable_by` (сначала дальние, при равенстве по ключу, чтобы они всё равно батчились), подряд идущие серии (материал, меш) делят один draw. Порядок в `draw`: opaque, небо, смешиваемые (отдельный пайплайн: `ALPHA_BLENDING`, без записи глубины, тест `Less`). Смешиваемые меши не отбрасывают тень. У поверхностных шейдеров blend-пайплайн создаётся лениво (`SurfacePipeline { module, opaque, blend }`, `build_blend_pipelines` в `upload_assets`). В установившемся режиме без аллокаций.
- Каскадные тени (`light.rs::fit_cascades`, `RenderSettings.shadow_cascades/shadow_filter/shadow_filter_radius`): первые `shadow_distance` метров делятся на до `MAX_CASCADES` (4) слоёв (0.6/0.4 логарифмически/равномерно; для ортографических камер равномерно), у каждого своя ортографическая камера вокруг ограничивающей сферы слоя, с привязкой к текселям. Один `Depth32Float` — атлас 2×2 (при одном каскаде вся карта); `render_shadows` — один проход со `set_viewport` на каскад; матрицы сэмплирования в `Globals` уже сдвинуты в тайл. В `mesh.wgsl` `sun_shadow` выбирает каскад по глубине, на последних 10% смешивает со следующим, переходит к следующему, если выборка (с учётом ядра) вышла за тайл, и затухает на `shadow_distance`. Фильтр `ShadowFilter::{Hard, Pcf (3×3, по умолчанию), Soft (16 выборок по повёрнутому диску, gradient noise)}`; `RenderCore::tier()` (из бэкенда; `set_tier` переопределяет): Compat ограничен 2 каскадами, а Soft откатывается к Pcf. Не сделано: PCSS и тени от point/spot.
- `post.rs` / `post.wgsl`: `PostProcess`, цепочка постобработки тира Full. Окно рисует сцену в `HDR_FORMAT` (Rgba16Float, `RenderCore::set_hdr_output(true)`: шейдеры пропускают экспозицию, тонмаппинг и sRGB), затем полноэкранные проходы: bright-pass + даунсэмпл до 1/2, до 1/4, гауссов блюр H/V и композит (bloom + экспозиция + ACES/clamp + sRGB, если цель не sRGB). `RenderSettings.bloom: Option<Bloom { threshold, intensity }>` (по умолчанию выключен). Compat и редактор (чужой проход) остаются на старом пути: тонмаппинг в шейдере меша. Не сделано: SSAO/GTAO, TAA/FXAA, LUT-грейдинг, высотный туман.
- `skinning.rs`: `SkinnedMesh { animator, bind mesh, joints, weights }` — скиннинг на CPU (4 влияния, нормали/тангенты поворачиваются), `skin_meshes` в `PostUpdate` пересчитывает меш через `Meshes::set`, когда у `Animator` выросла `version`. Работает на всех тирах (WebGL2/GLES3) и даёт позу теням и прозрачным; один слот меша на экземпляр. GPU-скиннинга (шейдер) пока нет.
- `frustum.rs`: 6 плоскостей из view-proj (Gribb–Hartmann, глубина 0..1), тест сферы.
- `particles.rs`: CPU-частицы. Компонент `ParticleEmitter { params: EmitterParams, texture, playing }` + `EmitterParams` — чистые данные (feature `serde`, `#[serde(default)]`): `rate`, `bursts`, `duration`/`looping`, `shape: EmitShape::{Point, Sphere, Hemisphere, Cone, Box, Circle}`, диапазоны `lifetime/speed/size/rotation/spin`, `gravity`, `drag`, `space: SimSpace::{World, Local}`, `color` × `color_over_life` (градиент), `size_over_life`, `blend`, `flip_book`, `sort`, `texture_path` (разрешает загрузчик), `seed`. Симуляция в `Stage::PostUpdate` (`update_emitters(world, dt)`): хранилище резервируется под `max_particles`, мёртвые убираются `swap_remove`, рождения размазываются по шагу, ГСЧ детерминирован по `seed`. `ParticleRenderer::{new, prepare(device, queue, gpu, world, view_proj), draw(pass)}` — билборды по осям камеры (берутся из строк view-proj), с depth-тестом без записи глубины, alpha сортируется от дальних. Нет тонмаппинга/освещения.
- `quad.rs` / `quad.wgsl`: общий батчер цветных квадов (`QuadBatcher`): инстанс = origin + два ребра + цвет + uv (80 Б, 5 атрибутов), 6 вершин из `vertex_index`, один uniform, текстура + сэмплер на батч; подряд идущие квады с одной (текстура, `QuadFilter::{Linear, Mipmapped, Nearest}`, `QuadBlend::{Alpha, Additive}`) — один draw. Bind-группы кэшируются по (текстура, фильтр, поколение); буферы переиспользуются. Тесты рисуют офскрин и читают пиксели (частицы, спрайты, атласы, тайлмапы).
- `sprite.rs`: 2D. `Sprite` (текстура/`uv`/`size`/`pivot`/цвет/flip/`layer`/`y_sort`/blend/filter/`space`), `SpriteAtlas` (`grid`, регионы по имени с pivot, `sprite(region, ppu)`), `TileSet` (margin/spacing, uv с подрезкой на 0.02 текселя), `Tilemap` (`tiles: Vec<u32>`, 0 = пусто, иначе индекс+1 с битами `FLIP_X/FLIP_Y`; рисуются только клетки в видимой области), `Camera2d { height }` (поза из трансформа сущности, y вверх). `Space2d::{World, Screen}`: Screen — пиксели от левого верхнего угла (y вниз), без камеры, всегда поверх мира (игровой UI). `SpriteRenderer::{new, prepare, draw}`: отсечение по вьюпорту, сортировка (space, layer, глубина z или y, текстура), без depth-теста, поверх 3D. Всё данные + serde, как у частиц.
- `overlay.rs`: экранный оверлей (игровой UI). `Overlay { quads }` — ресурс, куда продюсеры (`olvin_gui`) каждый кадр кладут `OverlayQuad` (прямоугольник в физических пикселях, uv, линейный цвет, текстура) в порядке рисования; `RenderPlugin` чистит его в `Stage::First`. `OverlayRenderer` — тонкая обёртка над `QuadBatcher` (без глубины, альфа-смешивание, линейный фильтр, подряд идущие квады с одной текстурой = один draw), `begin_overlay_pass` — проход поверх готового изображения (`LoadOp::Load`). `Renderer` рисует его отдельным проходом после постобработки и тонмаппинга, так что UI не получает bloom и ACES. Только обычные вершинные/фрагментные шейдеры: работает на тире Compat (WebGL2/GLES3). Тест: `overlay_paints_in_order_without_depth`.
- `Renderer` (окно) создаёт `ParticleRenderer` и `SpriteRenderer` и рисует их в основном проходе после мешей (и в HDR-цепочке). Не сделано: GPU-частицы, подключение к `scene_file`/редактору (компоненты не читаются из сцены), анимация спрайтов (кадры по времени), текстовый рендер, 9-slice, свет/тени на спрайтах, стрейч-билборды, столкновения и шлейфы частиц; во вьюпорте редактора (`EngineGpu`) частицы и спрайты не рисуются.
- `RenderSettings.scene_lights` (по умолчанию true): false — компоненты `Light` игнорируются (Solid-вид редактора).
- `mesh.wgsl`: instanced-шейдер в пределах WebGL2: один uniform, 7 атрибутов (матрица модели — 4 vec4 + цвет). Полусферический ambient, солнце с PCF 3×3 (сравнивающий сэмплер, slope bias + normal offset, затухание к краю дистанции), 16 point/spot (спад `saturate(1-(d/r)^4)^2/(d²+1)`, мягкий конус), Blinn-Phong, туман, экспозиция + ACES, sRGB. `shadow.wgsl` — проход только глубины. Тени работают и на Compat (GL).

## olvin_csg

Классический CSG редакторов уровней (Hammer, Realtime CSG) по выпуклым брашам.
- `shapes.rs`: `BrushShape` (Box, Wedge, Cylinder{sides}, Pyramid{sides}, Stairs{steps}) в локальном единичном кубе `[-0.5, 0.5]³`, поэтому размер браша — это его scale. Каждая форма — это набор выпуклых кусков (у лестницы кусок на ступень).
- `convex_hull(points)` (перебор троек, для брашей с десятками вершин), `shape_vertices(shape)` (углы однокусковой формы). `BrushInput.vertices: Option<Vec<Vec3>>` — отредактированный браш, это оболочка своих вершин вместо параметрической формы.
- `lib.rs`: `build(&[BrushInput]) -> Vec<Polygon>`. Каждая грань дробится плоскостями пересекающихся кусков (AABB-отсев), так что каждый фрагмент целиком внутри или снаружи каждого браша. Фрагмент остаётся, если твёрдость по разные стороны от него различается: точки берутся на ±2 мм по нормали, а операции `CsgOp::{Add, Subtract, Intersect}` применяются по порядку. Совпадающие сонаправленные грани оставляет только последний кусок. Метод устойчив к касающимся и совпадающим граням, где BSP-подходы ломаются. Зеркальные трансформы переориентируются. Есть `brush_edges` для контуров и `TriMesh::from_polygons`. `BrushInput.faces` — смоделированный браш (замкнутая поверхность из выпуклых полигонов, может быть невыпуклой): такой кусок проверяется на «внутри» обобщённым числом обмоток (телесный угол, Van Oosterom–Strackee), а фрагменты режутся всеми его плоскостями (для выпуклых — быстрый отсев по передней стороне). Ориентация граней выравнивается по знаку объёма (зеркальные трансформы). 8 тестов: комната, туннель, порядок операций, пересечение, замкнутость всех форм.

## olvin_mesh

Редактируемая полигональная сетка `PolyMesh { positions, faces: Vec<Vec<u32>> (n-угольники, против часовой снаружи), wire: Vec<[u32; 2]> (свободные рёбра) }`, сериализуется (feature `serde`). Добавляющие операции сохраняют все индексы; удаляющие возвращают `Remap` для вершин и граней. `validate()` проверяет инварианты. Операции: `extrude_faces` (регион: стенки только по границе выделения) / `extrude_edges` / `extrude_vertices`, `inset_faces`, `split_edge`, `connect_vertices`, `knife`, `loop_cut` (кольцо по квадам), `make_face` (порядок выбора не важен, ориентация по соседу), `fill_edges` (петля, цепочка или мост из двух рёбер), `delete_vertices/edges/faces(keep_edges)` (грани → рёбра), `dissolve_edges`, `merge_vertices`, `merge_by_distance`, `flip_faces`, `recalculate_normals_outside`, `subdivide_faces`, `catmull_clark`, `triangulate` (ear clipping в плоскости грани, плоские нормали), `compact`. `walk.rs`: `adjacency()` (`Adjacency`: рёбра → грани, соседи и грани вершин), `edge_loop` (через 4-валентные вершины, по границе и wire-цепочкам), `ring` (петля граней и кольцо рёбер через квады), `linked`, `grow_selection`, `shrink_selection`, `duplicate`. Конструкторы: `cube`, `plane`, `from_polygons(polys, weld_eps)`. UV по углам граней: `uvs[f][i]` ↔ `faces[f][i]`, пустой массив = «UV ещё нет» (`ensure_uvs` — box), V вверх как в Blender (в рендер V переворачивается: `olvin::render_assets::poly_mesh_data`), швы `seams`; все операции держат UV согласованными (интерполяция, mean value coordinates для inset, изометричные стенки extrude). `uv.rs`: проекции (box/planar/cylinder/sphere/from view/follow active quads), острова, `transform_uvs`, texel density, `triangulate_uv`. `unwrap.rs`: LSCM по картам, разрезанным швами, масштаб к реальной площади, поворот к минимальному bbox, упаковка полками в 0..1. 55 тестов.

## olvin_assets

Ассеты как в Unity, без GPU. `AssetRoot` (`assets/`): `resolve/relative`, `scan()` создаёт `.meta` (RON: `Meta { guid, importer: Importer::{None, Texture(TextureImport { srgb, max_size, generate_mips, point_filter }), Model(ModelImport { scale, .. })} }`), копии с чужим meta получают новый GUID, `guid_of/path_of`, `move_asset/delete_asset` переносят meta. `texture.rs`: `load_image(path, srgb)` → `ImageData` (HDR/EXR во float), `thumbnail`, `ThumbnailCache` (LRU). `model.rs`: `import_gltf` → `ModelData { meshes, materials: MaterialDesc, nodes (YXZ), extracted_textures, skipped }`, встроенные картинки в `<model>_textures/`, `model_to_entities` (poly + `uvs_per_face`), `write_materials`. `AssetWatcher` (notify 8): неблокирующий `poll()` с дебаунсом. `AssetsPlugin`. 9 тестов. `manager.rs`: `AssetManager` (ресурс, `AssetsPlugin` гонит его в `Stage::First`, `with_hot_reload()`) — счётные `Handle<T>`/`AnyHandle` (T: `Asset` = `ImageData`, `MaterialDesc`, `ModelData`), `load` отдаёт хэндл сразу и грузит в пуле потоков (meta читается на вызывающем потоке), тот же путь = тот же хэндл; `get` → `Arc<T>`, `state` (`Loading/Ready/Failed`), `is_fully_loaded`, `wait_idle`. Зависимости (`Dependency`) берутся из разобранных данных: материал → текстуры, модель → текстуры своих материалов; хэндлы зависимостей держит запись родителя, поэтому текстура живёт, пока жив материал. Выгрузка: `unload_unused` (и в `update`, если `auto_unload`) снимает записи без хэндлов до неподвижной точки; хэндл, брошенный до выгрузки, оживает без перезагрузки. Горячая перезагрузка поверх `AssetWatcher`: старые данные доступны, пока грузятся новые, при ошибке остаются последние рабочие, `version`/`take_changes` для потребителя (заливка в GPU). 7 тестов менеджера.

`model.rs` (glTF): меши, материалы, скины → `Skeleton`, анимации → `Clip`, камеры (`CameraData`; перспективные попадают в `CameraDesc` сущности), `ModelData::animator(skin)`. Позы в модельном пространстве с масштабом импорта; скин-меш рисуется в корне модели. `KHR_texture_transform` с поворотом запекается в UV примитива, отдельная текстура окклюзии сливается в `<модель>_textures/<материал>_orm.png`. Не поддержаны: морфы, ортографические камеры как компонент, анимация узлов вне скелета на сущностях.

## olvin_script

Скрипты как в Unity, на Rust. Фичи по умолчанию: `input`, `physics`.

- `behaviour.rs`: `trait Behaviour` — `start`, `update`, `fixed_update`, `on_collision_enter/exit`, `on_trigger_enter/exit`, `on_destroy`.
- `lib.rs`: компонент `Scripts(Vec<ScriptDesc>)` с билдером `Scripts::new().with(name, params)`; `ScriptPlugin` создаёт реестр и рантайм, `FixedSystems` получает `fixed_update`, `Update` получает `run_update`. Расширение `App::register_script::<T>(name)` (трейт `ScriptAppExt`).
- `registry.rs`: `ScriptRegistry` — `register::<T: Behaviour + FromParams>(name)`, `register_fn(name, schema, make)`, `create`, `schema`, `export_schema() -> ScriptSchema` (RON для редактора). Макрос `register!` принимает `"имя" => Тип` или просто имена типов.
- `runtime.rs`: `ScriptRuntime` (ресурс) хранит экземпляры; `run_pass` на каждый проход: attach новых, `start` один раз, события коллизий (только `Update`), затем `update` или `fixed_update`, затем отложенные команды и `on_destroy`. Паника в колбэке отключает только этот скрипт (`catch_unwind`).
- `ctx.rs`: `ScriptCtx` — мир и компоненты (`get`, `component`, `has`), `spawn`/`despawn`/`insert`/`remove` (отложены до конца прохода, id у `spawn` валиден сразу), Transform-помощники (`translate`, `rotate_euler_deg`, `look_at`, `forward`), время (`TimeInfo`, `dt`, `fixed_dt`), поиск `find_by_name`/`find_by_tag`/`find_all_by_tag`, ресурсы `res`/`res_mut`, ввод `input()` (фича `input`), `raycast`, `motor()`, `move_character()`, `apply_force`/`apply_impulse`/`set_velocity`/`velocity` для Dynamic-тела (фича `physics`), логи `log`/`warn`.
- `params.rs`: `Params` и `FromParams` (`from_params`, `schema() -> Vec<ParamSpec>`) — строковые параметры из редактора с типами (`parse_vec3`, `parse_bool`).
- `builtin.rs`: готовые поведения — Rotator, Oscillator, Mover, FollowTarget, DestroyAfter, FreeFlyCamera, SimplePlayerController.
- `lua.rs` (фича `lua`, выключена по умолчанию; mlua 0.12, Lua 5.4 `vendored`, системная Lua не нужна): Lua-поведения. `*.lua` возвращает таблицу с колбэками как у `Behaviour` (`start/update/fixed_update/on_collision_*/on_trigger_*/on_destroy`, аргументы `(self, ctx[, other])`) и необязательным `params = {{name, kind, default, doc}}` (схема для редактора, значения типизируются в `self.params`). Имя файла = имя скрипта в сцене. `LuaScripts` (ресурс) регистрирует их в `ScriptRegistry` через `register_fn`; `LuaPlugin { dir, hot_reload, limits }` грузит папку и в `PreUpdate` вызывает `poll` (раз в 250 мс сверяет mtime файлов, подхватывает новые). Горячая перезагрузка: колбэки подменяются в той же `proto`-таблице, а у каждой сущности свой `self` (метатаблица `__index = proto`), поэтому состояние живёт, `start` не повторяется; сломанный файл оставляет старую версию и пишет ошибку; упавший колбэк отключает скрипт до следующей перезагрузки, кадр не падает. `ctx` — userdata, `ScriptCtx` одалживается ему только на время колбэка (`unsafe` в `CtxSlot`, указатель сбрасывается guard'ом; сохранённый `ctx` вне колбэка даёт ошибку). API `ctx:`: `entity/name/dt/fixed_dt/elapsed/frame/log/warn`, Transform (`position/set_position/translate/translate_local/rotate_euler_deg/rotation_euler_deg/set_rotation_euler_deg/scale/set_scale/look_at/forward/right/up/world_position`), поиск (`find_by_name/find_by_tag/find_all_by_tag/alive/world_position_of`), `despawn/destroy_self`, физика (`apply_force/apply_impulse/set_velocity/velocity/raycast`), ввод (`pressed/just_pressed/just_released/value/axis2d`); векторы — таблицы `{x,y,z}` (глобальная `vec3(x,y,z)`), сущности — целые id. Песочница: только `table/string/math/utf8/coroutine`, без `dofile/loadfile/require`, лимит памяти (64 МБ) и инструкций на колбэк (`LuaLimits`). Фасад `olvin`: фича `lua` = `script` + `olvin_script/lua` (`olvin::script::lua`).
- `lua_tests.rs` (с фичей `lua`): 7 тестов (колбэки/параметры/API, перезагрузка с сохранением состояния, сломанный файл и восстановление, новые файлы, песочница, «протухший» ctx, коллизии). Не сделано: бенчмарк Lua против Rust, нодовый редактор, веб, ADR, `require` между файлами, отдельные `FixedUpdate`-таймеры, модуль `lua` в каталоге хаба.
- `tests.rs`: 10 тестов.

## olvin_input

## olvin_audio

kira 0.12: `AudioPlugin { assets_dir, enabled }`, ресурс `Audio` (one-shot, `play_at`, `play_with`, музыка потоком, громкость, высота). `AudioSourceDesc` играет при появлении и следует за позицией; 3D — затухание и панорама от `AudioListener`. Без устройства — no-op. Шины: `BusId::{SFX, MUSIC, AMBIENT, VOICE}` + `add_bus(name)`, у каждой громкость, mute, 3-полосный EQ (`EqSettings`, shelf 250 Гц / bell 1 кГц / shelf 4 кГц) и уровень отправки в общий реверб (`ReverbSettings`, kira send-трек). `PlayParams { bus, priority (0 важнее всего), occludable }`. Occlusion: `set_occluder(|listener, source| 0..1)` (обычно луч физики) или `set_occlusion(id, ..)`; позиционный звук получает свой sub-трек с low-pass (20 кГц → 500 Гц) и падение громкости до 0.35, значение сглаживается. Голоса: `set_max_voices` (64) и `set_max_streams` (8); не влезшие по (priority, громкость, новизна) виртуализируются — зацикленные ждут и стартуют с начала, one-shot отбрасываются. Стриминг: `stream_threshold` для источников, `play_music_fade` (кроссфейд), `position`, ошибки декодера в лог, `unload_clip/clear_clips` для кэша декодированных клипов. В тестах бэкенд — kira `MockBackend`: дорожки и эффекты строятся без звуковой карты. 13 тестов.

## olvin_physics (дополнения)

Фиксированные шаги: `FixedSystems`, кинематика, персонажи, `step_with_events`, обратная запись поз; тела удалённых сущностей убираются. Character Controller: капсула + `CharacterMotor { velocity, grounded, sliding, gravity_scale }`, ступени, уклон, `move_character`. `CollisionEvents` по сущностям. `raycast(_filtered)`, `spherecast(_filtered)`, `overlap_sphere`. `forces.rs`: `Physics::apply_force(&World, entity, force)` (одноразовая сила на следующий шаг, после шага сбрасывается через `clear_forces`, зовите каждый шаг), `apply_impulse` (Δv = импульс / масса), `set_velocity`, `velocity`; работают только с Dynamic-телом, иначе возвращают false (kinematic/fixed/character: у персонажа `CharacterMotor::velocity`). `olvin_window`: `Input.scroll`, публичные сеттеры, `CursorOptions`.

## olvin_scene::file (feature `serde`)

Формат сцен `*.scene.ron`, общий для редактора и игр. `SceneFile { entities, environment, extensions }`; `environment: Environment` (небо и земля для ambient + интенсивность, фон, экспозиция, `filmic` (ACES), `fog: Option<FogDesc>`, дистанция и разрешение теней) пишется, только если отличается от умолчания; `Environment::PRESETS` — Day / Sunset / Night / Studio, `EntityDesc` (стабильный `id`, `active`, `tag`, `layer`, `parent`, позиция, поворот в градусах по Эйлеру YXZ, масштаб, `mesh`, `camera`, `brush: BrushDesc { shape, op, color, vertices }`, `poly: PolyMesh` (отредактированный меш: у обычного объекта заменяет `mesh.shape`, цвет из `mesh`; у браша — его форма для CSG), `EntityDesc::brush_input(transform)` — вход CSG (выпуклые грани poly как есть, невыпуклые — треугольниками), `light: LightDesc` (Directional/Point/Spot), `collider: ColliderDesc` (Box/Sphere/Capsule/Mesh, center, trigger, friction, bounciness), `rigidbody` (Dynamic/Kinematic, mass, drag, gravity, freeze rotation, CCD), `character_controller`, `audio_source`, `audio_listener`, `scripts: [ScriptDesc { name, params }]`). Пустые поля в файл не пишутся. `active_in_hierarchy`, `sun()` — первый активный Directional Light. Родители в списке всегда идут раньше детей. `world_matrices[_with]` разворачивает иерархию в мировые матрицы, `hierarchy_order()` даёт порядок DFS, как в панели иерархии, `csg_brushes()` — браши в порядке операций. `extensions` — данные элементов редактора (клипы аниматора). `model: Option<ModelDesc { path, animation: Option<AnimationDesc::{Clip(имя) | Graph(путь .animgraph.ron) | Inline(AnimGraphDesc)}> }>` (glTF под объектом, `anim.rs`; формат v2; `collider: Mesh` на объекте берёт треугольники модели). `SceneFile.version` (`FORMAT_VERSION`, сейчас 2; миграция v1→v2 пустая, но старые сборки отказываются открывать v2) пишется всегда; файл без поля — версия 0. `SceneFile::parse(text)`/`load` проверяют версию (новее поддерживаемой — ошибка) и прогоняют по распарсенной сцене цепочку `MIGRATIONS` (`fn(&mut SceneFile)`, запись `n` переводит `n → n+1`); переименования и новые поля покрывает `#[serde(alias/default)]`, миграция исправляет смысл данных. Фикстуры старых версий: `crates/olvin_scene/tests/fixtures/`. Ломающее изменение формата = `FORMAT_VERSION += 1` + новая миграция.

## olvin_game

Игровой слой поверх ядра, без GPU и окна. Спавн загруженной сцены остаётся за фасадом `olvin::scene_file`.

- `state.rs`: `App::add_state(S)` (`S: Copy + Eq + Hash + Debug`, обычно enum), ресурс `State<S>` (`get`, `is`, `set`). `set` только запрашивает переход; он применяется раз в кадр в начале `PreUpdate` (побеждает последний запрос): хуки `on_exit(old)`, переключение, хуки `on_enter(new)`, событие `StateChanged<S>`. Хук может сам запросить следующий переход (цепочки обрываются на 8 шагах). `on_enter(initial)` выполняется в `Startup`. `add_system_in_state(stage, S, system)` запускает систему только в своём состоянии. Пауза: `on_enter(Paused, |r| r.fetch_mut::<Time>().pause())`.
- `loader.rs`: `SceneLoaderPlugin` + ресурс `SceneLoader`. `request(path) -> LoadHandle` читает и разбирает сцену (со всеми миграциями) в рабочем потоке; `status` (`Pending/Ready/Failed/Gone`), `take(handle) -> Option<Result<SceneFile, String>>`, `is_loading`. Канал опрашивает система в `First`. Экран загрузки — состояние `Loading`, которое ждёт `Ready` и ставит `Playing`.
- `save.rs`: сохранения игры, отдельно от сцен (сцена — уровень в том виде, как его сделал редактор, сохранение — состояние игровой сессии). `SaveRegistry`: `register_component::<T>(name)` и `register_resource::<T>(name)` (serde + RON, имя входит в формат). Сохраняются только сущности с `SaveId(u64)`. `capture(res, meta) -> SaveData { version, meta: SaveMeta { title, scene, playtime_secs, saved_at }, entities, resources }`, `restore(res, &data)`: сущности с `SaveId` обновляются или создаются, отсутствующие в сохранении удаляются, остальные не трогаются, зарегистрированные компоненты, которых нет в сохранении, снимаются. Всё разбирается до того, как тронут мир, поэтому ошибка ничего не меняет. Неизвестные имена пропускаются с предупреждением. Ссылки между сущностями внутри компонентов не переназначаются: храните `SaveId`. `SaveSlots` (`SavePlugin::new(dir)`): `<dir>/<slot>.save.ron`, `save` (tmp + rename), `load`, `list` (сначала новые, битые файлы пропускаются), `delete`, `exists`; имя слота не может выйти за каталог. Цепочка `SAVE_VERSION` + `SAVE_MIGRATIONS` как у сцен; будущая версия — ошибка. 18 тестов, фикстура `tests/fixtures/v1.save.ron`.

## olvin_physics

`PhysicsPlugin { gravity }` и ресурс `Physics { world: rapier PhysicsWorld }`. На каждом кадре (PreUpdate): сущности с `ColliderDesc` или `RigidbodyDesc` без маркера `Body` получают тела (Dynamic, Kinematic или Fixed, если Rigidbody нет). Масштаб объекта запекается в форму коллайдера, у Rapier масштаба нет. `Mesh` берёт `MeshGeometry`. Кинематические тела следуют за `Transform`, затем фиксированные шаги по 1/60 (не больше 5 за кадр), затем динамические пишут позу обратно. Rapier 0.36 считает в glam 0.33, конвертация через массивы. Тесты: ящик ложится на землю, шар — на mesh-пол, сквозь триггер проходит.

## olvin (фасад)

Features `window` и `render` включены по умолчанию. `scene` добавляет `scene_file::{load, spawn}`: загрузка сцены редактора в `World` — только активные объекты; компоненты переносятся как данные (`LightDesc`, `ColliderDesc`, `RigidbodyDesc`, `AudioSourceDesc`, `Scripts`, `AudioListener`, `Name`, `Tag`); для Mesh Collider примитива добавляется `MeshGeometry`. Объект с `poly` получает собственный меш (триангуляция) и `MeshGeometry` для Mesh Collider. Каждому `LightDesc` добавляется рантаймовый `olvin_render::Light` (`runtime_light`). `apply_lighting(scene, &mut RenderSettings)` переносит солнце и `Environment` в настройки рендера (vsync и прочее окна не трогает) — им пользуются и загрузчик, и редактор. Браш с Rigidbody не входит в уровень: он становится отдельным телом со своим мешем и выпуклым коллайдером. Первый Directional Light задаёт `RenderSettings.light_dir/light_color`. CSG собирается при загрузке: меши по цвету граней плюс одна сущность «CSG Level» со статическим mesh-коллайдером. Иерархия сохраняется: `Transform` локальный, `Parent` связывает детей, `GlobalTransform` сразу задан мировой матрицей. `physics` подключает `olvin_physics` в `DefaultPlugins`. Без них получается чистое ядро + ECS (сервер, инструменты). `DefaultPlugins` добавляет всё включённое. Для игр есть `prelude`. Фичи `script`/`input`/`audio` подключают свои плагины; `Scripts`/`AudioListener` в `scene_file` — их типы, загруженная сцена сразу запускает скрипты, персонажей и звук. `render_assets.rs` (фича `scene`): `RenderAssets` — кэш путь → хэндл для материалов, текстур, шейдеров и неба с горячей перезагрузкой по mtime (раз в 0,5 с), `Registries`, `material_in(res, path)`, `poly_mesh_data` (UV с переворотом V); `RenderAssetsPlugin` в DefaultPlugins, корень задаёт `scene_file::load` (папка `assets` над сценой). Загрузчик раздаёт материалы мешам, poly и CSG-уровню (группы по (цвет, материал), box-UV) и ставит небо. Реэкспорт `olvin::csg`. `models.rs` (фича `scene`): `scene_file::spawn` кладёт на объект с `model` компонент `PendingModel`, `ModelPlugin` (в DefaultPlugins) по готовности `AssetManager` (ресурс `olvin_assets::AssetManager`) строит под объектом дети-меши с материалами (`RenderAssets::inline_material`), скелет, `SkinnedMesh` и `Animator` с графом из `AnimationDesc` (`olvin_assets/animation.rs` переводит `AnimGraphDesc` в `AnimGraph`); `pending_count` — ждать загрузки; работает и без рендера (меши в `Meshes`). Фичи `anim` и `assets` реэкспортируют `olvin::anim`, `olvin::assets`; `AnimPlugin` не требует рендера. Через `SceneLoader` из `olvin_game` грузится тот же `SceneFile`, спавн общий.

Игровой UI, отдельный от egui (egui только в редакторе; крейт зависит от `olvin_core`, `olvin_input`, `glam`). Ядро само не рисует: отдаёт `DrawList`. С фичей `render` (включена в фасаде вместе с `gui`) есть отрисовка.

- `engine.rs`: движок внутри редактора. `EngineGpu` (в ресурсах callback egui): `RenderCore` на device egui, `GpuMeshes` для правки и для игры, `ViewData` на каждую панель. `ScenePreview` — ECS-мир, который раз в кадр собирается из сцены (меши, poly-меши, камеры, свет, glTF-модели в позе по умолчанию, без анимации). `Shading::{Solid, Rendered}` (на каждый вьюпорт, Shift+Z или тулбар): Rendered = `settings_for` (то же, что в игре), Solid = студийный свет из-за камеры, `RenderSettings.scene_lights = false`, без тумана и тонмаппинга. `render_shadows` вызывается из `CallbackTrait::prepare` в render.rs на энкодере egui, до прохода, где карта читается. `prepare_view(state, id, frame, view_proj)` готовит вид: в Play — игровой мир, иначе превью. `PlaySession` — настоящий `App` с `EcsPlugin`, `TransformPlugin` и `PhysicsPlugin`, сцена грузится через `olvin::scene_file::spawn`; модели сцены строит `ModelPlugin` с `AnimPlugin` (скиннинг на CPU живёт в `RenderPlugin`, поэтому в Play меши в позе по умолчанию). Инспектор: секция Model (путь, клип или граф). Есть пауза и шаг на кадр.
- `render.rs` + `viewport.wgsl`: GPU-вьюпорт рисует прямо в render pass egui через `egui_wgpu::CallbackTrait`, в общий буфер глубины. Сначала меши рисует рендерер движка (`Frame.engine`), затем поверх идёт геометрия редактора. Конвейеры: меши (освещение, трипланарная сетка 1 м и ¼ м для `GRID`, подсветка выделения), бесконечная адаптивная сетка (полноэкранный треугольник, пересечение луча с плоскостью, `frag_depth`, затухание мелких линий по `fwidth`, оси X/Z), линии с глубиной и поверх всего. Буферы на вьюпорт растут до степени двойки.
- `state.rs`: `EditorState` — сцена, путь, проект, выделение, `preview` (переопределение поз, не сохраняется), лог, `scene_generation`, активный инструмент (`tools::{VIEW, MOVE, ROTATE, SCALE}` или id элемента), `local_space`, `SnapSettings { enabled, step: Option (None = адаптивный), angle_deg }`, расширения. Undo/redo снимками: изменения коммитятся, когда отпущены мышь и клавиатура, так что перетаскивание = один шаг. Операции: `create/delete/duplicate/reparent/move_sibling`, `open/save/save_as/new_scene`, `request_open`.
- `workspace.rs`: `Tab { kind, id }`, `Workspace { name, dock: DockState<Tab> }`, `Layout` (вкладки рабочих областей, сохраняется в `<config>/olvin-editor/layout.ron` при выходе). Дублирование выдаёт новые id вкладок, у копий независимое состояние панелей.
- `app.rs`: меню (File/Edit/GameObject/Window). GameObject как в Unity: Create Empty, 3D Object/…, Light/…, Audio/…, Camera и пункты элементов. Примитивы создаются со своим коллайдером, камера с Audio Listener. Если инструмент выставил `state.tool_owns_keys`, Delete и Ctrl+D отдаются ему. вкладки рабочих областей как в браузере (клик, двойной клик — переименовать, СКМ или × — закрыть, ПКМ — дублировать или сдвинуть, «+» — шаблон, пустая или копия), DockArea (перетаскивание, разделение, всплывающие окна, «+» в каждой группе вкладок), горячие клавиши (Ctrl+S/N/Z/Shift+Z/Y/D, Del/X), подтверждение при несохранённых изменениях, статус-бар, заголовок окна.
- `theme.rs`: тонкая обёртка над `olvin_ui` (реэкспорт `Palette`, `ThemeKind`, `palette`, `anim`, `logo`, `caps`, `menu_title`, `bold`, `RADIUS_*`, `FS_*`). Константы `BG…LINE_SOFT` = токены темы **Dark** (`Palette::DARK`), оставлены, чтобы панели и плагины компилировались без правок; старые имена `BACKDROP`/`RAISED`/`TEXT_WEAK` — алиасы. Обвязка (верхняя панель, статус-бар, док, меню, кнопки) берёт цвета из `theme::palette(ctx)` и следует выбранной теме; виджеты egui следуют ей через Visuals. Вне STYLE.md: `SELECTED`, `AXIS_*`/`AXES`, `VIEWPORT_BG` (вьюпорт от темы не зависит; `Viewport`/`Game` ставят у себя Visuals тёмной темы, чтобы оверлеи читались на тёмной сцене). `apply(ctx)` переустанавливает текущую тему, `apply_kind(ctx, kind)` меняет её. `dock_style(style, &palette)` — вкладки-пилюли, фокусная инвертирована; `eased_tab_style` плавно (ease-std, 200 мс) переводит вкладку между inactive → front → focused через `TabViewer::tab_style_override`. Верхняя панель: вордмарк `olvin_ui::logo::wordmark` 16 px (курсор мигает раз в секунду через `request_repaint_after`), меню, вкладки рабочих областей, ▶ ⏸ ⏭ по центру; заголовки меню, вкладки, ⚙ и ▶ — `anim::button` (наведение и выбор плавно). `EditorApp::sync_theme` каждый кадр сверяет тему и «Reduce motion» с `Preferences`; подкраска при Play накладывается после. Статус-бар: `● PLAYING` с «дышащей» точкой (`anim::pulse`) или `PAUSED`, новое сообщение лога проявляется (`anim::appear`). Всплывающие меню и окна появляются через `animation_time` egui (0.18 с, 0 при reduce motion).
- `assets/fonts/`: Inter 4.1 и JetBrains Mono 2.304 (Regular + Bold, статические TTF) с лицензиями `Inter-OFL.txt`, `JetBrainsMono-OFL.txt`. Вшивает `olvin_ui` через `include_bytes!` от `CARGO_MANIFEST_DIR` (`/../../assets/fonts/...`).
- Выделение (`state.rs`): `selection` — активный объект, `multi` — остальные; `select`, `toggle_selected` (Ctrl+клик в иерархии и вьюпорте), `select_range` (Shift в иерархии). Move двигает всё выделенное, Delete/Ctrl+D — тоже. Строка иерархии: клик выделяет, перетаскивание меняет родителя.
- `panels/viewport/`: `mod.rs` — состояние панели, общие константы и порядок кадра в `Panel::ui`; блоки `impl Viewport` по задачам: `navigation.rs` (камера, хоткеи), `scene.rs` (геометрия сцены, гизмо компонентов, контур выделения, выбор лучом), `gizmo.rs` (Move/Rotate/Scale), `lights.rs` (ручки радиуса и конуса света), `overlay.rs` (панель инструментов, гизмо вида, иконки, статистика). Камера как в Unity: СКМ — сдвиг, Alt+ЛКМ — орбита, Alt+ПКМ — приближение, ПКМ — обзор, с WASD/QE — полёт (Shift ускоряет, колесо при зажатой ПКМ меняет скорость), Hand(Q)+ЛКМ — сдвиг, колесо, F. Кликабельное гизмо вида: оси ±X/±Y/±Z дают вид по ним, центр переключает Persp/Iso (ортография). Примитивы из `olvin_scene::primitives` с гладкими нормалями, неактивные объекты скрыты, свет вьюпорта от Directional Light сцены. Гизмо компонентов выделенного: коллайдеры (зелёные), свет (лучи, сфера, конус), радиусы звука, Character Controller. Иконки света и звука кликабельны. Инструменты: Q/W/E/R и инструменты элементов, X переключает Global/Local. Гизмо: Move (оси по ближайшей точке луча, плоскости, свободная ручка в плоскости экрана), Rotate (кольца по осям с передней полуокружностью, кольцо вида, угол из экранного угла вокруг центра), Scale (оси с кубиками, равномерный). Перетаскивание считается от снимка начала: привязка позиции к абсолютной сетке на мировых осях и к шагу на локальных, угол 1–90°, масштаб 0.1. Ctrl инвертирует Snap. Шаг Auto — степень двойки от высоты камеры, совпадает с сеткой. Порядок кадра: расширения → гизмо → выбор лучом → сборка геометрии → callback в заранее зарезервированный слот painter'а (3D под оверлеями). Панель инструментов и индикатор осей сверху.
- `prefs.rs`: `Preferences` (тема `theme: ThemeKind`, `reduce_motion`, масштаб UI, чувствительность/инверсия/скорость полёта/зум/FOV камеры, вид по умолчанию Solid/Rendered, тени и туман в окнах редактора, оверлей статистики) в `<config>/olvin-editor/preferences.ron`.
- `settings.rs`: окно Settings (Edit → Settings…, Ctrl+, или ⚙ справа сверху): страницы Rendering (окружение сцены `environment_ui` + качество окон редактора), Scene Camera, Interface, Keymap; сохраняет `Preferences` при изменении. `engine::editor_quality` применяет тени/туман из настроек ко всем видам редактора; `state.render_stats` — статистика последнего кадра на вид (оверлей в углу вьюпорта).
- `panels/lighting.rs`: окно Lighting и рабочая область Lighting: кнопка «Render Settings…», пресеты и список всех ламп; само окружение (`environment_ui`) живёт в Settings → Rendering.

В инспекторе Light — быстрые цветовые температуры (Candle…Sky, формула Таннера Хелланда в линейный цвет).
- `panels/game.rs`: панель Game — вид из первой камеры сцены, в Play это живая игра.

- `panels/inspector.rs`: заголовок Active / имя / Tag / Layer. Сворачиваемые секции: Transform, Mesh Renderer (выбор меша), Camera, Light, Box/Sphere/Capsule/Mesh Collider, Rigidbody, Character Controller, Audio Source, Audio Listener, Scripts (имя + параметры ключ–значение), компоненты элементов. Add Component — всплывающее меню с поиском и категориями Rendering / Physics / Audio / Scripts / Elements.
- `panels/assets.rs`: браузер `assets/` проекта: хлебные крошки, плитки, фильтр, создание папки или сцены, двойной клик открывает сцену.
- `olvin_editor_console`: панель лога с фильтрами по уровню.
- `olvin_editor_csg` (элемент CSG): `CsgViewport` пересобирает CSG, только когда изменился набор брашей (сравнение `BrushInput`), рисует полигоны с сеткой и подсветкой выделения, контуры брашей по цвету операции (с глубиной и бледно поверх — вычитания видны в стенах). Окно «Mapping» (панель + рабочая область): режимы Object / Draw / Resize / Edit Shape (= Edit Mode элемента Modeling), блоки Boolean (операция, Earlier/Later, Duplicate as Carve, Hollow, Rotate 90°, Flip), New brushes, Display, Build. Отдельного полигонального редактора у CSG больше нет: браш моделируется в общем Edit Mode (Tab), CSG режет по его форме. Инструмент Draw Brush (B): по лучу выбирается осевая плоскость поверхности, прямоугольник по сетке, затем высота по ближайшей точке луча к нормали; вниз — вычитание, Shift — вычитание всегда, Esc/ПКМ отменяют. Получается браш выбранной формы с размерами по рамке. Resize (T): 6 ручек граней, грань двигается по своей оси и встаёт точно на линию сетки, противоположная остаётся на месте (scale и position пересчитываются в пространстве родителя). Панель CSG: настройки новых брашей (операция, форма, цвет), Hollow (вычитающий потомок со стенами заданной толщины), Rotate 90°, Flip X/Z, Earlier/Later, отображение, статистика сборки (браши → полигоны → треугольники, мс). Компонент CSG Brush в инспекторе, GameObject → CSG/{Box, Wedge, Cylinder, Pyramid, Stairs, Room}, рабочая область Mapping. Общие настройки лежат в thread_local `Shared`.
- `olvin_editor_modeling` (элемент Modeling): Edit Mode как в Blender для объектов с `poly` и для CSG-брашей (браш остаётся брашем: `make_editable` кладёт его текущую поверхность в `poly`, выбор другого браша в Edit Mode сразу делает его редактируемым; в панели — секция CSG Brush: операция, цвет, Reset to Shape, Detach from CSG). Клавиши Edit Mode не срабатывают при зажатой ПКМ (полёт WASD). Плашка рисуется ниже тулбара (`ViewportCtx.overlay_top`). Tab — войти/выйти (примитив или браш сначала конвертируется в `PolyMesh`: `make_editable`). Общее состояние `Shared` (thread_local): режим, выделение вершинами (`verts`, рёбра и грани выводятся из него), `hidden`, `xray`, `gizmo`, `move_by`, `status`. `transform.rs` — общий модальный движок G/R/S (`Transform::step`): оси X/Y/Z (повтор — локальная/нормаль, третий — сброс), Shift+ось — плоскость, ввод числа (`NumInput`), Ctrl — привязка (сетка / 5° / 0.1), Shift — точность ×0.1, pivot = медиана; чистые функции `cycle`, `constrain_move`, `rotation`, `scaling`, `apply`. `gizmo.rs` — гизмо перемещения (стрелки, плоскости, центр), драг идёт через тот же движок. `cage.rs` — кадр клетки: экранные точки, кэш рёбер/треугольников, видимость (самоокклюзия лучами, ускорение `select::Occluders` — бины треугольников по экранной сетке, пересчёт только при смене камеры/меша), отрисовка (точки граней в режиме граней, тусклые скрытые), пикинг и box select. `select.rs` — чистые функции: `combine`, `box_edges`, `Occluders`. `edit.rs` — расширение вьюпорта: хоткеи (1/2/3, A, Alt+A, Ctrl+I, L/Shift+L, Ctrl+L, Ctrl±, H/Shift+H/Alt+H, Alt+Z, G/R/S, E — экструзия и сразу перемещение, у граней по нормали, I, Shift+D, J, F, X, M, Shift+N, Ctrl+R, K), ЛКМ-драг — рамка (Shift добавляет, Ctrl вычитает), Alt+клик — петля рёбер / Ctrl+Alt — кольцо / в режиме граней — петля граней, плашка слева сверху (Vertex/Edge/Face, X-ray, Gizmo, текст операции), динамическая подсказка. Ставит `tool_owns_keys`; ядро вьюпорта видит это через `keys_owned_last_frame` и не превращает простые клавиши в смену инструмента. На время Edit Mode выключается egui-зум на Ctrl+=/-. Модальная операция ставит `state.busy` — весь жест один шаг undo. Панель Modeling дублирует всё кнопками. GameObject → Mesh/{Cube, Plane, Cylinder, Sphere}, рабочая область Modeling. Базовый вьюпорт рисует `poly` через рендер движка.
- Материалы и ассеты: `materials.rs` — `MaterialLibrary` (скан `assets/`: `*.mat.ron`, картинки, `*.wgsl`; перечитывание по mtime, `create`, `create_shader`), `material_ui`, пресеты. Инспектор: секция Material (выбор/создание, правка всех полей, сохраняется сразу). Settings → Rendering: Skybox. Assets: миниатюры картинок, `.gltf/.glb` — двойной клик или «Import into scene» (`EditorState::import_model`: иерархия, poly с UV, материалы в `materials/<model>/`), «Create material» у картинки. `ScenePreview` держит свои `Textures/Materials/Shaders` и `RenderAssets`, раздаёт материалы, ставит небо в режиме Rendered и сам строит текстурированный CSG для брашей с материалом (элемент CSG оставляет их только для пикинга). - `olvin_editor_uv` (элемент UV Editor): как в Blender (без синхронизации). Панель «UV Editor», рабочая область «UV Editing». `view.rs` — 2D-камера; `select.rs` — выделение углов граней (UV-вершина — углы одной вершины в одной UV-точке), режимы вершина/ребро/грань/остров; `transform.rs` — G/R/S, оси X/Y, ввод чисел, Ctrl-привязка; `ops.rs` — unwrap (U), проекции, швы (Ctrl+E), упаковка (Ctrl+P), flip/rotate/align; `defaults.rs` — «только выделенное в 3D» из `state.mesh_selection` и текстура материала под развёрткой. Панель в `panel/`: `mod.rs` (состояние `UvEditor` и цикл кадра), `toolbar.rs` (меню и запросы), `input.rs` (навигация, хоткеи, выделение кликом и рамкой), `modal.rs` (модальные G/R/S), `draw.rs` (отрисовка холста), `tests.rs` (headless-тесты через события egui).
- `olvin_editor_ide` (элемент IDE, по умолчанию выключен): Explorer / Code / Problems / Output и рабочая область Code. Подсветка Rust/WGSL/RON/TOML/Markdown, поиск/замена, автоотступ, пары скобок, Ctrl+/; фоновый `cargo check|build|run` с JSON-диагностиками; проверка surface-шейдеров naga; палитра Ctrl+Shift+P, переход к файлу Ctrl+E; `KeyRouter` забирает Ctrl+S/N у сцены, пока фокус в коде. 38 тестов.

## hub (olvin-hub, рабочее имя)

Хаб создаёт проекты игр и ставит в них модули. Источник правды о модулях — `Cargo.toml` игры, у хаба нет своего состояния об установленном.

- `olvin_hub/catalog.toml`: встроенный каталог. `kind = "olvin"` — фича фасада `olvin` (плагин подключит `DefaultPlugins`). `kind = "crate"` — зависимость с crates.io (rapier3d, kira, gltf, rand, serde, ron). Поле `requires` ставит модули вместе.
- `catalog.rs`: `Catalog` (парсинг, проверка `requires`, `resolve` — сначала зависимости, ловит циклы, `categories`), `Module`, `Source`.
- `project.rs`: `Project::create` (модули с `default = true`) и `create_with(modules)` для шаблонов, `modified()`, `open`, `discover` (ищет вверх по папкам), `add` (вместе с requires), `remove` (не даёт удалить то, от чего зависят другие, если нет `force`), `save`. Правки через `toml_edit`, комментарии и форматирование пользователя сохраняются. `olvin` подключается с `default-features = false`, список модулей Olvin = `features`.
- `build.rs`: `Project::build(&BuildOptions { release, out, archive, target_dir })` — `olvin-hub build [--release] [--out DIR] [--archive tar.gz|zip]`. Запускает `cargo build --message-format=json-render-diagnostics` (вывод cargo идёт в терминал, путь к exe берётся из `compiler-artifact`), затем кладёт exe и копию `assets/` (без скрытых файлов и `*~`) в `<проект>/dist/<имя>` (или `--out`) и при желании пакует рядом в `<out>.tar.gz` / `<out>.zip` (внутри папка с именем игры, `flate2`+`tar`/`zip`). Выходную папку пересобирает только если её создал хаб (маркер `.olvin-build`), чужую непустую не трогает. Игра ищет `assets/` рядом с запуском, поэтому папка сразу запускается. Тесты: ядро на временных проектах с заглушкой `olvin` (4), CLI (`hub/olvin_hub_cli/tests/build.rs`, 2) с `XDG_CONFIG_HOME` во временной папке. Не сделано: кросс-компиляция (`--target`), сжатие/стрипинг ассетов, кнопка в GUI, подпись и инсталляторы.
- `config.rs`: `HubConfig` в `<config_dir>/olvin-hub/config.toml` (на Linux учитывает `XDG_CONFIG_HOME`): список проектов, `EngineSource` (`path` к checkout'у или `git`; по умолчанию папка, из которой собран хаб, если её нет — GitHub) и `[gui]` (`GuiSettings`: `theme` = dark/light/graphite/high-contrast, `reduce_motion`, `view` = list/grid, `sort` = modified/name — строками, чтобы ядро не зависело от UI).
- `template.rs`: Cargo.toml (deps всегда -O3, свой пустой `[workspace]`), `src/main.rs` — графический (грузит `assets/scenes/main.scene.ron`, иначе куб) или headless, если нет window+render+scenes; README, .gitignore.
- `editor.rs`: `EditorInstall` в `<data_dir>/olvin-hub/editor` — сгенерированный крейт (`Cargo.toml` + `main.rs` с плагинами, бинарник `olvin-editor`). Источник правды — его `Cargo.toml`. Методы: `write`, `build_command` (`cargo build --release`), `launch(project)`. Свежесть: `engine_fingerprint(engine)` — максимальный mtime `*.rs/*.toml/*.wgsl` в `crates/` и `editor/` плюс `Cargo.lock`; после сборки `mark_built` пишет `.engine-stamp`, `is_stale` сравнивает. CLI `editor open` и GUI при открытии проекта пересобирают устаревший редактор сами, GUI показывает плашку «The engine changed…» с кнопкой Rebuild. Элементы редактора описаны в каталоге как `[[editor_module]]`.
- Логотип: `olvin-hub-gui` ставит иконку окна так же, как редактор (`window_icon()`, `olvin-icon-256.png`). CLI печатает в шапке справки текстовый логотип `Olvin_` с зелёным `_` (`logo()` → clap `before_help`; без аргументов показывается справка). Цвет снимает clap при `NO_COLOR` и выводе не в терминал.
- CLI: `new`, `list`, `add`, `remove [--force]`, `run [--release]`, `projects`, `register`, `forget`, `engine [--path|--git]`, `editor install|list|add|remove|open [проект]`.
- Хаб, CLI и каталог (имена и описания модулей) на английском, тексты по STYLE.md §10.
- GUI (`olvin_hub_gui`, лаунчер в духе Unity Hub на `olvin_ui`, своей темы нет). Модули:
  - `main.rs`: `Hub` (состояние, действия, `poll` процессов cargo, тосты), `draw`. Тему и reduce motion ставит `sync_style`: первый `olvin_ui::apply` делается в замыкании создания eframe (шрифты включаются со следующего прохода, `bold()` в том же проходе паникует), кадр после первого apply пропускается.
  - `chrome.rs`: фон `--bg-radial` (полярный меш), боковая панель (вордмарк `logo::wordmark_intro` + «Hub», пункты Projects / Editor / Settings, полоска выбора скользит через `widgets::tween`; окно < 1000 px — узкая колонка с `logo::mark` и иконками), статус-строка (точка статуса, Ready / Building editor / игра + Stop, справа `ENGINE path · /…` моно с обрезкой), тосты (снизу справа, выезд и fade 300 мс, клик закрывает, ошибки 8 с с иконкой), переход страниц (fade + сдвиг 10 px), `page_header` (кнопки уходят под заголовок при ширине < 560).
  - `projects.rs`: поиск, переключатели сортировки (Recent / Name) и вида (list / grid) пилюлями, пустое состояние. Раскладка по ширине: ≥ 900 — таблица `name+path | modified | modules | actions` с общими `Columns` для шапки и строк (клик по NAME/MODIFIED сортирует), 600–900 — узкая колонка модулей, < 600 — карточки с мета-строкой «4h ago · 5 modules»; grid — карточки ≥ 250 px. Чипы модулей всегда в одну строку, лишнее сворачивается в `+N`; пути моно с `…`, полный путь в подсказке. Плитка с буквой, у самого свежего проекта (за неделю) — акцент. Hover: светлее фон, подъём 3–4 px, тень сильнее; появление строк лесенкой (`anim::stagger`, свой id на каждое открытие страницы).
  - `editor_page.rs`: карточка установки (знак, версия, статус, Open / Install / Rebuild), элементы карточками с Install/Remove — изменения копятся (`editor_pending`) и применяются одной пересборкой из всплывающей плашки «N changes · Discard · Apply»; журнал сборки (stderr cargo читается в фоновом потоке).
  - `settings.rs`: тема (карточки-миниатюры всех `ThemeKind`), Reduce motion, источник движка, About. Сохраняется в `[gui]` конфига.
  - `dialogs.rs`: модалки New project (шаблоны карточками, модули toggle-карточками с учётом `requires`, имя с проверкой, путь), Add project, Modules (по категориям, правки сразу в Cargo.toml). Появление `--ease-pop` (сдвиг + fade), радиус 20, светлая верхняя кромка. Важно: в модалках не использовать `ui.separator()` в горизонтальном layout — он берёт доступную высоту, окно растёт каждый кадр.
  - `widgets.rs`: `Btn` (primary/secondary/ghost, scale 0.98 при нажатии), линейные иконки, `chip_line`, `pill_switch` (подсветка скользит), `toggle`, `card_bg`, `tween`/`since`/`entrance`.
  - Горячие клавиши: Ctrl+N — новый проект, Ctrl+, — настройки. Все анимации ≤ 500 мс и выключаются reduce motion; repaint запрашивается только пока что-то движется (и раз в полсекунды для мигания курсора).
  - Тесты: `dialogs_fit_their_content`, `pages_render_at_all_widths` (470/800/1280/1920, обе раскладки, headless `Context::run_ui`). `shots.rs` (ignored): `egui_kittest` + wgpu через `build_eframe` рисует все страницы, диалоги и темы на 4 ширинах в PNG (`OLVIN_HUB_SHOTS=<папка>`, на llvmpipe: `__EGL_VENDOR_LIBRARY_FILENAMES=…/50_mesa.json WGPU_BACKEND=gl cargo test -p olvin_hub_gui -- --ignored screenshots`).

## Проверено

- Vulkan, RTX 3050: тир Full, 40k кубов за 2 draw call, упор в vsync.
- GL через Mesa llvmpipe (`__EGL_VENDOR_LIBRARY_FILENAMES=.../50_mesa.json WGPU_BACKEND=gl`): тир Compat, 10k кубов, около 90 fps на CPU-растеризаторе.
- GL на проприетарном NVIDIA под Wayland не работает: EGL не даёт native-renderable конфиг, и wgpu-hal отказывается презентовать. Это ограничение wgpu, не движка.
