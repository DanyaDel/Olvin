# Вертикальный срез: чего не хватило

Шаг 2 из [ROADMAP.md](../../ROADMAP.md): маленькая игра от первого лица на текущем движке, без правок движка. Здесь записано всё, обо что она споткнулась. Порядок — по тому, насколько сильно пункт мешает срезу: сверху то, без чего игру нельзя показать человеку, снизу мелочи.

Размер как в плане: **S** до недели, **M** несколько недель, **L** месяц и больше.

## Что получилось

`apps/vertical_slice`: уровень в `assets/scenes/level.scene.ron` (пол, стены, перегородка с дверью), персонаж от первого лица (мышь, WASD, Shift, прыжок), ящики и мяч на физике, которые можно толкать, нажимная плита-триггер, которая открывает дверь со звуком и сообщением, гудящий маяк с позиционным звуком и Lua-поведением, музыка, анимированный glTF-робот (Idle ↔ Wave через граф анимаций, машет, когда подходишь), пауза на Esc, быстрые сохранения F5/F9 через `olvin_game` в слот. Уровень грузится в фоне через `SceneLoader` (состояние `Loading`).

Всё бинарное (робот, звуки, музыка) генерирует `tools/gen_assets.py`, CC0.

Проверка: `cargo test -p vertical_slice` — 6 headless-тестов играют настоящий уровень (триггер открывает дверь, ящик толкается, сохранение → загрузка возвращает позиции, пауза замораживает мир, робот машет, Lua крутит маяк) и седьмой фиксирует пробел движка (персонаж сам не толкает тела). Окно: `cargo run -p vertical_slice -- --frames 240` (или `OLVIN_SLICE_AUTOQUIT=240`) — стартует на Vulkan, тир Full, около 185 fps.

## Пробелы

### 1. Нет текста на экране и игрового UI — L

- **Нужно было:** подсказки управления, сообщение «Дверь открыта», «Сохранено», меню паузы.
- **Что вышло:** рендер не умеет текст (нет шрифтов), `olvin_gui` строит `DrawList`, но его никто не рисует, и фасад его не реэкспортирует. У спрайтов нет флага видимости.
- **Обход:** HUD из экранных спрайтов (`Space2d::Screen`): прицел, полоса, длина которой зависит от длины сообщения, затемнение с «‖» на паузе. Скрытие — нулевой размер. Сам текст уходит в лог и stdout. Человек без терминала не узнает, что делать.
- **План:** Фаза 2, «Игровой UI в рантайме» [P1] и «2D-конвейер … текст» [P1 для UI].

### 2. Сцена не умеет ссылаться на модели и анимированных персонажей — M

- **Нужно было:** поставить робота в уровень так же, как куб.
- **Что вышло:** в `EntityDesc` нет поля модели, `scene_file::spawn` glTF не знает. В редакторе модель импортируется как статичные `poly`, скин и клипы теряются.
- **Обход:** пустой объект `RobotSpawn` в сцене, а игра сама импортирует `robot.gltf` (`olvin_assets::import_gltf`), собирает `Animator` с графом, `SkinnedMesh` на каждый примитив и коллайдер (`robot.rs`, ~70 строк, которые должны быть в движке).
- **План:** Фаза 2, «Скелетная анимация» [~] — «сцена и редактор про анимированные модели не знают»; «Редактор анимаций» [P2].

### 3. Пути к ассетам считаются от текущей папки — S

- **Нужно было:** запуск и через `cargo run -p vertical_slice` из корня репозитория, и из папки сборки хаба.
- **Что вышло:** `AudioPlugin` по умолчанию берёт `assets`, `InputPlugin` — `assets/input.ron`, шаблон хаба — `assets/scenes/main.scene.ron`, логи — `logs/`, всё от рабочей папки. Из корня workspace это корневой `assets/` с логотипами: сцена не находится, звук молчит, ошибок почти нет.
- **Обход:** `find_assets()` ищет папку рядом с exe, потом в `CARGO_MANIFEST_DIR`, потом `./assets`, и игра передаёт явные пути во все плагины.
- **План:** нет в плане (рядом с фазой 4: «игра ищет `assets/` рядом с запуском»). Нужен ресурс «корень проекта», который читают все плагины.

### 4. Сохранения: движковые компоненты не сериализуются, физика не восстанавливается — M

- **Нужно было:** F5/F9 возвращают положение игрока, ящиков, двери.
- **Что вышло:** `SaveRegistry` есть, но `Transform`, `CharacterMotor` и состояние тел не реализуют serde, их нельзя зарегистрировать. После `restore` новый `Transform` у динамического тела ничего не меняет: физика на следующем шаге перезаписывает его позой из Rapier. Внутреннее состояние поведений (поля Rust-`Behaviour`, `self` в Lua) не сохраняется вообще.
- **Обход:** свой компонент `Pose`, который копируется из `Transform` перед `capture`. После `restore` игра лезет в Rapier через `Body.handle`: `set_position`, обнуляет скорости (`save.rs`). Состояние, которое надо сохранять, вынесено из поведений в компоненты (`DoorState`) и ресурс (`Progress`).
- **План:** Фаза 1, «Сохранение и загрузка игры» [x] — отмечено как сделанное, но для игры с физикой нужны: serde у `Transform`, встроенная регистрация поз, телепорт/сброс тела в `olvin_physics`.

### 5. Объект сцены теряет id, игровые компоненты из сцены не задать — S

- **Нужно было:** `SaveId` = id объекта в сцене, `DoorState` на двери прямо из уровня.
- **Что вышло:** `scene_file::spawn` не кладёт `EntityDesc.id` на сущность (нет `SceneId`) и не возвращает соответствие id → `Entity`. Своих компонентов в сцене нет, только `scripts` со строковыми параметрами.
- **Обход:** после спавна игра ищет объекты по имени (`level::SAVED`, `level::setup`) и навешивает `SaveId`, `Player`, `DoorState`. Переименуешь объект в редакторе — молча сломаются сохранения.
- **План:** нет в плане (рядом с «Префабами», фаза 1).

### 6. Lua-поведения не видят звук, ресурсы и другие объекты — M

- **Нужно было:** логику плиты и двери написать на Lua, как задумано.
- **Что вышло:** у `ctx` в Lua есть только свой `Transform`, поиск по имени и тегу, физика своего тела и ввод. Нет проигрывания звука, нет ресурсов и событий (HUD, прогресс), нельзя двигать или читать другой объект (только `world_position_of`), нет `name_of(other)`, нет компонентов. Состояние Lua не попадает в сохранения.
- **Обход:** плита и дверь — Rust-поведение `DoorSwitch`. На Lua только декоративный маяк (`scripts/beacon.lua`: крутится, качается, здоровается в лог).
- **План:** Фаза 3, Lua [~], «Биндинги `ScriptCtx`» (отмечено [x], но для геймплея мало).

### 7. Хаб: в каталоге нет модулей `game` и `lua`, нет движковых крейтов glTF и анимации — S

- **Нужно было:** проект, который хаб умеет собрать из каталога.
- **Что вышло:** у фасада есть фичи `game` и `lua`, но в `catalog.toml` их нет: `olvin-hub new`/`add` их не поставит. Модули `gltf` и `saves` ставят голые крейты `gltf` и `ron`, а не `olvin_assets` и `olvin_game`. `olvin_assets` и `olvin_anim` фасад не реэкспортирует (см. п. 2), поэтому срез зависит от них напрямую по пути. В отдельном проекте хаба это ручная правка `Cargo.toml` с путём к checkout'у движка.
- **План:** Фаза 3, «Хаб: модуль `lua` в каталоге…»; Фаза 2, «`olvin` не реэкспортирует `olvin_anim`»; для `game` и `olvin_assets` — нет в плане.

### 8. Персонаж не толкает динамические тела, нет колбэка удара контроллера — S

- **Нужно было:** подойти к ящику и сдвинуть его.
- **Что вышло:** контроллер Rapier огибает динамические тела и упирается, импульса нет. Колбэк столкновений в `move_shape` пустой (`|_| {}`), аналога `OnControllerColliderHit` нет. Тест `engine_controller_alone_does_not_push` это фиксирует.
- **Обход:** `player::push_bodies`: `overlap_sphere` перед капсулой и `set_velocity` найденным телам.
- **План:** Фаза 3, «Физика» [~] (не упомянуто).

### 9. Пауза не останавливает звук — S

- **Нужно было:** на паузе замолкают эффекты, музыка может играть.
- **Что вышло:** `Time::pause` останавливает физику, скрипты и анимацию, но у `Audio` нет `pause/resume` ни для отдельных звуков, ни для шин.
- **Обход:** на паузе выключаются шины SFX и AMBIENT. Зацикленные звуки идут дальше беззвучно, one-shot доигрывают в тишине.
- **План:** нет в плане (Аудио [x]).

### 10. Headless-игра собирается вручную — S

- **Нужно было:** тестировать игру без окна тем же набором плагинов.
- **Что вышло:** `DefaultPlugins` с фичами по умолчанию всегда ставит окно и рендер. `AnimPlugin` добавляет только `RenderPlugin`. `scene_file::spawn` требует ресурс `Meshes` даже без рендера. `skin_meshes` — `pub(crate)`, поэтому скиннинг без `RenderPlugin` не проверить.
- **Обход:** `GamePlugin` сам добавляет `EcsPlugin`, `TransformPlugin`, `Meshes`, `AnimPlugin`, физику, ввод, звук и прочее. В бинарнике перед ним стоит `DefaultPlugins`, повторы пропускаются.
- **План:** нет в плане (рядом с фазой 0, «smoke-тесты»).

### 11. Фоновая загрузка сцены не настраивает материалы — S

- **Нужно было:** грузить уровень через `SceneLoader` (состояние `Loading`), как описано в `olvin_game`.
- **Что вышло:** корень `RenderAssets` выставляет только `scene_file::load`. Путь `SceneLoader::take` → `scene_file::spawn` его не трогает, и материалы сцены молча не находятся.
- **Обход:** `level::finish_loading` сам зовёт `RenderAssets::set_root` перед `spawn`.
- **План:** нет в плане.

### 12. Статичный коллайдер не следует за `Transform` — S

- **Нужно было:** маяк крутится и покачивается (Lua) вместе со своим триггером.
- **Что вышло:** объект с коллайдером без `Rigidbody` становится Fixed-телом, а за `Transform` ходят только Kinematic. Меш качается, триггер остаётся на месте. Без предупреждения.
- **Обход:** никакого, амплитуда маленькая. Правильно было бы дать маяку Kinematic Rigidbody, но редактор этого не подсказывает.
- **План:** нет в плане.

### 13. Сборка хаба: папка `dist/` внутри исходников, шаблон зависит от рабочей папки — S

- **Нужно было:** отдать собранную игру человеку.
- **Что вышло:** `olvin-hub build` работает (см. ниже), но кладёт `dist/<имя>` в папку проекта, а `.gitignore` шаблона знает только `/target` и `/logs`, так что 20 МБ бинарника легко закоммитить. `main.rs` шаблона грузит `assets/scenes/main.scene.ron` от рабочей папки: игра из `dist/`, запущенная двойным кликом или из другой папки, не найдёт сцену (п. 3). Хаб не проверяет, что собранная папка запускается.
- **Обход:** свой `.gitignore` (`/dist`, `/saves`, `/logs`) и `find_assets()` в срезе.
- **План:** Фаза 4, «Команда сборки игры» [x] — доделка; «Критерии готовности»: «собирается командой `olvin-hub build --release` и запускается без редактора».

## Сборка `olvin-hub build`

Работает и для члена workspace, отдельная раскладка проекта не нужна:

```
cargo run -p olvin_hub_cli -- build --release --project apps/vertical_slice
building vertical_slice (release)…
    Finished `release` profile [optimized] target(s) in 1m 05s
game:    apps/vertical_slice/dist/vertical_slice/vertical_slice
folder:  apps/vertical_slice/dist/vertical_slice (7 asset files)
```

`Project::open` принимает крейт, потому что у него есть зависимость `olvin` (имя — `package.name`). `cargo build --manifest-path` внутри workspace собирает в общий `target/`, exe находится по `compiler-artifact`, `assets/` копируется (без `tools/`). Собранная папка запускается из чужой рабочей папки (`--frames 240`: уровень, робот, Lua, Vulkan) только потому, что срез сам ищет `assets/` рядом с exe. Критерий готовности из ROADMAP по сборке выполнен, оговорки в п. 3, 7 и 13.

## Не проверено

- Захват курсора (`ActionState::lock_cursor` → `CursorOptions`) под Hyprland: синтетический ввод в сессию не отправлялся, игра запускалась только с автовыходом.
- Слышимость звука: устройство открывается (kira без предупреждений), позиционирование проверено только кодом движка.
