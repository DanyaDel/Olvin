# 0003. Retro-стиль рендера (PS1) в главном mesh-шейдере

<p align="center"><a href="0003-retro-render-style.en.md">English</a></p>

**Статус:** Принято — 2026-11-24

## Контекст

Нужен настоящий вид PlayStation 1 в 3D-рендере: дрожание вершин, аффинные текстуры, 15-битный цвет с дизерингом, освещение по вершинам, жёсткая дальность прорисовки, текстуры nearest и по желанию низкое внутреннее разрешение. Он должен работать на обоих тирах (Full: Vulkan / Metal / DX12, Compat: GL / WebGL2 с GLSL ES 3.00, то есть без `noperspective`), во вьюпорте редактора, по материалам (ретро-реквизит рядом с чистым UI или водой) и ничего не стоить, когда выключен.

Ограничение контракта библиотеки: поверхностный шейдер (`fn surface`) не трогает вершины и итоговый цвет. Поэтому привязка вершин, режим освещения и квантование живут в самом `mesh.wgsl`.

## Решение

Структура `RetroSettings` в `RenderSettings.retro` (глобально), `Environment.retro: Option<RetroDesc>` в файле сцены (`None` = выключено, при записи пропускается, serde-умолчания: старые сцены грузятся без изменений, `FORMAT_VERSION` остаётся 5), блок retro в `LookDesc` и `MaterialDesc.retro: Option<bool>` (`None` — как в сцене, `Some` — принудительно вкл / выкл). Значения всегда уходят в трёх vec4 `Globals` (`retro_a/b/c`); для материала решают `enabled` и флаг материала (`Material.flags.w`: 0 наследовать, 1 вкл, 2 выкл).

- **Привязка вершин.** В `vs_main` после проекции: `xy / w` округляется до сетки `snap_resolution` виртуальных пикселей (по умолчанию 320x240, не зависит от реального кадра) и умножается обратно на `w`, поэтому глубина и перспектива не меняются. Вершины с `w <= 1e-4` (за камерой) не трогаются, NaN нет. Округление детерминировано, картинка не мерцает. Второй вариант, `snap_grid_m`, привязывает мировую позицию к метрической сетке до проекции. По умолчанию экранная сетка (мировая 0 м): метровая сетка двигает целые предметы шагом в метр, это годится только для крупной геометрии уровня, поэтому она в виде ползунка для подбора.
- **Аффинное наложение.** Вершинный шейдер передаёт `uv * w`; фрагментный умножает интерполированное на `position.w` (это `1 / w`) и получает ровно экранно-линейные uv. Нужен один лишний varying и не нужен `noperspective`, поэтому на всех тирах одинаково. `affine_strength` смешивает с перспективными uv, а сила гаснет по `smoothstep(0, affine_fade_near, глубина)` (4 м по умолчанию): ближние поверхности не «плывут». Все текстуры материала (база, нормали, ORM, emissive) берут эти uv, поверхностные шейдеры получают аффинные `in.uv`. Triplanar берёт мировую позицию и не затрагивается. Большие полигоны сильно искажаются: контент PS1 тесселировали, поэтому демо-пак строит стены из кубов по 2 м.
- **Глубина цвета и dither.** `color_bits` (5 = 15 бит) округляет цвет в отображаемом (sRGB) виде по матрице Байера 4x4 в экранных координатах, масштаб `dither_strength` шагов квантования (0 = простое округление). Правило против двойного применения: **без пост-цепочки (Compat, редактор) это делает `finish()` в mesh- и sky-шейдерах; при HDR-цепочке окна Full это делает только composite-проход `post.wgsl`, один раз, на итоговой картинке после грейдинга** (mesh-шейдер отдаёт линейный HDR и пропускает). FXAA в ретро-режиме пропускается: он смазал бы дизеринг.
- **Освещение по Гуро.** `vertex_lighting` считает в `vs_main` полусферический ambient и point / spot (Ламберт, прежнее затухание, без спекуляра, без отражения неба, без теней) и `n.l` солнца отдельным значением; фрагментный шейдер умножает альбедо на интерполированный свет. `retro.shadows` добавляет к солнечной части тень из карты по пикселям (блочную, если карта грубая); тени point / spot не применяются. Карты нормалей в этом режиме игнорируются, металл считается диэлектриком. Цвета вершин и `MeshRenderer.color` умножаются как раньше.
- **Дальность прорисовки и отсечение.** `draw_distance` отбрасывает фрагменты глубже этого значения (по желанию растворяет последнюю десятую по Байеру) и подгоняет туман, чтобы он заканчивался ровно там (без тумана: цвет фона). CPU-проход отсечения убирает объекты, чья ограничивающая сфера начинается дальше, и (`cull_small_px`) объекты, чья сфера меньше заданного числа пикселей виртуального экрана. **Невозможно:** отбрасывать отдельные мелкие или дальние треугольники. Без геометрических шейдеров и compute треугольник по вершинам не убрать, а compute-отсекатель вне объёма. Отсечение обратных граней остаётся.
- **Текстуры.** У материала есть вторая bind group с nearest-сэмплером без мипов; для ретро-материала с `force_nearest` она подставляется при отрисовке. Переимпорт не нужен.
- **Низкое внутреннее разрешение.** Только окно на Full. `PostProcess` гоняет всю цепочку в размере `RetroSettings::scene_size` (`internal_resolution` либо окно / `pixel_scale`; аспект камеры следует размеру сцены), composite квантует, а nearest-проход растягивает результат на окно (`letterbox`: сохранить внутренний аспект с чёрными полосами; иначе внутренняя высота и аспект окна). Оверлей (`olvin_gui`) рисуется после этого в полном разрешении. Вьюпорт редактора (один MSAA-проход egui) и Compat его игнорируют, в UI это написано.
- **Looks.** Старый встроенный look «Retro PS1» (постеризующий грейд) стал «PS1»: тот же грейд плюс `retro: Some(ps1)`; look теперь всегда задаёт `Environment.retro` (Neutral выключает). Пресет: `RetroSettings::ps1()` / `RetroDesc::ps1()`.

## Рассмотренные варианты

- **Отдельные варианты пайплайна или `override`-константы.** Ноль стоимости в обычном пути по построению, но умножает пайплайны (поверхностный шейдер x blend x retro), а переключение по материалам требует смены пайплайна при отрисовке. Отвергнуто: ретро-ветки это uniform-ветвления (`globals.retro_*`, `material.flags.w`), которые GPU выполняют когерентно. Замер на llvmpipe (release, 256x256, 400 освещённых кубов, 8 ламп, машина под нагрузкой, прогоны вперемешку): main 4,32-4,67 мс на кадр, эта ветка 4,42-4,45 мс, то есть разницы за пределами шума нет. Обычный путь и попиксельно тот же: все прежние рендер-тесты проходят без правок.
- **`noperspective`** для аффинности: нет в GLSL ES 3.00 / WebGL2.
- **Квантование только в пост-цепочке.** В редакторе и на Compat её нет.
- **Освещение отдельным проходом или в поверхностном шейдере.** Запрещено контрактом, а Гуро по природе в вершинной стадии.
- **Отсечение по треугольникам через compute.** Вне объёма, см. выше.

## Последствия

- В mesh-шейдере 7 varyings (было 5), а uniform материала читает и вершинная стадия.
- На цепочке Full снижение цвета действует на весь кадр: материал с Retro Off тоже квантуется (пост-проход не знает материалов). На Compat и в редакторе это по материалам.
- Частицы и 2D-спрайты на Compat не квантуются.
- Скрипт не умеет менять интенсивность света, поэтому мигающая лампа демо-пака на мгновения уводит источник за пределы дальности.
- Открыто: привязка, которая сама следует за внутренним разрешением, тесселяция больших полигонов при импорте, ретро-режим для частиц.
