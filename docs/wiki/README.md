# Olvin Wiki: как писать и собирать

Вики по движку Olvin в стиле Arch Wiki и Hyprland Wiki: одна страница на тему, короткие факты, много ссылок между страницами. Две книги [mdBook](https://rust-lang.github.io/mdBook/): русская (`ru/`, основная) и английская (`en/`, копия). Опубликована на GitHub Pages: `https://danyadel.github.io/Olvin/` (workflow `.github/workflows/wiki.yml`).

Источник правды о фактах: [ARCHITECTURE.md](../../ARCHITECTURE.md) и код. Если страница расходится с кодом, исправляйте страницу.

## Сборка и просмотр

```sh
cargo install mdbook --locked           # один раз
docs/wiki/tools/build.sh                # проверки + обе книги в book/{ru,en}
docs/wiki/tools/build.sh --serve        # то же и сервер на http://127.0.0.1:3000/ru/
mdbook serve docs/wiki/ru --open        # одна книга с автоперезагрузкой (переключатель языка работает только при build.sh --serve)
```

Результат лежит в `book/` в корне репозитория, он в `.gitignore`.

## Структура

```
docs/wiki/
  ru/  book.toml  src/SUMMARY.md  src/<раздел>/<страница>.md  src/images/
  en/  то же самое, те же имена файлов
  tools/
    build.sh                  проверки и сборка
    check_links.py            ссылки, якоря, SUMMARY, парность ru/en, шаблон страницы
    check_lua_reference.py    справочник Lua сверяется с кодом
```

Разделы: `start/` (начало), `tutorial/` (первая игра), `editor/`, `engine/`, `reference/`, `troubleshooting/`, `dev/`. Имена файлов совпадают в `ru` и `en`: переключатель языка и проверка парности на этом держатся.

## Шаблон страницы

```markdown
# Название страницы

Одно-два предложения: что это и зачем.

> **Статус:** частично. Не сделано: GPU-скиннинг, см. [#8](https://github.com/DanyaDel/Olvin/issues/8).

## Раздел

Короткие факты, таблицы, фрагменты кода.

## См. также

- [Другая страница](../engine/rendering.md)
```

Правила:

- Заголовок первого уровня один, он же название в боковой панели. Дальше только `##` и `###`.
- Обязательный раздел `## См. также` (в английской книге `## See also`) в конце страницы. Проверяется скриптом.
- Заметка о статусе пишется, когда возможность частичная или в разработке: что не сделано и номер открытого issue. Пишем `Статус: планируется`, если код ещё не в `main`.
- Один абзац одна мысль, факты вместо рассказа. Таблицы для горячих клавиш, параметров, команд.
- Ссылки между страницами относительные и на `.md` (`../engine/physics.md#raycast`), на файлы репозитория вне книги абсолютные на GitHub, на issues тоже.
- Код в блоках с языком (`rust`, `lua`, `ron`, `sh`, `toml`). Фрагменты берём из реального кода, не придумываем: источник указывайте в тексте (`apps/vertical_slice/assets/scripts/door.lua`).
- Интерфейс редактора и хаба английский (STYLE.md, раздел 10), поэтому названия кнопок и меню пишем как в интерфейсе: «Window → Add Panel».
- Без эмодзи, без маркетинга. Если что-то не работает, так и пишем.
- Каждое утверждение проверяется по коду. Новая возможность в `main`: страница обновляется в том же PR.

## Скриншоты

Готовые лежат в `docs/screenshots/`. Нужные копируются в `ru/src/images/` и `en/src/images/` (одинаковые имена), каждый до 300 КБ. Новые рендерятся без окна, через llvmpipe:

```sh
export __EGL_VENDOR_LIBRARY_FILENAMES=/usr/share/glvnd/egl_vendor.d/50_mesa.json WGPU_BACKEND=gl
OLVIN_EDITOR_REVIEW=/tmp/olvin-shots \
  cargo test -p editor_dev --test screenshots review -- --ignored
# одна рабочая область: OLVIN_EDITOR_REVIEW_ONLY=animation
```

Если картинка большая, уменьшите (`magick in.png -resize 1400x -strip out.png`; для скриншотов редактора подходит и `pngquant`). Не переписывайте `docs/screenshots/*.png` без причины (их использует README).

## Проверки

- `check_links.py` падает на битой ссылке или якоре, странице вне `SUMMARY.md`, странице только на одном языке, странице без раздела «См. также».
- `check_lua_reference.py` читает `crates/olvin_script/src/lua/{api.rs,audio.rs,prelude.lua,mod.rs}` и требует, чтобы каждая функция `ctx:` и каждый колбэк были в `reference/lua-api.md` обеих книг (и ничего лишнего). Добавили функцию в Lua API без записи в справочнике: CI красный.
- `mdbook build` без предупреждений.

Всё это идёт в CI (`.github/workflows/wiki.yml`) на каждый PR; деплой только из `main`.

## Языки

Русский основной, английский копия (STYLE.md, раздел 10). Новая страница создаётся сразу в обеих книгах; если перевода нет, в английской книге остаётся страница с тем же заголовком и пометкой `> Translation pending.` Никаких автопереводов без вычитки.
