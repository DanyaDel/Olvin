# Step 7. On-screen text

We will show the "door is open" message from `plate.lua` ([step 5](05-door.md)) on screen. This needs the game UI `olvin_gui` (the `gui` feature of the facade, added in [step 1](01-project.md)): separate from egui, with real text (built-in Inter with Cyrillic).

The script sends the message with `ctx:send("hud", text)`. The game reads the `Events<ScriptMessage>` queue and shows a panel for four seconds. This is a simplified version of `apps/vertical_slice/src/hud.rs`:

```rust
use olvin::core::{EventCursor, Events};
use olvin::gui::{Color, Gui, Node, NodeId};
use olvin::prelude::*;
use olvin::script::ScriptMessage;

struct Toast {
    panel: NodeId,
    text: NodeId,
    cursor: EventCursor,
    left: f32,
}

/// Stage::Startup: build the tree once.
fn build_hud(res: &mut Resources) {
    let (panel, text) = {
        let mut gui = res.fetch_mut::<Gui>();
        let ui = &mut gui.ui;
        let root = ui.root();
        let panel = ui.add(
            root,
            Node::panel()
                .padding(12.0)
                .background(Color::rgba(0.05, 0.06, 0.08, 0.78))
                .anchor(Vec2::new(0.5, 0.0), Vec2::new(0.5, 0.0), Vec2::new(0.0, 24.0))
                .hidden(),
        );
        let text = ui.add(panel, Node::label("").text_size(20.0));
        (panel, text)
    };
    res.insert(Toast { panel, text, cursor: EventCursor::default(), left: 0.0 });
}

/// Stage::Update: script messages -> the panel, hide timer.
fn update_hud(res: &mut Resources) {
    let dt = res.fetch::<Time>().unscaled_delta();
    let mut shown = None;
    {
        let events = res.fetch::<Events<ScriptMessage>>();
        let mut toast = res.fetch_mut::<Toast>();
        for m in events.read(&mut toast.cursor) {
            if m.name == "hud" {
                shown = m.value.as_str().map(str::to_owned);
            }
        }
        toast.left = if shown.is_some() { 4.0 } else { (toast.left - dt).max(0.0) };
    }
    let toast = res.fetch::<Toast>();
    let mut gui = res.fetch_mut::<Gui>();
    if let Some(t) = &shown {
        gui.ui.set_text(toast.text, t);
    }
    gui.ui.set_visible(toast.panel, toast.left > 0.0);
}
```

Wire it up in `main.rs`: `.add_system(Stage::Startup, build_hud).add_system(Stage::Update, update_hud)`.

How it works:

- `Gui { ui, .. }` is a resource holding the node tree. `Node::panel()`, `Node::label(..)`, `Node::button(..)`, `row()/column()`, `fill()`, `anchor(..)`, `centered()`.
- `GuiRenderPlugin` (installed by `DefaultPlugins` with the `gui` and `render` features) lays the tree out and draws it over the frame after post-processing: the UI gets no bloom and no tonemapping.
- Buttons produce `UiEvent::Click { name, .. }` in `Events<UiEvent>`; focus works from keyboard, mouse and gamepad.
- Sizes are in UI pixels, screen scale is taken into account (`Gui::scale`).

The slice builds the crosshair, "Загрузка…" and the pause menu with "Продолжить" / "Выйти" buttons the same way.

> **Status:** not done in `olvin_gui`: line wrapping (only an explicit `\n`), text fields, sliders, scrolling, an image node. Input that the UI handled (a button click, focus navigation) is not visible to the game, see [Game UI](../engine/game-ui.md).
