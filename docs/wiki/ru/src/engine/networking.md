# Сеть (в работе)

> Статус: **в разработке**, ветка `feat-net`. Решение и обоснование: `docs/adr/0003-netcode.md` (ADR 0003). Страница обновляется вместе с кодом; что уже есть, а чего нет, сказано в конце.

Цель: **сеть безумно гибкая и при этом несложная в написании.** Для этого `olvin_net` устроен слоями, и каждый слой можно взять отдельно.

| Слой | Что даёт |
|---|---|
| L0 Транспорт | надёжный и ненадёжный каналы. `Loopback` внутри процесса с имитацией задержки, потерь, джиттера; QUIC (`quinn`, TLS) за фичей `quic` |
| L1 Сессия | режимы `Offline`, `Host`, `Dedicated`, `Client`; вход по адресу или короткому коду комнаты; рукопожатие, кик, таймауты |
| L2 Репликация | отметил префаб `Replicated`, зарегистрировал компоненты, и объект появляется у всех |
| L3 Сообщения | команды клиента с проверкой на сервере, лимиты частоты и размера |
| L4 Предсказание | свой персонаж откликается сразу, сервер всё равно главный |
| L5 Скрипты | `ctx:net_send`, `on_net_message`: мультиплеер на одном Lua |
| L6 Инструменты | RTT, потери, трафик в профилировщике; «лаг 80 мс, потери 2 %» в Play |

## Принципы

- **Сервер главный.** Реплицируемое состояние пишет только сервер. Клиент шлёт команды («иду туда», «стреляю»), сервер их проверяет.
- **Offline это тоже сеть.** Одиночная игра идёт тем же кодом через `Loopback`, поэтому любая игра готова к мультиплееру.
- **Всё ограничено.** Размеры пакетов, частота сообщений, число клиентов; мусорные байты не роняют сервер.
- **Безопасность по построению:** TLS 1.3 (QUIC), сертификат закрепляется отпечатком из кода комнаты, nonce и метки времени против повтора, у каждой сессии свой ключ.
